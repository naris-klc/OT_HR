ตกลงและลงมือทำเมื่อ 9 ก.ย. 2569 ของที่ shipped อยู่ใน components/ManualView.jsx · test/manualScreen.test.js และย่อหน้าคู่มือใน README.md หน้านี้เก็บไว้เพื่อบันทึกว่าตัดสินใจอะไรไว้เพราะอะไร ไม่ใช่เพื่อบอกว่าตอนนี้ระบบเป็นอย่างไร สองจุดที่ต้นแบบนี้เดาไว้ไม่ตรงกับของจริง — ต้นแบบนับว่าผู้ดูแลระบบเห็นครบทุกหัวข้อ ของจริงเห็น 16 จาก 18 เพราะ isSigner เป็นเท็จสำหรับบทบาทนั้น สอง section เรื่องคิวของผู้เซ็นขั้นแรกจึงหายไปพร้อมหน้าจอที่บทบาทนั้นไม่มี และภาพประกอบของจริงวาดสองเครื่องคู่กันทุกภาพ (คอมพิวเตอร์ · มือถือ) ตามที่สั่งเพิ่มหลังจากหน้านี้ถูกเขียน ส่วนต้นแบบวาดเครื่องเดียว

ข้อที่สาม เพิ่มเมื่อ 10 ก.ย. 2569 — คำและตัวเลขในมินิสกรีนของหน้านี้ ไม่ใช่คำที่อยู่บนหน้าจอจริง วันนั้นคู่มือถูกเดินสอบกับแอปทีละหน้าตามคำสั่ง “ภาพ ui ขั้นตอนและข้อความต้องให้ตรงกับ ui ของจริง” แล้วแก้ที่ components/ManualView.jsx อย่างเดียว หน้านี้ไม่ได้ตามไปแก้ เพราะเป็นบันทึกของข้อเสนอ ไม่ใช่ภาพของระบบตอนนี้ ตัวอย่างที่ต่างกันชัด: ป้ายสถานะขั้นที่สองบนจอจริงเขียนว่า รอ HR ไม่ใช่ รอฝ่ายบุคคล · ชื่อช่องอัตราคือ OT วันปกติ ×1.5 ไม่ใช่ ×1.5 วันปกติ · หัวข้อคำนวณบนฟอร์มเขียนว่า ระบบคำนวณได้ ไม่ใช่ ตัวอย่างชั่วโมงที่จะได้ · แถบเตือนรหัสผ่านเขียนว่า คุณยังใช้รหัสผ่านที่ฝ่ายบุคคลตั้งให้อยู่ พร้อมปุ่ม เปลี่ยนรหัสผ่าน · สรุปสถานะงวดเป็นประโยคเดียวไม่ใช่ช่องตัวเลขสามช่อง · และ ตั้งค่าระบบมีเจ็ดหัวข้อ ไม่ใช่สี่ส่วน · ทั้งหมดนี้แก้แล้วในของจริง

คู่มือการใช้งาน — หน้าเดียว เลื่อนอ่าน มีภาพประกอบ และตัดตามสิทธิ์

วันนี้คู่มือเป็น เมนู 11 หัวข้อ ที่เปิดทีละหัวข้อ ข้อความล้วน และเหมือนกันทุกบทบาท — พนักงานที่อ่านจึงเจอวิธีตั้งค่าระบบและวิธีปิดคิวของหัวหน้าปนอยู่ด้วย ข้อเสนอนี้เปลี่ยนสามอย่างพร้อมกัน แล้วให้ทั้งสามอย่างช่วยกัน: ตัดตามสิทธิ์ทำให้หน้ามันสั้นพอจะเป็นหน้าเดียวได้ · หน้าเดียวทำให้แถบหัวข้อด้านซ้ายมีความหมาย · และภาพประกอบทำให้แต่ละขั้นดูออกโดยไม่ต้องอ่านจบย่อหน้า

แสดงเฉพาะที่ใช้งานได้ตามสิทธิ์

section ถูกกรองด้วย predicate ตัวเดียวกับที่ App.jsx ใช้สร้างเมนู พนักงานเห็น 8 หัวข้อ · ผู้ดูแลระบบเห็น 18 — และไม่มีใครอ่านวิธีใช้หน้าที่ตัวเองเปิดไม่ได้

ข้อนี้กลับคำตัดสินที่เขียนเหตุผลไว้แล้ว และควรรู้ก่อนตกลง

1 · ประตูของแต่ละ section — ใช้ predicate ที่มีอยู่แล้ว ไม่เขียนกฎใหม่

ทุกบรรทัดในตารางนี้อ่านจากไฟล์ที่ตัดสินเรื่องนั้นอยู่แล้ว lib/roles.js · lib/entries.js · publicUser — คู่มือจึงไม่กลายเป็นที่ที่สองที่ตัดสินว่าใครทำอะไรได้ ซึ่งเป็นความล้มเหลวที่ AGENTS.md พูดถึง (“กฎเดียวกันถูก implement สองรอบ”)

2 · ระบบภาพประกอบ — สามชนิด และไม่มีชนิดไหนเป็นไฟล์รูป

  • มินิสกรีน (HTML) — จำลองการ์ด ช่องกรอก ปุ่ม ชิปสถานะ ด้วยคลาสย่อส่วนที่กินโทเคนสีชุดเดียวกับแอป เปลี่ยนธีมสว่าง/มืดตามแอปเอง และไม่มีวันเพี้ยนเพราะสีถูกแก้ที่อื่น
  • แผนภาพ (inline SVG) — เส้นทางอนุมัติ ผังตัดสินใจ และการตัดกะข้ามคืน วาดด้วย currentColor กับตัวแปร CSS ทั้งหมด
  • หมุดชี้ขั้นตอน — วงกลมเลขขั้นวางทับมินิสกรีนตรงจุดที่ต้องกด เลขตรงกับข้อความข้างบนเสมอ
ทำไมไม่ใช้ภาพถ่ายหน้าจอ — เดือนกันยายนเดือนเดียวแท็บถูกเปลี่ยนชื่อสามรอบ (สรุปทีม → รายงาน OT ประจำทีม, OT ของฉัน → บันทึกและประวัติ OT) ภาพถ่ายจะค้างชื่อเก่าโดยไม่มีเทสต์ตัวไหนร้อง ทั้งยังเป็นไฟล์ไบนารีใน git และต้องมีคนเปิดแอปจริงไปถ่ายใหม่ทุกครั้ง ภาพที่วาดจากโทเคนไม่ต้องถ่ายใหม่ และผ่าน /api/print/pdf ได้โดยไม่ต้องแนบ asset

3 · ไฟล์ที่ต้องแตะ

  • components/ManualView.jsx — TOPICS ได้ gate กับ steps, ตัวหน้าจอเปลี่ยนจาก menu/detail สองสถานะเหลือหน้าเดียว + แถบหัวข้อ + scroll-spy (IntersectionObserver), ลบ openKey ทิ้ง

  • app/styles.css — คลาสชุด .manual-rail .manual-step .ms-* เพิ่มต่อจากบล็อก .manual-* เดิมที่บรรทัด ~15192
