## ปัญหาที่ต้องแก้ เรียงตามความเร่งด่วน

### 1. IP เป็น DHCP — บุ๊กมาร์กของทุกคนจะพังพร้อมกัน

`192.168.109.119` มาจาก DHCP lease เมื่อเราเตอร์รีสตาร์ท ไฟดับ หรือ lease หมดอายุตอนเครื่องปิด
เครื่องอาจได้เลขใหม่ ตอนนั้นบุ๊กมาร์กบนมือถือของพนักงานและหัวหน้างาน**ทุกคนจะพังพร้อมกัน**
โดยไม่มีข้อความอะไรบอก — หน้าจอจะขึ้นแค่ "เชื่อมต่อไม่ได้" ซึ่งอ่านได้ว่า "ระบบล่ม"

**ทางแก้ที่ถูกต้องคือ DHCP Reservation ที่เราเตอร์** ไม่ใช่ตั้ง Static IP บนเครื่อง:

- ผูก MAC `2C-1B-3A-E3-AE-5B` เข้ากับ IP ที่ต้องการ ที่หน้าจัดการเราเตอร์
- เครื่องยังรับค่าจาก DHCP เหมือนเดิม จึงได้ gateway/DNS/subnet ที่ถูกต้องเสมอ
  แม้วันหนึ่งเครือข่ายจะเปลี่ยนผัง
- ไม่มีความเสี่ยง IP ชนกัน เพราะเราเตอร์เป็นคนจัดการเอง

> **ทำไมไม่แนะนำให้ตั้ง Static IP บนเครื่องโดยตรง:** ต้องรู้ว่า DHCP pool ของเราเตอร์กินช่วงไหน
> ถ้าตั้งเลขที่อยู่ในช่วงนั้น วันหนึ่งเราเตอร์จะแจกเลขเดียวกันให้เครื่องอื่น แล้วเกิด IP ชนกัน
> — อาการคือระบบใช้ได้บ้างไม่ได้บ้างแบบสุ่ม ซึ่งหาสาเหตุยากกว่าปัญหาเดิมมาก
> **ข้อมูลนี้อ่านจากเครื่องไม่ได้ ต้องดูที่เราเตอร์**

ถ้าเข้าเราเตอร์ไม่ได้จริง ๆ และจำเป็นต้องตั้งบนเครื่อง — ต้องได้ตัวเลขที่ยืนยันแล้วว่า**อยู่นอก
DHCP pool** ก่อน แล้วจึงรัน (ตัวอย่างสมมติว่าเลือก `.50`):

```powershell
# ⚠ อย่ารันจนกว่าจะยืนยันแล้วว่า .50 อยู่นอกช่วงที่เราเตอร์แจก
New-NetIPAddress -InterfaceAlias 'Wi-Fi' -IPAddress 192.168.109.50 `
  -PrefixLength 24 -DefaultGateway 192.168.109.253
Set-DnsClientServerAddress -InterfaceAlias 'Wi-Fi' `
  -ServerAddresses 115.178.58.10,115.178.58.26
```

ย้อนกลับเป็น DHCP:

```powershell
Set-NetIPInterface -InterfaceAlias 'Wi-Fi' -Dhcp Enabled
Set-DnsClientServerAddress -InterfaceAlias 'Wi-Fi' -ResetServerAddresses
```

**และไม่ว่าจะทำวิธีไหน เครื่องนี้ควรเสียบสาย LAN แทน Wi-Fi** เซิร์ฟเวอร์ที่คนทั้งบริษัทใช้
ไม่ควรแขวนอยู่กับสัญญาณไร้สาย ถ้าย้ายไปสาย **MAC จะเปลี่ยน** ต้องทำ reservation ใหม่กับ
MAC ของการ์ด Ethernet

### 2. ชื่อแทนตัวเลข — `ot.primus.local`

หลังจากตรึง IP ได้แล้ว ให้เพิ่ม A record ที่ DNS ภายใน (มักตั้งได้ที่หน้าเราเตอร์ตัวเดียวกัน
หัวข้อ Local DNS / Static DNS / DNS Host Names):

```
ot.primus.local   →   192.168.109.<เลขที่จอง>
```

แล้วพนักงานเข้าที่ **`http://ot.primus.local:3000`**

ข้อดีที่แท้จริงไม่ใช่แค่จำง่าย: วันที่ต้องย้ายระบบไปเครื่องอื่น แก้ DNS record ที่เดียว
โดยไม่ต้องไล่บอกพนักงานทุกคนให้เปลี่ยนบุ๊กมาร์ก

> **หมายเหตุ:** DNS ที่เครื่องตั้งอยู่ตอนนี้เป็นของ ISP (`115.178.58.x`) ไม่ใช่ DNS ภายใน
> ถ้าเราเตอร์ไม่ได้ทำหน้าที่ DNS ให้เครื่องในวง ชื่อ `.local` จะใช้ไม่ได้ — ต้องแก้ให้เครื่อง
> ลูกข่ายชี้ DNS มาที่เราเตอร์ก่อน

**ถ้าเราเตอร์ทำ Local DNS ไม่ได้เลย** ทางออกที่ยังพอใช้ได้คือแก้ไฟล์ `hosts` บนเครื่องพนักงาน
— แต่ต้องทำทีละเครื่อง และ**ทำบนมือถือไม่ได้** จึงไม่ใช่คำตอบสำหรับที่นี่
กรณีนั้นให้ใช้ IP ที่จองไว้ตรง ๆ แล้ว **เขียนใส่กระดาษแปะไว้ที่ฝ่ายบุคคล**

### 3. Firewall ผูกอยู่กับ profile "Public" — ✅ **แก้แล้ว 2026-08-18**

**สิ่งที่พบตอนตรวจ:**

- Network profile ของ `RD-Software_5G 2` คือ **Public**
- Rule ขาเข้าของ Node.js ที่เปิดอยู่ ก็อยู่บน profile **Public** เท่านั้น
- **ไม่มี rule ที่ระบุพอร์ต 3000 โดยตรงเลย** — ที่ใช้ได้อยู่ทุกวันนี้คือ rule ที่ Windows
  สร้างให้ `node.exe` ตอนมีคนกด "Allow" ในป๊อปอัปครั้งแรก

นี่คือระเบิดเวลาเงียบ ๆ สองลูก:

1. ถ้าใครกดเปลี่ยนเครือข่ายนี้เป็น **Private** (ซึ่งเป็นสิ่งที่ Windows แนะนำให้ทำกับ
   เครือข่ายที่บ้าน/ที่ทำงาน) inbound จะถูกบล็อกทันที และอาการคือ **ทั้งบริษัทเข้าระบบไม่ได้
   พร้อมกันโดยไม่มีใครแตะโค้ดอะไรเลย**
2. rule ผูกกับ path ของ `node.exe` — อัปเดต Node.js เมื่อไหร่อาจต้องกด Allow ใหม่

**สร้าง rule นี้ไปแล้วเมื่อ 2026-08-18** (ต้องใช้สิทธิ์ผู้ดูแลระบบ):

```powershell
New-NetFirewallRule -DisplayName 'OT system (Next.js) 3000' `
  -Direction Inbound -Protocol TCP -LocalPort 3000 -Action Allow `
  -Profile Domain,Private,Public `
  -RemoteAddress 192.168.109.0/24 `
  -Description 'Primus OT system - LAN only'
```

ยืนยันค่าที่ได้จริง:

```
DisplayName   : OT system (Next.js) 3000
Enabled       : True
Direction     : Inbound
Action        : Allow
Profile       : Domain, Private, Public
Protocol/Port : TCP 3000
RemoteAddress : 192.168.109.0/255.255.255.0
```

ตอนนี้เปลี่ยน network profile เป็น Private ได้แล้วโดยระบบไม่ล่ม

`-RemoteAddress` จำกัดให้เฉพาะเครื่องในวงเดียวกันเรียกได้ — เป็นการเขียน perimeter ที่ตกลงกันไว้
ลงในเครื่องจริง แทนที่จะเป็นแค่ข้อตกลง

> ⚠️ **ถ้าวันหนึ่งเปลี่ยน subnet** (ย้ายเราเตอร์ เปลี่ยนผังวง) **ต้องแก้ rule นี้ด้วย**
> ไม่งั้นจะไม่มีใครเข้าระบบได้เลยและอาการจะเหมือน "เซิร์ฟเวอร์ล่ม"
> แก้ด้วย `Set-NetFirewallRule -DisplayName 'OT system (Next.js) 3000' -RemoteAddress <วงใหม่>`

ยังเหลือ rule เดิมของ `node.exe` (profile Public) อยู่ในเครื่อง ไม่ได้ลบทิ้ง — ไม่ได้เสียหายอะไร
แต่ถ้าจะเก็บกวาดให้เรียบร้อยก็ลบได้ ตอนนี้ไม่ใช่ตัวที่ทำให้ระบบเข้าถึงได้แล้ว

## เรื่อง HTTPS และการเปิดออกอินเทอร์เน็ต

**ข้อสรุปที่ตกลงกันแล้ว: อยู่ใน LAN เท่านั้น ถ้าต้องใช้จากนอกสถานที่ให้ต่อผ่าน corporate VPN**
ไม่เปิดเซิร์ฟเวอร์นี้ออกอินเทอร์เน็ตตรง ๆ

เหตุผลที่ทำให้ VPN เป็นคำตอบที่ถูก ไม่ใช่แค่ปลอดภัยกว่า:

- ระบบนี้ถือ **รายชื่อพนักงานทั้งบริษัท วันเกิด และชั่วโมง OT** ซึ่งสะท้อนโครงสร้างค่าจ้างโดยอ้อม
- เข้าระบบด้วย**รหัสพนักงาน + รหัสผ่าน** เท่านั้น ไม่มี 2FA
- มีการหน่วงเวลาเมื่อรหัสผิดซ้ำ (`lib/loginThrottle.js`) แต่**หน่วงต่อบัญชี ไม่ใช่ต่อ IP** —
  ซึ่งพอสำหรับคนเดาสุ่มในออฟฟิศ ไม่พอสำหรับบ็อตทั้งอินเทอร์เน็ต
- รหัสพนักงานเดาได้ (`PM-0412`) จึงเท่ากับครึ่งหนึ่งของ credential เป็นข้อมูลสาธารณะ

### ผลข้างเคียงของ HTTP เปลือย ที่เกิดขึ้นแล้ววันนี้

บน HTTP เบราว์เซอร์ถือว่าไม่ใช่ secure context จึงปิด API บางตัว ที่กระทบจริงคือ
**`navigator.clipboard` ใช้ไม่ได้** — โค้ดจึงต้องมี `legacyCopy` มารองรับ
(ดู `components/AdminView.jsx`) ปุ่ม "คัดลอกรหัสผ่าน" ยังทำงานได้ แต่ผ่านทางที่เก่ากว่า
และเบราว์เซอร์บางตัวอาจปฏิเสธ — ซึ่งเป็นเหตุผลหนึ่งที่เพิ่มปุ่ม **พิมพ์สลิป** เข้ามา

ระบบนี้**ไม่ได้เป็น PWA** (ไม่มี manifest ไม่มี service worker) ปัญหาเรื่อง PWA ต้องใช้ HTTPS
จึงยังไม่เกิด แต่จะเกิดทันทีถ้าวันหนึ่งอยากทำให้ติดตั้งลงหน้าจอมือถือได้

### ถ้าจะทำ HTTPS ในวง LAN จริง

ไม่จำเป็นเร่งด่วน (JWT อยู่ใน httpOnly cookie แล้ว และวงเป็นวงปิด) ถ้าจะทำ ทางที่เจ็บน้อยสุด
คือวาง **Caddy** ไว้หน้าพอร์ต 3000 แล้วออก certificate จาก internal CA — แต่ต้องติดตั้ง
root certificate ลงทุกเครื่องและทุกมือถือ **สำหรับ 20 คน งานติดตั้ง cert บนมือถือทุกเครื่อง
แพงกว่าประโยชน์ที่ได้** ควรทำเมื่อขยับไปเซิร์ฟเวอร์จริงพร้อมกัน
