## 2. ⚠ ทำไมหน้าของตารางนี้ไม่ใช่ `.slice()`

**`Ctrl+P` บนจอนี้พิมพ์ตารางนี้จริง ๆ** `app/print.css` จัดรูป `.acct-table` เป็น
เอกสารหลายหน้ากระดาษ: 8pt · `table-layout: auto` · `thead` วาดซ้ำหัวทุกหน้า ·
`tfoot` ถูกบังคับกลับเป็น row group ธรรมดาเพื่อให้ยอดรวมพิมพ์ครั้งเดียว ไม่ใช่
ท้ายทุกหน้า — กฎพวกนี้ถูกเขียนขึ้นเพราะมีคนพิมพ์จากจอนี้

ถ้าหน้าเป็น `.slice()` ใบที่ส่งให้บัญชีจะมีเฉพาะแถวของหน้าที่คนเปิดค้างไว้
**และไม่มีอะไรบนกระดาษบอกว่ามันขาด** — ใบเงินเดือนที่สั้นไปอย่างเงียบ ๆ ซึ่งคือ
ความผิดพลาดคนละชั้นกับ "จอแสดงผลไม่สวย"

| | |
|---|---|
| แถวนอกหน้า | ยังถูกวาดลง DOM ครบ ติดคลาส `off-page` |
| บนจอ | `.acct-table tbody tr.off-page { display: none; }` |
| บนกระดาษ | `@media print` คืนเป็น `display: table-row !important` |
| ตัวแถบ | `no-print` |

**`off-page` เป็นคลาสที่แอปมีอยู่แล้ว** ตรวจสอบรายเดือน (`.hr-table`) ใช้ชื่อนี้
ด้วยกลไกเดียวกัน ต่างที่ซ่อนเฉพาะใต้ 860px · ผลข้างเคียงที่ต้องตามแก้คือย่อหน้าใน
`app/styles.css` ที่เขียนไว้ว่า *"`.off-page` ไม่มีกฎที่ไหนเหนือบรรทัดนี้ และนั่น
คือสิ่งที่ค้ำอยู่"* — ประโยคนั้นเป็นจริงจนถึงวันนี้ แก้ในคอมมิตเดียวกันให้เหลือ
สิ่งที่อันตรายจริง: กฎที่ไปถึง `.hr-table` และ selector `.off-page` เปล่า ๆ ซึ่ง
กินทุกตารางในแอป · `test/hrMonthCards.test.js` เปลี่ยนจากห้ามสตริงเป็นห้ามกฎ

## 3. ผลพลอยได้: A PAGE IS NOT A FILTER บนจอนี้ฟรี

ไม่ต้องตรึงด้วยการนับ `pageRows` แบบสองจอก่อนหน้า เพราะ**ไม่มี `pageRows`**
ทุกแถวอยู่ในเอกสารเสมอ และของที่นับ:

* `<tfoot>` — รวมแผนก และ รวมทั้งหมด — สร้างจาก `company.departments` กับ
  `company.totals` ซึ่ง route คำนวณมาจากทั้งเดือน ไม่เคยสร้างจากแถว
* ป้ายสองใบบนหัวการ์ด (`n คนมี OT` · `รวม x ชม.`) อ่านจาก `totals` เหมือนกัน

## 4. ข้อที่ตอบต่างจากคิวรออนุมัติ

**`usePageReset` ผูกกับข้อมูล ไม่ใช่ตัวกรอง** — ตรงข้ามกับคำตอบของคิว และต่างกัน
ตรงที่**จอนี้ไม่มีอะไรแก้แถวเลย** ไม่มีอนุมัติ ไม่มีลบ แถวเปลี่ยนก็ต่อเมื่อเปลี่ยน
เดือน เปิดงวดสองเดือน หรือติ๊ก แสดงพนักงานที่ไม่มี OT ซึ่งทั้งสามแปลว่ากำลังดู
คนละรายการ — หน้า 3 ของรายการใหม่ไม่ใช่หน้าที่คนอ่านค้างไว้

**แถบหนึ่งอันต่อหนึ่งใบบริษัท** บนแท็บ ทั้งหมด มีสองใบ แต่ละใบถือ `page` ของตัวเอง
และ `goPage` เลื่อนขึ้นหัวตารางของใบที่ถูกกด ไม่ใช่ยอดรายงาน

**เริ่มที่ 50** เดือนที่ใช้ทดสอบมีคนได้ OT 23 คน แถบจึงส่วนใหญ่ทำหน้าที่บอกว่า
*ทั้งหมดมีเท่านี้*

## 5. `บริษัทที่ N` — ถอดทั้งสาย

บรรทัด `.kicker-sm` ถูกถอด พร้อม**พร็อพ `index` และ `findIndex` ที่ป้อนมัน** —
ค่าที่ไม่มีใครอ่านแล้วยังคำนวณอยู่คือค่าที่จะถูกเอากลับมาใช้ผิดวันหนึ่ง

**ตอนนี้ไม่มีที่ไหนในแอปพูดลำดับของบริษัทอีกแล้ว** และนั่นคือสิ่งที่ต้องบันทึก
เพราะเช้าวันเดียวกันเพิ่งมีคอมมิตที่ถอด `บริษัทที่ N` ออกจากแถวของตาราง
รวมทุกบริษัท **โดยให้เหตุผลว่า "การ์ดของบริษัทนั้นแบกมันเป็น kicker อยู่ข้างล่าง"**
— ครึ่งนั้นตกไปแล้ว แก้ไว้สามที่ในคอมมิตนี้: คอมเมนต์ใน `AccountingView.jsx`,
ย่อหน้าใน README และแถวใน `docs/features.md` · เหตุผลที่ยังยืนคือครึ่งที่เหลือ:
เลขลำดับไม่ใช่สิ่งที่คนอ่านเดาเองไม่ได้ และบนแท็บบริษัทเดียวก็ไม่มีรายการให้นับ

## 6. คลาส `.queue-pager` เปลี่ยนชื่อเป็น `.flush-pager`

การ์ดของทั้งสองจอเป็น `.card.flush` ที่ `padding: 0` และต้องการระยะขอบชุดเดียวกัน
ทางเลือกที่เหลือคือ `.acct-pager` ที่เขียนเลขสามตัวเดิมซ้ำ ซึ่งคือสำเนาที่จะเริ่ม
ไม่ตรงกันวันหนึ่ง · `.queue-pager` ยังอยู่ ถือประกาศเดียวที่เป็นของคิวจริง ๆ คือ
`margin-top: 0` ใต้ 860px เพราะแถวของคิวเป็นการ์ดที่ `tbody` เว้นใต้ใบสุดท้ายไว้
12px แล้ว ส่วน `.acct-table` ยังเป็นตารางที่ความกว้างนั้น จึงใช้ 8px ของกฎกลาง

## 7. ทางที่ไม่ได้เลือก

* **ไม่แบ่งหน้าที่เซิร์ฟเวอร์** ทั้งเดือนถูกดึงมาครั้งเดียว (`company=all`) แล้ว
  แบ่งตามบริษัทในเบราว์เซอร์อยู่แล้ว — การสลับบริษัทคือตัวกรอง ไม่ใช่รอบใหม่
* **ไม่แตะตาราง รวมทุกบริษัท** มีสองแถวกับยอดรวม แถบใต้มันคือกรอบรอบสองแถว
* **ไม่แตะ `AccountingPrint.jsx`** ใบพิมพ์แบบฟอร์มเป็นเอกสารคนละใบ ไม่เคยมีหน้า
* **ไม่ทำให้แถบพิมพ์ออกมาด้วยแล้วเขียนว่า "หน้า 1 / 3"** กระดาษมีหน้าของมันเอง
  และมันไม่ตรงกับหน้าของจอ
