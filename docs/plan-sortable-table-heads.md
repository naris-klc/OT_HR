# หัวตารางกดเรียงได้ทั้งแอป — แผนงาน

**สั่งมา 2026-09-10:** *"และหัวตาราง ของทั้ง app ควร sort ได้"* — ต่อจากรอบ
แถบตัวกรองเดียวทั้งแอปในวันเดียวกัน

**สถานะ: ยังไม่เริ่มเขียนโค้ด** เอกสารนี้คือสิ่งที่ต้องตกลงกันก่อนลงมือ เพราะ
คำว่า "ทั้ง app" กับตารางสิบแปดตัวในแอปนี้ ไม่ได้แปลว่าอย่างเดียวกันทุกตัว

---

## 1. วันนี้ยังไม่มีตารางไหน sort ได้เลย

`grep -rn "aria-sort\|sortBy\|onSort\|sortKey" components/ lib/` คืนค่าว่าง —
ไม่มีของเดิมให้ต่อยอด และไม่มีของเดิมให้ขัดกัน ทุกตารางเรียงมาจากที่เดียว คือ
ลำดับที่ route ส่งมา

## 2. ตารางสิบแปดตัว แบ่งได้สี่กลุ่ม และมีแค่กลุ่มเดียวที่ตรงไปตรงมา

| กลุ่ม | ตาราง | กด sort ได้ไหม |
|---|---|---|
| **ก · รายการล้วน** | `queue-table` (รออนุมัติ OT) · `stack-table` (ทะเบียนพนักงาน · รายการ OT ของฉัน · ตรวจสอบใบของพนักงาน · ประวัติการแก้ทะเบียน · ผู้รับช่วงอนุมัติ · วันหยุดบริษัท) · `log-table` (บันทึกประวัติระบบ ทั้งสามแท็บ) · `cmp-table` (การใช้สิทธิ์พิเศษ) | **ได้ ตรงไปตรงมา** |
| **ข · มีแถวรวมท้ายตาราง** | `hr-table` (ตรวจสอบประจำเดือน) · `acct-table` + `allco-table` (การเงิน) · `dept-table` (แยกแผนก) | **ได้ แต่ `<tfoot>` ห้ามขยับ** |
| **ค · ลำดับคือความหมาย** | `dept-table` มีคอลัมน์ `ลำดับที่` ที่นับ 1 ใหม่ทุกแผนก **เพื่อให้ตรงกับใบที่พิมพ์** — คอมเมนต์ใน `DepartmentView.jsx` เขียนไว้ว่า "บรรทัดบนจอกับบรรทัดบนกระดาษถือเลขเดียวกันและอ่านเทียบกันได้ด้วยตา" | ⚠ **ต้องตัดสินใจ — ดูข้อ 5** |
| **ง · ไม่ใช่ตารางข้อมูล** | `cal-table` (ปฏิทินวันหยุด) · `manual-table` (คู่มือ) · `pver-table` (รุ่นนโยบาย เรียงตามเวลาโดยธรรมชาติ) · `deptset-table` (ตั้งค่าแผนก) | **ไม่ทำ** |

## 3. รูปแบบที่จะใช้ — ตามที่นิยมกัน

- กดที่ `<th>` = เรียงจากน้อยไปมาก · กดซ้ำ = กลับด้าน · กดครั้งที่สาม = กลับไป
  ลำดับเดิมของ route (ไม่ใช่วนสองสถานะ — คนที่เผลอกดต้องมีทางกลับ)
- `aria-sort="ascending" | "descending" | "none"` บน `<th>` ที่เรียงอยู่
- ลูกศรจาง ๆ บนหัวที่ยังไม่ถูกเลือก แสดงว่ากดได้ · ลูกศรทึบบนหัวที่เรียงอยู่
- `<th>` ที่ sort ไม่ได้ (จัดการ · หมายเหตุ) ไม่มีลูกศร ไม่มี cursor pointer
- คีย์บอร์ด: `<th>` เป็น `<button>` ข้างใน ไม่ใช่ `onClick` บน `<th>` เปล่า

## 4. ที่ต้องเขียนใหม่

- `lib/tableSort.js` — เทียบค่าแบบเดียวทั้งแอป: ตัวเลข · วันที่ · **ไทยด้วย
  `localeCompare(a, b, 'th')`** (แอปนี้เรียงชื่อแผนกด้วย `'th'` อยู่แล้วใน
  `HrView.jsx`) · ค่าว่างไปท้ายเสมอไม่ว่าจะเรียงทางไหน
- `useSort(rows, initial)` + `<SortHead>` ใน `components/common.jsx` — ที่เดียว
  ที่รู้เรื่องลูกศร `aria-sort` และการวนสามสถานะ
- `app/styles.css` — `th.sortable` และลูกศร

## 5. ⚠ สี่ข้อที่ต้องให้ผู้ใช้ตัดสิน ก่อนเขียนโค้ด

1. **`dept-table` กับคอลัมน์ `ลำดับที่`** — ถ้าเรียงใหม่ เลขบนจอจะไม่ตรงกับใบที่
   พิมพ์อีกต่อไป ทางเลือก: (ก) ห้าม sort ตารางนี้ (ข) sort ได้ แต่ `ลำดับที่`
   เดินตามลำดับใหม่ (เลขบนจอ ≠ เลขบนกระดาษ) (ค) sort ได้ และ `ลำดับที่` ยัง
   ติดกับแถวเดิม (เลขกระโดด 3 · 1 · 7) — **ผมเสนอ (ก)** เพราะจอนี้มีไว้อ่าน
   เทียบกับกระดาษ
2. **มือถือ** — ต่ำกว่า 860px ทุกตารางกลายเป็นการ์ด `thead` ถูกซ่อน จึงไม่มีหัว
   ให้กด ถ้าอยากให้ sort ได้บนมือถือด้วย ต้องมี dropdown **เรียงตาม** บนแถบ
   ตัวกรอง ซึ่งเป็นงานอีกก้อน — **ผมเสนอ: รอบนี้เดสก์ท็อปก่อน**
3. **sort ฝั่งไหน** — ตารางที่แบ่งหน้า (`log-table` 161 แถว 17 หน้า) ถ้าเรียง
   ในเบราว์เซอร์จะเรียงแค่หน้าที่เห็น ซึ่งเป็นการโกหกโดยการละเว้น ทางเลือก:
   ส่ง `?sort=` ไป route (งานหลังบ้าน) หรือปิด sort บนตารางที่แบ่งหน้า —
   **ผมเสนอ: ตารางที่โหลดครบทั้งชุดให้เรียงในเบราว์เซอร์ · ตารางที่แบ่งหน้าจาก
   เซิร์ฟเวอร์ยกไปทำรอบถัดไป**
4. **จำค่าที่เลือกไว้ไหม** — เปลี่ยนแท็บแล้วกลับมา ยังเรียงแบบเดิมอยู่หรือกลับ
   เป็นค่าตั้งต้น — **ผมเสนอ: กลับเป็นค่าตั้งต้น** (ไม่เก็บ ไม่ต้องอธิบาย)

## 6. ลำดับงานที่ตั้งใจ

1. `lib/tableSort.js` + เทสต์ของมัน (เทียบไทย · ค่าว่าง · วันที่)
2. `useSort` + `SortHead` ใน `common.jsx` + `th.sortable` ใน `styles.css`
3. กลุ่ม ก ทีละตาราง
4. กลุ่ม ข — `<tfoot>` อยู่นอก `useSort` โดยโครงสร้าง ไม่ใช่โดยกฎ
5. `test/tableSort.test.js` ปักว่าทุกตารางในกลุ่ม ก และ ข มีหัวที่กดได้ และ
   กลุ่ม ง ไม่มี
