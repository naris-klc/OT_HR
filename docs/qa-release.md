# ด่านก่อนส่งมอบ — ต้องผ่านอะไรก่อนพูดว่า "พร้อม deploy"

เขียน 2026-10-10 ตามที่ผู้ใช้สั่ง · ใช้ทุกครั้งที่ agent จะส่งงานให้ผู้ใช้เอาไป deploy

**ทำไมต้องมีไฟล์นี้** — agent ที่บอกว่า "เทสต์ผ่านหมด" อาจส่งระบบที่คนใช้จริง
เข้าไม่ได้เลย เพราะมันทดสอบเฉพาะสิ่งที่มันคิดถึง และใช้บัญชีที่มีอยู่แค่ใน
browser automation ของมันเอง ไฟล์นี้กำหนดว่า "เสร็จ" แปลว่าอะไร และรายงานต้อง
บอกตรง ๆ ว่าข้อไหน*ไม่ได้*ทดสอบ

---

## กติกา

1. **ทำทุกชั้นที่สิ่งที่เปลี่ยนไปแตะถึง** ชั้นไหนไม่ได้ทำให้เขียน NOT TESTED
   พร้อมเหตุผล ห้ามละไว้เฉย ๆ เพราะการละไว้จะถูกอ่านว่าผ่าน
2. **ตัวเลขในรายงานต้องมาจากการรันจริงในรอบนั้น** ไม่ใช่จากรายงานรอบก่อน
3. **ห้ามลด assertion ห้ามลบหรือ skip เทสต์ที่ตก และห้ามปิด validation**
   เพื่อให้ผลออกมาเขียว ถ้าเห็นว่าเทสต์ผิดเอง ให้เขียนเหตุผลไว้ในคอมมิต
4. **บั๊กทุกตัวที่แก้ต้องมีเทสต์ที่ตกก่อนแก้และผ่านหลังแก้** ถ้าเขียนเทสต์
   อัตโนมัติไม่ได้ (เช่นเรื่องเวลาตอบ) ให้บันทึกตัวเลขก่อนและหลังแก้แทน
5. **ห้ามแตะฐานจริง** ทดสอบบนฐาน QA เท่านั้น (ชั้นที่ 2) · deploy เป็นการตัดสินใจ
   ของผู้ใช้ ไม่ใช่ขั้นตอนหนึ่งของการทดสอบ
6. **ห้ามใส่รหัสผ่าน secret หรือข้อมูลพนักงานจริงลงในรายงานหรือคอมมิต**
7. **เรื่องหน้าตาไม่แก้เอง** ให้บันทึกไว้แล้วรอผู้ใช้ตัดสิน (AGENTS.md
   §จอใหม่ไม่ได้เริ่มจากศูนย์) · ส่วนบั๊กที่ทำให้ข้อมูลผิด ระบบล่ม หรือข้ามสิทธิ์ได้ แก้ได้เลย

### สถานะของแต่ละข้อ

| สถานะ | ความหมาย |
|---|---|
| PASS | รันจริงแล้ว ผลตรงกับที่คาด และมีหลักฐาน (output ของคำสั่ง, HTTP status, ค่าในฐาน) |
| FAIL | รันแล้วไม่ผ่าน หรือพบบั๊ก |
| BLOCKED | ทดสอบต่อไม่ได้ ต้องระบุว่าขาดอะไร (สิทธิ์, เครื่องมือ, ข้อมูล) |
| NOT TESTED | ยังไม่ได้ทดสอบ ต้องระบุเหตุผล |

**ห้ามเขียนว่า "พร้อม deploy" ถ้ายังมี FAIL ที่ทำให้ข้อมูลผิด ระบบล่ม หรือข้าม
สิทธิ์ได้** หรือมีข้อ BLOCKED/NOT TESTED ในเรื่องที่งานรอบนี้เปลี่ยน

## ชั้นที่ 1 — เทสต์อัตโนมัติและ build

```bash
npm test                                                        # ไม่ต่อฐานข้อมูล รันได้ทุกเมื่อ
VERIFY_DIST_DIR=.next-verify-<task> npx next build --webpack    # ใน worktree
```

- build ต้องใช้ distDir แยกเสมอ ห้ามรัน `npm run build` เปล่า ๆ บนแล็ปท็อป
  (AGENTS.md §What serves this app)
- `--webpack` ไม่ได้พิสูจน์ว่า build ด้วย Turbopack ผ่าน ถ้างานแตะ `next.config.js`
  หรือ loader ต้อง build ซ้ำใน tree หลักหลัง merge

## ชั้นที่ 2 — ฐาน QA และ server สำหรับทดสอบ

```bash
# seed ล้างฐานปลายทางแล้วเติมใหม่ · ถ้าฐานนั้นมีข้อมูลที่ seed ไม่ได้สร้าง มันจะปฏิเสธ
# ห้ามใส่ --force เพื่อให้ผ่าน ถ้ามันปฏิเสธ แปลว่า URI อาจชี้ผิดฐาน
MONGODB_URI=mongodb://127.0.0.1:<พอร์ตใน .env>/primus_ot_qa npm run seed

MONGODB_URI=mongodb://127.0.0.1:<พอร์ตใน .env>/primus_ot_qa \
JWT_SECRET=<สุ่มใหม่ คนละตัวกับของจริง> \
VERIFY_DIST_DIR=.next-verify-<task> npx next start -p 3011 -H 127.0.0.1
```

- `JWT_SECRET` ต้องเป็นคนละตัวกับของจริง เพื่อให้คุกกี้ของสองฝั่งใช้แทนกันไม่ได้
- ถ้าต้องใช้ข้อมูลจริง ใช้ `npm run restore -- <โฟลเดอร์ backup> --to <URI ฐาน QA> --yes`
  แล้วดูแลฐานนั้นเท่ากับฐานจริง ([testing-safely.md](testing-safely.md) §เอาข้อมูลจริงมาลงฐานทดสอบ)
- port 3011 ใช้ตรวจเองเท่านั้น ส่วน 3005 คือพรีวิวที่ให้ผู้ใช้ดู (AGENTS.md)

## ชั้นที่ 3 — ไล่ทุกจอด้วย browser

```bash
QA_BASE=http://127.0.0.1:3011 npm run qa:sweep                 # 8 บทบาท ~6 นาที
QA_BASE=http://127.0.0.1:3011 QA_ROLE=hr npm run qa:sweep      # บทบาทเดียว
```

[scripts/qa-sweep.js](../scripts/qa-sweep.js) ล็อกอินด้วยบัญชีจาก seed แล้วกดทุกเมนู
ของทั้ง 8 บทบาท (4 บทบาทจนถึง 2026-10-10 — การเงินและผู้อนุมัติขั้นสูงไม่เคยถูกไล่
เพราะ seed ไม่มีบัญชี) ไล่ 7 ความกว้าง สองธีม และหน้าพิมพ์ ตรวจ console error, 5xx,
หน้าเลื่อนแนวนอน, ของที่ล้นจอ, ปุ่มเล็กกว่า 24px, เมนูล่างหรือข้างผิดฝั่ง
breakpoint และ axe (WCAG 2.1 AA) · **สคริปต์อ่านอย่างเดียว ไม่กดปุ่มในจอ**

- บัญชีของแต่ละบทบาทอยู่ในตารางบัญชี seed ของ README · ฐานที่ใช้รหัสอื่น (เช่น
  บัญชี `[ทดสอบ]` บนฐานของเครื่อง dev) ส่งรหัสแทนด้วย
  `QA_ACCOUNTS=บทบาท=รหัส,บทบาท=รหัส` ชื่อบทบาทตาม `ROLES` ในสคริปต์
- คืนค่า exit 1 เมื่อเจอปัญหา ให้เทียบกับ `docs/plan-qa-fixes-*.md` ฉบับล่าสุดก่อน
  ว่าข้อไหนผู้ใช้รู้แล้วและสั่งให้รอไว้
- ไม่ตรวจขนาดตัวอักษรในช่องกรอก เพราะ 15px ทุกความกว้างเป็นสิ่งที่ผู้ใช้เลือกเอง ([design.md](design.md))
- ใช้ Chrome หรือ Edge ที่ติดตั้งอยู่แล้ว ไม่ดาวน์โหลด browser ใหม่ · ถ้าต้องใช้ตัวอื่น ตั้ง `CHROME_PATH`
- จอที่งานรอบนี้เปลี่ยน ให้เดินด้วยมือเพิ่ม (กดปุ่ม กรอกฟอร์ม) ตามรายการใน
  AGENTS.md §Before you call a screen done

## ชั้นที่ 4 — สิ่งที่ระบบนี้พังได้

ทำเฉพาะหัวข้อที่งานรอบนี้แตะ · ยิง API บน :3011 แล้วตรวจผลในฐาน QA ด้วย ไม่ใช่ดูแค่ข้อความบนจอ

| หัวข้อ | ต้องตรวจ |
|---|---|
| สิทธิ์ | ทุก route ที่ไม่มี session ต้องได้ 401 · ยิงข้ามบทบาท · เปลี่ยน id เป็นของคนอื่น (IDOR) · หัวหน้าต้องไม่เห็นวันเกิดหรือ hash · หัวหน้าที่เป็น HR ด้วย |
| login | throttle · เวลาตอบของรหัสที่มีกับไม่มีต้องใกล้กัน · รหัสผ่านแรกเข้า · ถ้าแตะ auth ต้องเช็กว่า `npm run reset-admin` ยังกู้บัญชีแอดมินได้ |
| input | body ผิดรูป ค่าว่าง ค่ายาวเกิน ชนิดผิด ต้องได้ 4xx ไม่ใช่ 500 |
| คำนวณ OT | วันหยุด วันเกิด เหมารายวัน เพดาน และการปัดเศษ ต้องตรงกับที่คำนวณด้วยมือ · ถ้าแก้กติกา ใช้ `npm run whatif` ดูว่าตัวเลขที่อนุมัติแล้วจะเปลี่ยนกี่ใบ |
| งวดที่ปิดแล้ว | ตัวเลขต้องไม่เปลี่ยนย้อนหลัง ไม่ว่าจะ replay นโยบายหรือ recompute |
| flow | ยื่น → หัวหน้า → HR → อนุมัติ · ถอน · ยกเลิก · ย้อนการอนุมัติ ตรวจสถานะในฐานทุกขั้น |
| ทำพร้อมกัน | กดอนุมัติซ้ำ · สองแท็บอนุมัติใบเดียวกัน · สองคนแก้ใบเดียวกันแล้วต้องไม่ทับกันเงียบ ๆ · logout แล้ว login เป็นอีกคนระหว่างหน้ายังโหลดอยู่ ข้อมูลของคนก่อนต้องไม่โผล่ |
| import สแกนนิ้ว | ไฟล์ซ้ำ · ไฟล์ผิดรูป · ไฟล์ที่มีข้อมูลบางส่วน |
| พิมพ์ | ใบ F-HR-027 และ PDF |
| ข้อมูลไม่หาย | `npm run backup` แล้ว restore ลงฐาน QA ต้องใช้งานได้ · migration ที่เพิ่มใหม่ต้องรันซ้ำบนฐาน QA แล้วผลไม่เปลี่ยน · restart server แล้วข้อมูลยังอยู่ |
| เครื่องปลายทาง | ระบุว่าทดสอบบนแล็ปท็อปหรือเครื่อง Docker ([docker.md](docker.md)) และบอกว่ามีอะไรที่ยังไม่ได้ทดสอบบนอีกเครื่อง |

## ชั้นที่ 5 — ผู้ใช้ต้องใช้ได้เอง

หลัง merge แล้ว ให้เปิดพรีวิว :3005 จาก main ตาม AGENTS.md แล้วเขียน
**"สิ่งที่คุณควรลองเองก่อน deploy"** ไว้ในรายงาน 3–5 ข้อ เป็นขั้นตอนที่ใช้บัญชี
ที่ผู้ใช้มีอยู่จริง ไม่ใช่บัญชีที่ seed สร้างหรือ session ที่ automation ถือไว้

ถ้างานรอบนี้แตะการล็อกอิน รหัสผ่าน หรือสิทธิ์ ให้ตอบในรายงานว่า ถ้าแอดมินเข้าระบบ
ไม่ได้หลัง deploy จะกู้กลับมาอย่างไร
