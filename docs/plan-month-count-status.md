## 1. งบความสูงที่มีอยู่จริง — **สองบรรทัด ฟรี บรรทัดที่สามเสียเงิน**

วัดจากซอร์ส ไม่ได้เดา:

| เซลล์ | วันนี้วาดกี่บรรทัด |
|---|---|
| `who-col` **พนักงาน** | **2** — ชื่อ แล้ว `รหัส` 12px ใต้ชื่อ (`components/HrView.jsx`) |
| `cap-col` **สะสม / เพดาน** | **2** — `26 / 40` แล้ว `รวมรออนุมัติ 28 / 40` |
| `count-col` **รายการ** | **1** ปกติ · **2** เมื่อมี `ค้าง n` · **3** เมื่อมี `HR อนุมัติชั้นเดียว n` ด้วย |
| ที่เหลือ | 1 |

**ความสูงของแถวถูกกำหนดโดยเซลล์ที่สูงที่สุด ซึ่งวันนี้คือสองบรรทัดอยู่แล้ว**
คอลัมน์ `รายการ` จึงมีบรรทัดที่สอง**ให้ใช้ฟรี** — ใช้แล้วแถวไม่สูงขึ้นเลย
บรรทัดที่สามคือบรรทัดที่ทำให้ทุกแถวในตารางสูงขึ้นพร้อมกัน

⚠️ **และวันนี้มันเลยงบไปแล้วในบางแถว** — `ค้าง n` กับ `HR อนุมัติชั้นเดียว n`
เป็นบรรทัดที่สองและสาม เจอพร้อมกันเมื่อไหร่แถวนั้นก็สูงกว่าเพื่อน · แบบที่เสนอ
ข้างล่างนี้**กิน `ค้าง n` เข้าไปด้วย** เพราะมันคือข้อมูลเดียวกันที่ละเอียดกว่า
ผลคือกรณีที่เคยสามบรรทัดจะเหลือสอง

## 2. งบความกว้าง — คอลัมน์นี้ไม่มีความกว้างประกาศไว้

`app/styles.css` ประกาศความกว้างให้ `who-col` 196 · `dept-col` 160 ·
`cap-col` 152 · `act-col` 104 — **`count-col` ไม่มี** มันกว้างตามเนื้อหา
ซึ่งวันนี้คือหัวคอลัมน์คำว่า `รายการ` ราว 46px

ที่กว้างขึ้นตรงนี้ ต้องไปเอามาจาก `who-col` กับ `dept-col` และหมายเหตุใน
สไตล์ชีตบันทึกไว้แล้วว่าสองคอลัมน์นั้น**เคยโดนบีบจนชื่อกับแผนกแตกบรรทัดกลางคำ
มาแล้วรอบหนึ่ง** — `แผนก / บัญชี / และ / การ / เงิน` ห้าบรรทัด ·
**เพดานที่ปลอดภัยคือราว 90px** เกินกว่านั้นต้องวัดชื่อยาวที่สุดใหม่

## 3. บนมือถือไม่ต้องออกแบบ — คอลัมน์นี้ถูกซ่อน

ใต้ 860px `.hr-table tbody td.count-col { display: none; }` เป็นหนึ่งในเจ็ด
คอลัมน์ที่การ์ดตัดทิ้ง · **งานนี้จึงเป็นงานของจอคอมพิวเตอร์ล้วน ๆ** ไม่มีครึ่ง
ที่สองของดีไซน์ให้ตกลง ซึ่งผิดปกติสำหรับจอนี้และเป็นเหตุผลที่เขียนข้อนี้ไว้

> ⚠️ ถ้าอยากให้มือถือเห็นด้วย นั่นเป็นอีกคำถามหนึ่ง — การ์ดมือถือมีแถวของตัวเอง
> (`grid-template-areas`) และการเพิ่มแถวที่แปดคือการเพิ่มความสูงของการ์ดทุกใบ
> ซึ่งเป็นสิ่งที่รอบ *กระชับ* เมื่อวันที่ 10–11 ก.ย. เพิ่งตัดออกไป

## 4. ตัวเลขที่มีให้ใช้ — เราต์ส่งมาครบแล้ว ไม่ต้องแก้หลังบ้าน

`app/api/reports/monthly/[period]/route.js` ส่งมาต่อแถว:

| ฟิลด์ | คือ |
|---|---|
| `entryCount` | จำนวนใบทั้งหมดในเดือน **ตามสถานะที่นับ** |
| `pendingCount` | `status !== 'approved'` — **รวม `pending_mgr` ด้วย** คือเลขที่ `ค้าง n` ใช้อยู่ |
| `pendingHrCount` | `status === 'pending_hr'` เท่านั้น |
| `approvable.count` | ใบที่**ผู้อ่านคนนี้**กดยืนยันได้ — ต่างจาก `pendingHrCount` ด้วยกฎ §6 |

**สามเลขที่จะแสดงคำนวณได้ครบจากนี้:**

```
อนุมัติ    = entryCount - pendingCount
รอหัวหน้า  = pendingCount - pendingHrCount
รอ HR     = pendingHrCount
```

⚠️ **และมันขึ้นกับ `สถานะที่นับ`** — ที่ `อนุมัติแล้วเท่านั้น` สองเลขหลังเป็นศูนย์
เสมอ ไม่ใช่เพราะไม่มีใบค้าง แต่เพราะตัวกรองไม่ได้นับมันมา · **นี่เป็นข้อที่ต้อง
ตัดสิน** ดูข้อ 6

## 5. สามแบบที่เสนอ

### แบบ ก — สามช่องคงที่ใต้เลขรวม *(แนะนำ)*

```
┌─ รายการ ────────┐
│ อนุ · หัว · HR  │   ← หัวคอลัมน์ถือคำอธิบาย 10px สีจาง
├─────────────────┤
│       12        │   ← เลขรวม เหมือนเดิมทุกอย่าง
│   5    2    3   │   ← สามช่องกว้างเท่ากัน ศูนย์วาดเป็น –
└─────────────────┘
    ~84px · 2 บรรทัด
```

- **ตำแหน่งคือความหมาย** ไม่ใช่สีคือความหมาย — สีเป็นตัวช่วย ไม่ใช่ตัวเดียวที่
  แบก ซึ่งเป็นกฎของ `docs/design.md` §3
- ช่องกว้างเท่ากันตายตัว **เลขจึงตรงคอลัมน์กันลงมาทั้งตาราง** กวาดตาหาคนที่
  `รอ HR` เยอะได้โดยไม่ต้องอ่านทีละแถว
- ศูนย์เป็น `–` ไม่ใช่ `0` — ช่องว่างทำให้คอลัมน์อ่านยาก ส่วน `0` แย่งสายตาเท่ากับ
  เลขจริง
- เป็นสำนวนเดิมของตารางนี้อยู่แล้ว: เลขใหญ่ + บรรทัดเล็กใต้มัน แบบเดียวกับ
  `สะสม / เพดาน` และแบบเดียวกับ `ค้าง n` ที่มันจะมาแทน
- **ราคา** ผู้อ่านต้องเงยไปดูหัวคอลัมน์รอบแรก · แก้ด้วย `title` บนเซลล์ที่เขียน
  เต็มคำว่า *อนุมัติแล้ว 5 · รอหัวหน้า 2 · รอฝ่ายบุคคล 3*

### แบบ ข — บรรทัดคำ ตัดตัวที่เป็นศูนย์ทิ้ง

```
┌─ รายการ ──────────────┐
│          12           │
│  อนุมัติ 5 · รอ HR 3   │   ← เขียนเฉพาะสถานะที่มีจริง
└───────────────────────┘
    ~110px · 2 บรรทัด
```

- **อ่านออกทันทีโดยไม่ต้องมีคำอธิบายที่หัวคอลัมน์**
- **ราคาสองข้อ และหนักทั้งคู่**
  - แถวที่มีครบสามสถานะจะยาว ~150px — **เกินเพดาน 90px ในข้อ 2** ต้องตัดคำจน
    เหลือ `อนุ 5 · หัว 2 · HR 3` ซึ่งกลายเป็นแบบ ก ที่อ่านยากกว่า
  - ความยาวไม่เท่ากันทุกแถว **เลขจึงไม่ตรงคอลัมน์กัน** กวาดตาลงมาไม่ได้

### แบบ ค — ป้ายเล็กสามใบ

```
┌─ รายการ ────────┐
│       12        │
│  ✓5   ⧗2   ●3   │   ← ใช้ .chip ที่มีอยู่แล้ว
└─────────────────┘
    ~92px · 2 บรรทัด
```

- ใช้ชุดที่มีอยู่ (`.chip`) ไม่ต้องประดิษฐ์อะไรใหม่
- **ราคา** คอลัมน์ `สแกน` ที่อยู่ถัดไปสองช่องก็เป็นป้ายสามสถานะเหมือนกัน
  (`ตรง` / `เวลาไม่ตรง n` / `ไม่ได้สแกน`) — **ป้ายสองกลุ่มในแถวเดียวกันที่ไม่
  เกี่ยวกันเลยคือจุดที่ตารางเริ่มอ่านเหมือนแผงไฟ** · และไอคอนสามตัวที่ไม่เคยมี
  ในแอปนี้ต้องนิยามความหมายใหม่ทั้งสามตัว

## 6. ข้อที่ต้องตัดสินก่อนลงมือ

1. **เลือกแบบไหน** — ก / ข / ค
2. **เลขรวมอยู่ต่อไหม** หรือให้สามช่องแทนมันไปเลย (ประหยัดหนึ่งบรรทัด แต่
   `รวมทั้งหมด` แถวล่างสุดยังต้องการเลขรวมอยู่ดี)
3. **`ค้าง n` กับ `HR อนุมัติชั้นเดียว n` เอายังไง** — ข้อเสนอนี้ให้ `ค้าง n`
   หายไปเพราะซ้ำซ้อน ส่วน `HR อนุมัติชั้นเดียว n` เป็นคนละเรื่อง (ใบที่ไม่มี
   ลายเซ็นหัวหน้าเลย) และควรอยู่ต่อ — **แต่มันคือบรรทัดที่สาม**
4. **ที่ `สถานะที่นับ` แคบ ๆ จะพูดยังไง** — ที่ `อนุมัติแล้วเท่านั้น` สองช่องหลัง
   เป็นศูนย์เสมอ ซึ่ง*ถูก* แต่**อ่านเหมือนบอกว่าคนนี้ไม่มีใบค้าง** ทั้งที่แปลว่า
   ตัวกรองไม่ได้นับมา · ทางเลือก: ซ่อนสองช่องนั้นเมื่อตัวกรองไม่ได้นับสถานะนั้น
   มาเลย แล้วหัวคอลัมน์ก็สั้นลงตาม
