สี่ข้อในรอบเดียว — ชิปสลับ · นับรวมบนแท็บ · มือถือทำเหมือนกัน · ออกแบบการแสดงผล

เอกสารนี้คือแบบที่ตกลงกันก่อนเขียนโค้ด ตาม AGENTS.md §จอใหม่ไม่ได้เริ่มจากศูนย์

## 1. ทำไมไม่ใช่ตารางเดียวที่มีสองชนิดแถวปนกัน

ถามไปตอนแรกและตอบกันแล้ว แต่บันทึกไว้เพราะเป็นเหตุผลที่ทำให้ **ชิป** ถูก ไม่ใช่
แค่สวยกว่า

| | รออนุมัติ | คำขอถอนใบที่อนุมัติแล้ว |
|---|---|---|
| ดึงจาก | `/entries?status=…&usage=cap` | `/entries?withdrawal=open` |
| สถานะใบ | ยังไม่มีลายเซ็น | `approved` / `pending_hr` แล้ว |
| การตัดสิน | ให้ชั่วโมงเข้า | เอาชั่วโมงที่นับไปแล้วออก |
| ช่องติ๊ก + ปุ่มกอง | มี | มีปุ่มรวมคนละตัว และ **ไม่มีปฏิเสธแบบกอง** |
| คอลัมน์เพดาน | มี | ไม่เกี่ยว |

ปนกันในตารางเดียวเมื่อไร ช่องติ๊ก · เลือกทั้งหมด · แถบปุ่มกอง · คอลัมน์เพดาน
ต้องเรียนรู้ที่จะข้ามแถวถอนทุกอัน และหน้าจอจะมีปุ่มชื่อ "ทั้งหมด" สองตัวที่ทำ
คนละเรื่องพร้อมกัน — ซึ่งคือเหตุผลที่ `components/WithdrawalRequests.jsx` ถูกแยก
ออกมาตั้งแต่แรก

**ชิปแก้ได้เพราะสองตารางไม่เคยอยู่บนจอพร้อมกัน** ไม่มีอะไรต้องเรียนรู้ที่จะข้าม

## 2. สืบทอด ไม่ประดิษฐ์ — `.queue-tabs` ยังอยู่ในสไตล์ชีต

`app/styles.css` มีบล็อก `/* ══ queue tabs ══ */` อยู่แล้ว เขียนไว้ตอนหน้าจอนี้มี
สองกอง (ใบรอยืนยัน / วันเกิดรอตรวจ) คอมเมนต์เปิดบล็อกเขียนว่า *"Two piles of
work on one screen … Drawn as a segmented control rather than as underlined
tabs"* — โจทย์เดียวกับรอบนี้ทุกตัวอักษร

คอมโพเนนต์ `QueueTabs.jsx` ถูกลบไป 2026-09-03 ตอนกองที่สองหายไป **แต่ CSS ไม่ได้
ถูกลบ** วันนี้ไม่มีไฟล์ไหนอ้างถึงมันเลย (มีแต่คอมเมนต์ใน
`test/roleNavTabs.test.js`) — เท่ากับเป็น CSS ตาย ที่เป็นของสำหรับงานนี้พอดี

**จะใช้ซ้ำ ไม่เขียนใหม่** ของที่ได้มาฟรีคือ: กล่อง segmented พร้อมพื้น
`--neutral-wash` · ปุ่ม `flex: 1` (จอแคบจึงแบ่งครึ่งเอง) · สถานะ `.active` พร้อม
เงา · และ `.queue-tabs .count` ซึ่งเป็นตัวเลขบนชิปที่กลับสีตอนถูกเลือก

คอมเมนต์เดิมที่ว่า *"The sidebar badge carries the SUM of the two"* กลับมาเป็น
จริงอีกครั้งพอดี — `queueBadge` คือผลบวก ชิปคือกองละอัน

## 3. โครงหน้าจอ

```
┌─ card flush ───────────────────────────────────────────────────────┐
│ [ รออนุมัติ 12 ][ คำขอถอน 3 ]        [+ บันทึก OT แทนพนักงาน]      │  ← card-head
│ ตรวจสอบรายวัน · เฉพาะแผนกผลิต1                                      │  ← hint (เปลี่ยนตามชิป)
├────────────────────────────────────────────────────────────────────┤
│ (แบนเนอร์: รับช่วงอนุมัติแทน · PolicyDriftBanner · แสดง n จาก m)     │
│ (แถบตัวกรอง .queue-tools)                                           │  ← เฉพาะชิป รออนุมัติ
│ (ตาราง + แถบปุ่มกอง + ตัวแบ่งหน้า)                                   │
└────────────────────────────────────────────────────────────────────┘
```

### 3.1 หัวการ์ด

- **ชิปแทนบรรทัดชื่อ** `.t` เดิม (`รออนุมัติ` / `รออนุมัติ OT`) หายไปตอนมีชิป
  ชื่อกองไปอยู่บนชิปตัวแรกแทน
- **ตัวเลขที่เคยพิมพ์สองที่ หายไปทั้งคู่** ตอนนี้ `countLabel` ถูกวาดสองรอบ —
  `.t-count` บนจอเล็ก และ `.chip muted` บนเดสก์ท็อป โดยมีอันเดียวโผล่ต่อความกว้าง
  ชิปพกตัวเลขของตัวเองอยู่แล้วและเห็นทุกความกว้าง สองอันนั้นจึงไม่วาดตอนมีชิป
  (ตัว `countLabel` ยังคำนวณอยู่ ไม่แตะ — มันคือที่เดียวที่รู้ว่า `3 / 12 รายการ`
  ตอนกรองอยู่ และมันไปอยู่บน **hint** แทน ดู §3.2)
- **ปุ่มขวาเปลี่ยนตามชิป** — `+ บันทึก OT แทนพนักงาน` บนชิปรออนุมัติ ·
  `อนุมัติให้ถอนทั้งหมด` บนชิปคำขอถอน (ยังวาดเฉพาะเมื่อมีตั้งแต่สองใบขึ้นไป ตาม
  เหตุผลเดิมในหัวไฟล์ `WithdrawalRequests.jsx`) ทั้งสองปุ่มไม่มีทางอยู่พร้อมกัน

### 3.2 บรรทัด hint ใต้ชิป

เปลี่ยนตามชิป เพราะสองกองอธิบายตัวเองคนละเรื่อง:

| ชิป | hint |
|---|---|
| รออนุมัติ | ของเดิมทุกตัวอักษร (`ตรวจสอบรายวัน · เฉพาะแผนก…` / `ตรวจสอบรายเดือน · …` / ข้อความคิวรับช่วง) และต่อท้ายด้วย `· {countLabel}` |
| คำขอถอน | `พนักงานขอถอนรายการที่มีผู้อนุมัติไปแล้ว · รายการเหล่านี้ยังมีผลและยังถูกนับอยู่จนกว่าจะอนุมัติให้ถอน` (ของเดิม) |

`countLabel` ย้ายลงมาที่นี่เพราะชิปพกได้แค่จำนวนเต็ม ส่วน `3 / 12 รายการ` ตอน
ตัวกรองทำงานอยู่เป็นข้อมูลที่หายไปไม่ได้ — คนอ่านต้องแยกออกว่าคิวว่างจริง หรือ
ตัวกรองซ่อนอยู่

### 3.3 ชิปโผล่เมื่อไร

**ไม่มีคำขอถอนค้าง = ไม่มีแถบชิป** หัวการ์ดกลับเป็นชื่อ + ตัวเลขแบบเดิมทุกอย่าง

สองเหตุผล ทั้งคู่มีของเดิมยืนอยู่:

1. `WithdrawalRequests.jsx` คืน `null` เมื่อไม่มีแถว และเขียนเหตุผลไว้ว่า *"a
   permanent empty panel for a thing that happens a few times a month is a row
   of furniture they learn to read past"* — ชิปที่เขียนว่า `คำขอถอน 0` ทุกวันคือ
   เฟอร์นิเจอร์ชิ้นเดียวกันในรูปที่เล็กลง
2. segmented control ที่มีช่องเดียวคือสิ่งที่ฆ่า `QueueTabs.jsx` เมื่อ
   2026-09-03 — *"the wrapper was a tab bar with one tab in it"* วาดชิป
   `รออนุมัติ` เดี่ยว ๆ คือทำผิดข้อเดิมซ้ำ

ผลข้างเคียงที่ตั้งใจ: **วันที่ไม่มีใครขอถอน หน้าจอที่คนทำงานทุกวันหน้าตาเท่าเดิม
เป๊ะ** ของใหม่โผล่เฉพาะวันที่มีของใหม่จริง

### 3.4 ชิปคำขอถอนซ่อนอะไรบ้าง

ทุกอย่างที่เป็นของคิวรออนุมัติล้วน ๆ: แถบตัวกรอง `.queue-tools` · แถบปุ่มกอง ·
ตัวแบ่งหน้า · แบนเนอร์ `แสดง n จาก m` · แบนเนอร์รับช่วงอนุมัติแทน

**`PolicyDriftBanner` วาดทั้งสองชิป** มันพูดถึงกฎที่ใช้คำนวณตัวเลขบนหน้านี้ และ
แถวคำขอถอนก็มีตัวเลขชั่วโมงเหมือนกัน

## 4. ตารางคำขอถอน — เดสก์ท็อป (≥ 861px)

`.table-wrap` + `<table class="withdraw-table">` — โครงเดียวกับ `.queue-table`
ทุกประการ: `table-layout: fixed`, คอลัมน์ที่ห้ามตัดบรรทัดถูกตรึงเป็น px, คอลัมน์
ข้อความกินที่เหลือ, ล้นแล้วเลื่อนแนวนอนแทนที่จะบีบ

### 4.1 หกคอลัมน์ + ช่องปุ่ม

| # | หัวคอลัมน์ | ข้างใน | กว้าง |
|---|---|---|---|
| 1 | พนักงาน | `1.` ลำดับ · ชื่อ / รหัส · แผนก | 200px |
| 2 | วันที่ · เวลา | `14/09/2569 · 18:00–21:00 · 3 ชม.` ห้ามตัดบรรทัด | 210px |
| 3 | รายละเอียด | คำอธิบายงาน + โน้ตเทา `ใบนี้ยังรอฝ่ายบุคคลยืนยัน` | ที่เหลือ |
| 4 | เหตุผลที่ขอถอน | เหตุผลของพนักงาน + โน้ตเทาเรื่องงวดปิด | ที่เหลือ (มากกว่า) |
| 5 | ผู้ขอ | ชื่อผู้ขอ · วันที่ขอ | 140px |
| 6 | — | ไม่อนุมัติการถอน · อนุมัติให้ถอน | 236px |

ตรึงไว้ 786px → `min-width` ราว 1032px เท่ากับ `.queue-table` พอดี สองชิปจึงไม่
เขย่งกันเวลาสลับ

**สามอย่างบนคอลัมน์ 2 อยู่ด้วยกันเพราะเป็นข้อเท็จจริงเดียว** ไม่แยก `ชม.` ออกไป
เป็นคอลัมน์ตัวเลขของตัวเอง แม้สไตล์ของแอปจะชอบแบบนั้น — โค้ดเดิมเขียนเหตุผลไว้
ว่า *"the figure is what a grant takes off the books, and reading it away from
the clock it belongs to is how the wrong row gets withdrawn"* เหตุผลนั้นไม่ได้
เปลี่ยนไปเพราะแถวกลายเป็นแถวตาราง

**เหตุผลที่ขอถอนอยู่ในคอลัมน์ ไม่ได้อยู่หลังปุ่ม** กฎเดิมของการ์ด: *"A reviewer
who has to open something to find out why they are being asked will approve on
the strength of the fact that they were asked"* ตารางไม่ทำให้ข้อนี้อ่อนลง

**โน้ตเทาสองอันไม่อยู่ติดปุ่ม** ทั้ง `ใบนี้ยังรอฝ่ายบุคคลยืนยัน` และประโยคงวดปิด
(`cancelCutoffQueueNote`) เป็น `.cell-note` ใต้เซลล์ข้อความ ไม่ใช่ข้าง ๆ ปุ่ม —
เหตุผลเดิมคือ *ประโยคที่วางข้างการตัดสินใจ จะถูกอ่านเป็นการตัดสินใจอันที่สาม*
ซึ่งเป็นข้อเดียวกับที่ทำให้ป้ายสถานะสีเขียวถูกถอดออกจากการ์ดใบนี้

**ปุ่มยังเป็นคำ ไม่ใช่ไอคอน** `.queue-table` พับคำในปุ่มเหลือไอคอนบนเดสก์ท็อป
(`.btn-word` เป็น `display: none` ที่ ≥861px) จะไม่ทำแบบนั้นที่นี่: สองปุ่มนี้
ตรงข้ามกันและอันหนึ่งเอาชั่วโมงออกจากบัญชีอย่างถาวร ไอคอนคู่หนึ่งที่เดาผิดได้คือ
ราคาที่ไม่คุ้มกับ 100px

**ปุ่มตรึงขอบขวา** `position: sticky; right: 0` เหมือน `.queue-table td.act-col`
เมื่อตารางเลื่อน — ด้วยเหตุผลเดิมคือ ห้ามให้คนต้องดันตารางไปทางขวาก่อนจึงจะกดได้

### 4.2 ของที่หายไปจากแถว — และหายเพราะอะไร

- **ป้ายวันที่ตัวใหญ่ (`14` / `จ.`)** ออก — วันที่เต็มอยู่ในคอลัมน์ 2 แล้ว และ
  `.queue-table` ก็ไม่มีป้ายแบบนี้ทั้งบนเดสก์ท็อปและมือถือ
- **เพดาน `.withdraw-list { max-height: 400px }` ออก** เหตุผลของมันเขียนไว้ชัดว่า
  *"This card sits ABOVE รออนุมัติ OT … the panel that is news once a month
  decided where the panel that is worked daily began"* — พอเป็นชิป มันไม่ได้อยู่
  เหนืออะไรอีกแล้ว เพดานจึงกลายเป็นกล่องเลื่อนซ้อนในหน้าที่เลื่อนได้อยู่แล้ว
  ซึ่งเป็นของที่ §6.1 ของ `docs/design.md` ห้าม

**ไม่มีข้อมูลชิ้นไหนหายไป** ลำดับ · ชื่อ · รหัส · แผนก · วันที่ · ช่วงเวลา ·
ชั่วโมง · คำอธิบายงาน · เหตุผลที่ขอถอน · ผู้ขอ · วันที่ขอ · สถานะยังไม่ยืนยัน ·
ประโยคงวดปิด · ปุ่มสองปุ่ม — ครบสิบสี่อย่างเท่าเดิม

## 5. จอมือถือ (≤ 860px)

ใช้กลไกเดียวกับ `.queue-table` เป๊ะ ๆ ไม่ใช่ `.stack-table`: `display: block` ·
ซ่อน `thead` · `tbody` เป็นคอลัมน์ flex · แต่ละ `tr` เป็นการ์ดกริดที่เซลล์ถูกวาง
ด้วย `grid-area`

```
┌──────────────────────────────────────────┐
│ 1. นางสาวรณพร สอนฤทธิ์      14/09/2569  │   who / when
│    PM00112 · ผลิต1      18:00–21:00 3 ชม.│
│ ซ่อมสายพานลำเลียง                        │   why
│ เหตุผลที่ขอถอน: ลงวันที่ผิด ขอถอนใบนี้    │   reason
│ ⚠ งวด สิงหาคม 2569 · กำหนดสุดท้าย …      │   (เมื่อมี)
│ ขอโดย รณพร · 15/09/2569                  │   asked
│ [ ไม่อนุมัติการถอน ][ อนุมัติให้ถอน ]     │   act — 44px เต็มความกว้าง
└──────────────────────────────────────────┘
```

**`thead` หายไปพร้อมคำอธิบายคอลัมน์ ทุกเซลล์จึงต้องมีป้ายของตัวเอง**
(`docs/design.md` §6.1) วิธีที่ใช้: ป้ายเป็น `<span class="lbl">` อยู่ใน DOM
ตลอดเวลา และถูกซ่อนที่ ≥861px ซึ่งหัวคอลัมน์พูดแทนอยู่แล้ว — `เหตุผลที่ขอถอน:`
มีอยู่แล้วในโค้ดเดิม ส่วน `ขอโดย ` ก็เป็นคำเดิมในบรรทัดผู้ขอ เท่ากับไม่ได้เพิ่ม
คำใหม่บนจอเลย แค่ตัดสินว่าความกว้างไหนเห็น

คอลัมน์ 1 กับ 2 อยู่บรรทัดเดียวกันแบบ `who | when` ตามที่ `.queue-table` ทำ
(`grid-template-areas`) · ปุ่มยืดเต็มความกว้าง `flex: 1 1 0; min-height: 44px`
ซึ่งเป็นกฎที่ `.withdraw-actions` มีอยู่แล้วในบล็อก 860px — ย้ายมาทั้งก้อน

**ชิปที่จอแคบ** `.queue-tabs button { flex: 1 }` แบ่งครึ่งเองอยู่แล้ว · `.card-head`
พับลงบรรทัดใหม่ที่ความกว้างนี้ แถบชิปจึงกินเต็มบรรทัด และปุ่มขวาตกลงไปอยู่บรรทัด
ถัดมาเต็มความกว้าง (`.withdraw-batch { flex: 1 1 100%; min-height: 44px }` มีอยู่
แล้ว)

## 6. ของที่ไม่แตะเลย

- **ฝั่งเซิร์ฟเวอร์ทั้งหมด** ไม่มีเราต์ใหม่ ไม่มีฟิลด์ใหม่ ไม่มีการย้ายข้อมูล
  `/entries?withdrawal=open` และ `queue-summary` เหมือนเดิมทุกตัวอักษร
- **กฎว่าใครกดอะไรได้** `isPastCancelCutoff` · `mayCorrectEntries` ·
  `cancelCutoffQueueNote` · `withdrawDecisionPermission` ไม่ถูกแตะ ปุ่มเทาตอนงวด
  ปิดยังเทาด้วยเงื่อนไขเดิม และยังพกเหตุผลเต็มเป็น `title` + `aria-label`
- **กล่องโต้ตอบทั้งสาม** ไม่อนุมัติ · อนุมัติให้ถอน · อนุมัติให้ถอนทั้งหมด
  (พร้อมรายการที่พิมพ์เหตุผลครบทุกใบและยอดรวมท้ายกล่อง) ไม่เปลี่ยน
- **`queueBadge` และ nav** ตามข้อ 0

## 10. สองอย่างที่การวัดจริงเปลี่ยนไปจากแบบข้างบน

เขียนไว้เพราะแบบข้างบนคือสิ่งที่ตกลงกัน*ก่อน*เห็นของจริง และสองข้อนี้เปลี่ยนหลัง
วัดบน CSS ที่ build แล้ว

**§4.1 เขียนไว้ว่า “รายละเอียด และ เหตุผลที่ขอถอน แบ่งที่เหลือกันคนละครึ่ง”
ซึ่งไม่เกิดขึ้น** สไตล์ชีตมีกฎกลาง `th.why-col { width: 150px }` กับ
`th.act-col { width: 258px }` อยู่แล้ว — คอลัมน์ที่ไม่ประกาศความกว้างจึงไม่ใช่
คอลัมน์ยืด แต่เป็นคอลัมน์ที่ไปใช้ค่าที่ตารางอื่นวัดไว้ วัดที่ 1440 ก่อนแก้: `รายละเอียด`
ได้ 150px เป๊ะ และ `เหตุผลที่ขอถอน` กลืนที่เหลือไป 500px · แก้เป็น**ตรึงห้าคอลัมน์
เขียนออกมาครบ** (190 · 130 · 170 · 130 · 236 = 856px) และเหลือ `เหตุผลที่ขอถอน`
ตัวเดียวที่ยืด เพราะมันคือข้อความที่พนักงานพิมพ์เองและไม่มีเพดาน ส่วน `รายละเอียด`
ถูก `DESCRIPTION_MAX_CHARS` จำกัดไว้ที่ 22 ตัวอักษรอยู่แล้ว

**§5 ไม่ได้บอกว่าจะเกิดอะไรที่ต่ำกว่า 390px** บล็อกวันที่กว้างราว 128px และเป็น
`nowrap` จึงไม่ยอมหด — วัดที่ 360 แล้วเหลือให้ชื่อ 132px ซึ่งห่างจาก
`นางสาวฟ้าประทาน` (115.4px โทเคนชื่อเดี่ยวที่กว้างที่สุดในทะเบียนจริง) แค่ 17px ·
เพิ่ม `@media (max-width: 389px)` ให้การ์ดเหลือคอลัมน์เดียว วันที่ลงบรรทัดของตัวเอง
— เส้น 389 มีอยู่แล้วใน §6 ของ `docs/design.md` และข้อนี้คือการใช้ตามที่มันถูกเขียนไว้
