# เมื่อระบบ OT ใช้ไม่ได้ — ทำอย่างไร

สำหรับ **ฝ่ายบุคคล** และ **หัวหน้างาน** · ปรับปรุง 2026-08-25

ระบบนี้รันอยู่บนเครื่องเดียวในออฟฟิศ ไฟดับ เน็ตล่ม หรือเครื่องมีปัญหา = ทุกคนยื่น OT
ไม่ได้พร้อมกัน เอกสารนี้คือสิ่งที่ทำแทนในระหว่างนั้น และวิธีเก็บกวาดหลังระบบกลับมา

**หลักการเดียวที่ต้องจำ: งานยังเดินต่อบนกระดาษ ระบบตามทีหลังได้เสมอ**
ไม่มีข้อจำกัดว่าคีย์ย้อนหลังได้กี่วัน ตราบใดที่งวดเดือนนั้นยังไม่ปิด

---

## ขั้นที่ 0 — ก่อนแจกกระดาษ: เช็คว่าเซิร์ฟเวอร์รันอยู่ไหม

"เปิดหน้าเว็บไม่ขึ้น" กับ "ระบบล่ม" ไม่ใช่เรื่องเดียวกัน สาเหตุที่พบบ่อยที่สุดคือ
**โปรแกรมบนเครื่องไม่ได้รันอยู่** — เครื่องรีสตาร์ตแล้วยังไม่มีใครล็อกอิน หรือโปรเซส
ตายไปเอง ซึ่งแก้ได้ในไม่กี่สิบวินาที ไม่ต้องแจกกระดาษ

> 🔴 **แก้เมื่อ 2026-09-01 — ขั้นตอนเดิมในหัวข้อนี้ใช้ไม่ได้** เดิมเขียนไว้สองข้อว่า
> ให้ล็อกอินด้วยบัญชี `suwan` เพราะ “งานที่ทำให้แอปขึ้นเองผูกกับการล็อกอิน” แล้วถ้า
> ยังไม่ขึ้นให้สั่ง `Start-ScheduledTask -TaskName 'OT server'`
>
> **งาน `OT server` ไม่เคยถูกลงบนเครื่องนี้** — ตัดสินใจไม่ลงเมื่อ 2026-08-27
> (`README.md` หัวข้อ ให้แอปขึ้นเองทุกครั้งที่ล็อกอิน) และ `Get-ScheduledTask`
> ถูกอ่านอีกครั้งเมื่อ 2026-09-01 ยืนยันว่างาน OT ตัวเดียวบนเครื่องคือ `OT backup`
> คำสั่งเดิมจึงตอบว่าหาไม่พบ และ **แอปไม่ขึ้นเองหลังรีสตาร์ตหรือหลังล็อกอิน**
> ไม่ว่าจะรอนานแค่ไหน

**สิ่งที่ต้องรู้ก่อนอย่างอื่น: ไม่มีอะไรปลุกแอปนี้เอง** เครื่องรีสตาร์ต ไฟดับ หรือ
โปรเซสตายไปเอง = แอปดับค้างจนกว่า**คนจะไปเปิดให้** ไม่ใช่ความผิดปกติ เป็นสิ่งที่
ตกลงกันไว้ตอนที่เครื่องนี้ยังเป็นแล็ปท็อป

ให้คนที่ใช้เครื่องเซิร์ฟเวอร์ได้ทำสองอย่างนี้ (ต้องนั่งที่เครื่องนั้น ไม่ใช่จากมือถือ):

1. **ล็อกอินเข้าเครื่องด้วยบัญชี `suwan`** แล้วเปิด PowerShell เช็คว่าแอปยังอยู่ไหม

   ```powershell
   (Invoke-WebRequest http://127.0.0.1:3000/api/health -UseBasicParsing).StatusCode
   ```

   ได้ `200` = แอปยังรันอยู่ ปัญหาอยู่ที่**เครือข่าย ไม่ใช่ที่แอป** ให้ข้ามไปอ่าน
   `docs/network.md` — อาการที่พบบ่อยที่สุดคือ **IP ของเครื่องเปลี่ยน** แล้วบุ๊กมาร์ก
   ของทุกคนพังพร้อมกัน (เกิดมาแล้วจริงระหว่าง 2026-08-18 ถึง 2026-09-01)
   อ่านที่อยู่ปัจจุบันด้วย `powershell -File scripts\lan-url.ps1`

2. **ไม่ได้ `200` หรือขึ้น error** = แอปไม่ได้รัน สั่งเปิดด้วยตัวเรียกสามบรรทัด

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File C:\Users\suwan\deploy-ot.ps1
   ```

   มันหยุดของเก่า build ใหม่ แล้วปลุกขึ้นมาแบบที่ไม่ตายตามหน้าต่างที่สั่ง
   ใช้เวลาราวหนึ่งถึงสองนาที แล้วลองข้อ 1 ใหม่

ถ้าสองข้อนี้ไม่ช่วย — หรือไม่มีใครเข้าถึงเครื่องได้ — ให้ทำตามขั้นที่ 1 ต่อไป
วิธีตรวจโดยละเอียดอยู่ใน `README.md` หัวข้อ
**ให้แอปขึ้นเองทุกครั้งที่ล็อกอิน** พร้อมไฟล์ log ที่บอกว่ามันตายไปตอนไหน

## ขั้นที่ 1 — ระหว่างระบบล่ม: กลับไปใช้ F-HR-027 กระดาษ

1. หัวหน้างานแจกใบ **F-HR-027 Rev.4** เปล่า (เก็บสำรองไว้ที่ฝ่ายบุคคลอย่างน้อย 20 ใบเสมอ)
2. กรอกและ**เซ็นตามปกติทุกช่อง** — พนักงาน → หัวหน้า → ฝ่ายบุคคล
   ใบกระดาษที่เซ็นครบคือหลักฐานตัวจริงในช่วงนี้ ไม่ใช่ฉบับร่าง
3. เขียนมุมขวาบนของทุกใบว่า **"ระบบล่ม <วันที่>"** — นี่คือสิ่งที่ทำให้ตอนคีย์ย้อนหลัง
   แยกออกว่าใบไหนคีย์แล้วใบไหนยัง
4. **ฝ่ายบุคคลรวบใบไว้ที่เดียว** อย่าให้กระจายอยู่ตามแผนก ใบที่หายคือ OT ที่ไม่มีใครได้เงิน

> ถ้าไฟดับตอนกลางวันและกลับมาก่อนเลิกงาน อาจไม่ต้องแจกกระดาษเลย — ให้พนักงานยื่นย้อนหลัง
> ในระบบตอนเย็นได้ตามปกติ ระบบไม่ห้ามย้อนหลัง

## ขั้นที่ 2 — ระบบกลับมา: คีย์ย้อนหลัง

### ใครคีย์

| กรณี | ใครทำ | ทำที่ไหน |
|---|---|---|
| ทีมตัวเอง | **หัวหน้างาน** | รายการรออนุมัติ → ปุ่ม **บันทึก OT แทนพนักงาน** |
| ทุกแผนก / หัวหน้าไม่อยู่ | **ฝ่ายบุคคล** | ตรวจสอบประจำเดือน → เปิดพนักงาน → บันทึกแทน |

### วิธีคีย์

1. เรียงใบกระดาษ**ตามวันที่** แล้วคีย์เรียงลงมา จะได้รู้ว่าค้างถึงใบไหน
2. **หลายคนทำกะเดียวกัน คีย์ทีเดียวได้** — ในหน้าบันทึกแทน ติ๊กชื่อได้หลายคนพร้อมกัน
   (หรือกด **เลือกทั้งหมด**) แล้วกรอกวันที่/เวลา/รายละเอียดครั้งเดียว
   ระบบจะแยกบันทึกเป็นคนละใบ และคิดชั่วโมง เพดาน วันหยุด ของแต่ละคนแยกกัน
3. หลังบันทึก ระบบจะขึ้น **สรุปผลรายคน** — ✓ คือเข้าแล้ว ✕ คือไม่เข้าพร้อมเหตุผล
   **อ่านให้ครบทุกบรรทัดก่อนกดเสร็จสิ้น** เหตุผลที่เจอบ่อย:

   | ระบบบอกว่า | แปลว่า | ทำอย่างไร |
   |---|---|---|
   | พบรายการ OT ของวันที่ … แล้ว กรุณาแก้ไขรายการเดิม | คนนี้มีใบของวันนั้นอยู่แล้ว (อาจคีย์ไปแล้วรอบก่อน) — ใบ F-HR-027 มีบรรทัดเดียวต่อหนึ่งวัน จึงมีได้ใบเดียว | เปิดใบเดิมแล้ว **แก้เวลาให้ครอบคลุมทั้งวัน** อย่ายื่นใบที่สอง และอย่ายกเลิกใบเดิมทิ้งโดยไม่ดู |
   | เวลาทับซ้อนกับใบที่บันทึกไว้แล้ว | มีใบของ**คนเดียวกัน วันเดียวกัน**ที่กินเวลาช่วงนี้อยู่แล้ว | เปิดใบนั้น ถ้าซ้ำจริงให้ข้าม ถ้าเวลาผิดให้แก้ใบเดิม |
   | เวลาสิ้นสุดต้องอยู่หลังเวลาเริ่ม — งานที่ทำข้ามเที่ยงคืนให้แยกยื่นเป็นสองใบ ใบละวัน | ใบกระดาษเขียนกะที่ข้ามเที่ยงคืนไว้ในใบเดียว ซึ่งระบบไม่รับแล้วตั้งแต่ 10 ก.ย. 2569 | คีย์เป็น**สองใบ** — ถึง 23:59 ของวันแรก และตั้งแต่ 00:01 ของวันถัดไป · เขียนกำกับบนใบกระดาษว่าคีย์เป็นสองใบ เพื่อให้คนกระทบยอดเห็นว่าทำไมจำนวนใบไม่ตรง |
   | เกินเพดาน…ไม่สามารถบันทึกได้ | ชนเพดานเดือน/สัปดาห์ของแผนก | ทบทวนชั่วโมงกับหัวหน้า หรือให้ผู้ดูแลระบบดูเพดานของแผนกที่ **ตั้งค่าระบบ** *(เดิมบอกให้ฝ่ายบุคคลใช้ปุ่ม **อนุมัติเกินเพดาน** — ปุ่มนั้นถูกถอดออกทั้งระบบ 2026-09-02)* |
   | แผนกนี้ไม่มีโอที / เหมารายวัน | รูปแบบโอทีของแผนกไม่รับ OT วันธรรมดา | ตรวจกับหัวหน้าว่าตั้งค่าถูกหรือไม่ |

4. คีย์ครบใบไหนแล้ว **เขียน "คีย์แล้ว" บนใบกระดาษนั้น** ทันที
5. **เก็บใบกระดาษไว้ทั้งหมด อย่าทิ้ง** — เป็นทั้งหลักฐานลายเซ็นและตัวทานยอด

> **สำคัญ:** ใบที่คีย์แทนจะขึ้นชื่อ**พนักงาน**เป็นเจ้าของ และบันทึกว่า**คุณเป็นผู้บันทึกแทน**
> ทั้งบนหน้าจอและบนใบพิมพ์ ไม่ได้กลายเป็น OT ของคนคีย์
>
> **และยังไม่จบเมื่อกดบันทึก** — ตั้งแต่ 2026-09-09 ใบที่หัวหน้าคีย์แทนจะไปรออยู่ที่
> **รายการรออนุมัติ** ของหัวหน้าคนนั้นเอง ต้องเปิดแล้วกด **อนุมัติ** อีกครั้งใบจึงจะ
> ไปถึงฝ่ายบุคคล *(ย่อหน้านี้ไม่มีมาก่อนวันนั้น เพราะเดิมใบข้ามขั้นรอหัวหน้าไป รอ HR
> ให้เองทันทีที่กดบันทึก)* · คีย์ครบทั้งกองแล้วใช้ **เลือกทั้งหมด** บนคิวกดอนุมัติรวดเดียวได้

## ขั้นที่ 3 — คีย์ย้อนหลังข้ามเดือนได้เลย ไม่ต้องขออะไรจากใคร

**ขั้นตอนนี้เคยเป็น "ถ้างวดเดือนนั้นปิดไปแล้ว"** และเคยยาวสี่ข้อ: ฝ่ายบุคคลเปิดงวด
เองไม่ได้ · ต้องให้ **ผู้ดูแลระบบ (ADMIN)** เข้าไปกด **เปิดงวด** พร้อมกรอกเหตุผล ·
คีย์ให้ครบ · แล้ว **ปิดงวดใหม่ทันที** มีคำเตือนกำกับด้วยว่ามี ADMIN ใช้งานได้แค่
บัญชีเดียว ถ้าคนนั้นไม่อยู่ก็คีย์ย้อนหลังไม่ได้เลย

**ตั้งแต่ 2026-08-31 การปิดงวดถูกถอนออกจากระบบ** ระบบไม่มีเดือนที่ "ปิดแล้ว" อีก
ต่อไป การคีย์ย้อนหลัง การแก้ไข และการอนุมัติทำได้ทุกเดือนไม่ว่าเก่าแค่ไหน —
**ไม่ต้องรอ ADMIN และไม่มีอะไรค้างเพราะหาคนเปิดงวดไม่ได้** ซึ่งเป็นสถานการณ์ที่
ขั้นตอนเดิมเขียนไว้เองว่าจะเกิด

สิ่งที่มาแทนคือ **ป้ายสรุปสถานะงวด** บน ตรวจสอบประจำเดือน — มันไม่ห้ามอะไร มันบอก
ว่าเดือนนั้นยังมีใบรออนุมัติหรือคำขอถอนค้างอยู่กี่ใบ **อ่านมันก่อนพิมพ์ทุกครั้ง**
เพราะใบที่ยังไม่มีใครเซ็นจะไม่ขึ้นบนกระดาษที่พิมพ์ออกมา

> **แฟ้มกระดาษคือหลักฐาน ไม่ใช่สถานะในฐานข้อมูล** นี่คือเหตุผลที่ถอน: ฝ่ายบุคคล
> พิมพ์ F-HR-027 เซ็นและเก็บเข้าแฟ้มอยู่แล้วทุกเดือน ล็อกในระบบไม่ได้เพิ่มหลักฐาน
> อะไร แต่ทำให้การแก้ย้อนหลังต้องรบกวนคนอื่นทุกครั้ง
>
> **สิ่งที่ต้องระวังแทน** ไม่มีอะไรกันการคีย์ย้อนหลังไปเดือนไหนก็ได้แล้ว การทานยอด
> ในขั้นที่ 4 จึงเป็นด่านเดียวที่เหลือ — ทำทุกครั้ง อย่าข้าม

## ขั้นที่ 4 — ทานยอด (Reconcile)

ทำทุกครั้งหลังคีย์ย้อนหลัง **ก่อนพิมพ์ F-HR-027 เข้าแฟ้ม** ไม่ใช่หลัง

1. **นับจำนวนใบ** — นับใบกระดาษที่เขียน "ระบบล่ม" แล้วเทียบกับจำนวนที่คีย์เข้าไป
   ต้องเท่ากันเป๊ะ ต่างกันแม้ใบเดียวแปลว่ามีคนตกหล่นหรือคีย์ซ้ำ
2. **ทานรายคน** — เปิด **ตรวจสอบประจำเดือน** แล้วเทียบชั่วโมงรวมของแต่ละคนกับใบกระดาษของเขา
3. **ตัวเลขไม่ตรงเป็นเรื่องปกติในสองกรณีนี้ และไม่ใช่ความผิดพลาด:**
   - **หักพักเที่ยง** — กะที่คร่อม 12:00–13:00 ระบบหักให้ 1 ชม. ถ้าบนกระดาษเขียนเวลาดิบไว้
   - **ปัดเศษลงทีละ 30 นาที** — 2 ชม. 20 นาที ระบบคิดให้ 2.00 ชม. · ถ้ามีคนเปิด
     **ผ่อนปรนปัดขึ้น** ไว้ที่ ตั้งค่าระบบ → นโยบายการคำนวณ ตัวเลขนี้จะปัดขึ้นแทน
     (เปิด 10 นาที แล้ว 2 ชม. 20 นาที คิดให้ 2.50 ชม.) — เปิดหน้านั้นดูก่อนว่าตั้งไว้เท่าไร

   ถ้าต่างกันด้วยเหตุอื่น **อย่าเพิ่งพิมพ์เข้าแฟ้ม** ให้หาสาเหตุก่อน
4. **อ่านป้ายสรุปสถานะงวด** บน ตรวจสอบประจำเดือน ถ้ามันบอกว่ายังมีใบรออนุมัติหรือ
   คำขอถอนค้างอยู่ ให้เคลียร์ให้หมดก่อน — ใบที่ยังไม่มีใครเซ็นจะไม่ขึ้นบนกระดาษ
5. **พิมพ์ F-HR-027 จากระบบ** ของคนที่คีย์ย้อนหลัง แล้วแนบไว้กับใบกระดาษต้นฉบับ
   เก็บเป็นชุดเดียวกัน — ผู้ตรวจสอบจะเห็นได้ว่าใบไหนคือใบไหน

รายการนี้ไม่ใช่ขั้นตอนตอนเกิดเหตุ — เป็นของที่ต้องมี**ก่อน**เกิดเหตุ ไม่งั้นขั้นตอนข้างบนใช้ไม่ได้จริง

- [ ] **ใบ F-HR-027 เปล่าอย่างน้อย 20 ใบ** เก็บไว้ที่ฝ่ายบุคคล ในลิ้นชักที่เปิดได้ตอนไฟดับ
- [ ] **ADMIN บัญชีที่สอง** — ตอนนี้มีคนเดียว ควรเป็นผู้จัดการโรงงานหรือหัวหน้า
      ฝ่ายบุคคล **ห้ามใช้บัญชี ฝ่ายบุคคล ที่ใช้ร่วมกันทั้งแผนก** เพราะบันทึกจะบอก
      ได้แค่ว่า "บัญชีไหน" ไม่ใช่ "คนไหน"

      **ข้อนี้เร่งด่วนน้อยลงตั้งแต่ 2026-08-31** เดิมเขียนว่า "ถ้าไม่อยู่แล้วงวด
      ปิดไปแล้ว จะคีย์ย้อนหลังไม่ได้เลย" — การปิดงวดถูกถอนออกแล้ว การคีย์ย้อนหลัง
      จึงไม่ต้องพึ่ง ADMIN อีก ที่ยังต้องใช้ ADMIN คือ การรีเซ็ตรหัส ADMIN เอง
      (`npm run reset-admin`) การเปลี่ยนรหัสพนักงาน และ การคำนวณใหม่รวมใบที่
      อนุมัติแล้ว
- [ ] 🔴 **เสียบไดรฟ์ `E:` เข้าเครื่อง แล้วสร้างโฟลเดอร์ `E:\ot-backups`**

      งานอัตโนมัติชื่อ **`OT backup`** ตั้งไว้แล้ว รันทุกวัน **01:00** เก็บ 30 ชุด และทดสอบ
      ครบวงจรแล้วว่าสำรองและกู้คืนได้จริง — **แต่ตอนนี้ไดรฟ์ยังไม่ได้เสียบ มันจึงยังไม่ได้
      สำรองอะไรเลยสักคืน** ทุกคืนมันจะเขียนลง `backups\backup.log` ว่า
      `ล้มเหลว: ไม่พบปลายทาง E:\ot-backups`

      สำเนาที่มีอยู่ตอนนี้อยู่บนไดรฟ์ `C:` ดิสก์เดียวกับฐานข้อมูล — ดิสก์เสียทีเดียวหายทั้งคู่
      **ขั้นตอนทั้งหมดในเอกสารนี้ตั้งอยู่บนสมมติฐานว่าข้อมูลเก่ายังอยู่** ถ้าข้อมูลหายไปด้วย
      นี่ไม่ใช่แค่ไฟดับแล้ว

      เสียบเสร็จแล้วสั่งทดสอบหนึ่งรอบ ต้องได้ `LastTaskResult: 0`:
      ```powershell
      Start-ScheduledTask -TaskName 'OT backup'
      Get-ScheduledTaskInfo -TaskName 'OT backup' | Select LastRunTime, LastTaskResult
      ```
- [ ] **ตรวจ `backups\backup.log` เดือนละครั้ง** — งานที่รันตอนตีหนึ่งไม่มีใครเฝ้า
      ไฟล์นี้คือหลักฐานเดียวว่ามันทำงาน บรรทัดสุดท้ายต้องเป็น `สำเร็จ`
- [ ] **จอง IP ให้เครื่องที่เราเตอร์ (DHCP Reservation)** — ตอนนี้ที่อยู่ยังเป็น DHCP
      ซึ่งเปลี่ยนเองได้เมื่อเราเตอร์รีสตาร์ท และบุ๊กมาร์กของทุกคนจะพังพร้อมกัน
      ดู `docs/network.md`
- [ ] **เขียน URL ของระบบไว้บนกระดาษ** แปะไว้ที่ฝ่ายบุคคล

## สิ่งที่เอกสารนี้ไม่ครอบคลุม

- **ข้อมูลหาย ไม่ใช่แค่ระบบล่ม** — ต้องกู้จากไฟล์สำรอง อ่าน `README.md` หัวข้อ
  สำรองและกู้คืนข้อมูล และ**อย่ารันคำสั่งกู้คืนโดยไม่มีคนที่เข้าใจอยู่ด้วย**
  การกู้คืนจะเขียนทับข้อมูลปัจจุบัน
- **ลืมรหัสผ่าน ADMIN** — ไม่มีทางกู้จากในหน้าเว็บ ฝ่ายบุคคลแตะแถว ADMIN ไม่ได้เลย
  ต้องรัน `npm run reset-admin -- ADMIN` ที่คอนโซลของเครื่องเซิร์ฟเวอร์
  *(บรรทัดนี้เคยเขียนว่า "ไม่มีทางกู้จากในระบบ … ต้องแก้ที่ฐานข้อมูลโดยตรง" ซึ่งค้าง
  อยู่ตั้งแต่ก่อนมีสคริปต์นี้ — ดู README หัวข้อ `npm run reset-admin`)*
  · **นี่คือที่เดียวที่ยังได้รหัสผ่านสุ่ม** ทุกการรีเซ็ตจากหน้าจอตั้งรหัสผ่านกลับเป็น
  รหัสพนักงาน แต่ ADMIN คือทางกู้ของทุกบัญชีอื่น จึงต้องเป็นค่าที่อ่านออกจากทะเบียนไม่ได้
- **ระบบล่มถาวร / ย้ายเครื่อง** — เป็นงานติดตั้ง ไม่ใช่ขั้นตอนสำหรับผู้ใช้
