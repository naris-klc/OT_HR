# รวมคิวอนุมัติให้เหลือหน้าเดียว — ตัด "ไม่มีหัวหน้าเซ็น" และ "รออนุมัติแทน"

ถามไว้ 2026-09-18 · *"ใบที่ไม่มีหัวหน้าเซ็น ทำไมต้องแยกหน้าด้วย รวมเข้าหน้า
รออนุมัติหน้าเดียวดีกว่า"*

## ทำไมข้อเสนอนี้ถูก

**แถวเดียวกันขึ้นอยู่แล้วทั้งสองจอ** หน้า รออนุมัติ OT ของฝ่ายบุคคล/ผู้ดูแลระบบ
ลิสต์ทั้ง `pending_mgr` และ `pending_hr` มาตั้งแต่ต้น (`wholeFlow` ใน
`components/ApprovalQueue.jsx`) และผู้ดูแลระบบเห็นทั้งบริษัท (`scopeFor` คืน
`{}`) ใบที่ค้างเพราะไม่มีหัวหน้าจึงอยู่ในตารางนั้นแล้ว ต่างกันแค่ตรงนั้น
**ไม่มีปุ่ม** ต้องเดินไปอีกแท็บถึงจะกดได้ · ตัวเลขข้างแท็บไม่ตรงกันด้วย เพราะ
`pendingHr` นับเฉพาะขั้น HR ใบที่ค้างจึงไม่ถูกนับในเลข 47

**และกฎที่อยากได้ มีอยู่แล้วครึ่งหนึ่ง** `initialStatus`
(`lib/proxyFiling.js`) ส่งใบที่ยื่น*วันนี้*ในแผนกที่ไม่มีใครเซ็นได้ ไปขั้น
รอ HR ทันทีอยู่แล้ว ใบที่ยังค้างในแท็บคือใบที่ยื่นตอนยังมีคนเซ็น แล้วหัวหน้า
หายไปทีหลัง — ลาออก, ถูกแคบสโคปบริษัท, หรือแผนกถูกยกไปให้ฝ่ายบุคคลเป็นหัวหน้า
(`signedByHr`) · เป็นของตกค้าง ไม่ใช่สถานะที่ระบบตั้งใจให้มี

## สิ่งที่ผู้ใช้ตัดสินแล้ว

| คำถาม | คำตอบ |
|---|---|
| ใบที่ไม่มีใครเซ็นได้ | **ย้ายขั้นจริงไป `pending_hr`** ไม่ใช่แค่เขียนบนจอ |
| ใบเก่าที่ค้าง | **ย้ายอัตโนมัติตอนแสดงผล** ไม่รันสคริปต์ครั้งเดียว |
| ชิปในแถว | สถานะ **รอ HR** ตามปกติ · บวกป้ายเขียว **รับช่วงอนุมัติแทน** (แก้เมื่อ 2026-09-18 หลังเห็น mockup: เดิมตกลงว่าไม่มีป้าย) |
| ตัวเลขข้างแท็บ | **งานที่กดได้ทั้งหมด** |
| แท็บ รออนุมัติแทน | **รวมเข้าหน้าเดียวด้วย** |
| ปุ่มเซ็นแทนหัวหน้า | **เอาออกจากจอ เก็บกฎฝั่งเซิร์ฟเวอร์ไว้** (เคาะ 2026-09-18) |
| แถบเตือนรับช่วง | **ย่อเหลือประโยคเดียว** ขึ้นหัวคิวหลักเฉพาะตอนรับช่วงจริง |

## สิ่งที่ต้องเปลี่ยน

### ฝั่งเซิร์ฟเวอร์

1. **ซ่อมใบค้างตอนโหลดคิว** — ฟังก์ชันใหม่ (เช่น `repairUnsignable` ใน
   `lib/delegation.js` ข้าง `nobodyCanSign`) ที่รับใบ `pending_mgr` ที่ไม่มีใคร
   เซ็นได้ แล้ว `updateMany` ไป `pending_hr` โดยมีเงื่อนไขว่าสถานะยังเป็น
   `pending_mgr` — idempotent ปลอดภัยเมื่อสองเซสชันโหลดพร้อมกัน
   - เรียกจาก `GET /api/entries` (คิวของฝ่ายบุคคล/ผู้ดูแลระบบ) และจาก
     `queue-summary` ซึ่งรัน `nobodyCanSign` อยู่แล้ว — สองทางนี้ใช้ predicate
     ตัวเดียวกัน เลขกับตารางจึงไม่มีทางไม่ตรงกัน
   - **ต้องเขียนร่องรอย** หนึ่งแถวใน ประวัติรายการ ว่าใบถูกย้ายขั้นเพราะแผนกไม่มี
     ผู้เซ็น ไม่งั้นประวัติจะอ่านเหมือนใบข้ามขั้นเฉย ๆ ใช้ถ้อยคำเดียวกับที่
     `initialStatus` ใช้กับใบใหม่
2. **ธงรายแถว** ตอบว่าใบนี้ผู้อ่าน *เซ็นขั้นหัวหน้าได้ไหม* (รับช่วงอยู่) เพื่อให้
   หน้าเดียวรู้ว่าจะวางปุ่มที่แถวไหน — ปัจจุบันจอรู้จากการที่ *ทั้งจอ* ถูกเปิดด้วย
   `scope=delegated`
3. **`scope=unsigned` ถอดออก** ไม่มีจอไหนเรียกอีก
4. `queue-summary` — `unsignedPending` ไม่ต้องมี, ตัวเลขแท็บกลายเป็น
   "ที่กดได้ทั้งหมด" = `pending_hr` + `pending_mgr` ที่ผู้อ่านรับช่วงอยู่

### ฝั่งจอ

5. `components/App.jsx` — ตัดแท็บ `unsigned` และ `delegated` เหลือ `confirm`
   ตัวเดียว · `PAGE` เหลือคีย์เดียว · URL เดิมของสองแท็บนั้นเด้งไป `confirm`
6. `components/ApprovalQueue.jsx` — `unsignedOnly` / `delegatedOnly` ถอดออก
   ทั้งคู่ · `needsReason` เปลี่ยนจากระดับ *จอ* เป็นระดับ *แถว/แบตช์* แบบเดียว
   กับ `capReason` ที่ทำอยู่แล้วกับใบเกินเพดาน
7. **ป้ายเขียวใบเดียว สองที่มา** `TeamMark` (`components/common.jsx`) เปลี่ยนจาก
   ชิปเทา `chip delegated` ที่เขียนชื่อแผนก เป็น `chip green` เขียนว่า
   **รับช่วงอนุมัติแทน** และติดทั้งกับใบที่ผู้อ่านรับช่วงจริง และกับใบที่
   ระบบดันขึ้นขั้นเพราะแผนกไม่มีผู้เซ็น
   - ใช้ `chip green` ที่มีอยู่แล้ว (`--green-bg` / `--green-dark`) ไม่เพิ่มสีใหม่
     — `test/theme.test.js` วัดคู่นี้ผ่านทั้งสองธีมแล้ว
   - **ป้ายเดียวสองความหมายโดยตั้งใจ** คนอ่านต้องการคำตอบเดียว: *ใบนี้ฉันเซ็น
     แทนหัวหน้าได้* · ที่มาที่ต่างกัน (มีคนมอบ / ไม่มีหัวหน้าเลย) ยังแยกกันอยู่ใน
     ประวัติรายการ ซึ่งเป็นที่ที่ใช้ตอนตรวจสอบย้อนหลัง ไม่ใช่ตอนกดอนุมัติ
   - ชื่อแผนกหลุดออกจากป้าย — อ่านได้จากใต้ชื่อพนักงานในแถวเดียวกันอยู่แล้ว

## สองข้อที่เคาะแล้ว 2026-09-18

8. **ปุ่มเซ็นแทนหัวหน้าออกจากจอ กฎยังอยู่** ในเมื่อใบที่ไม่มีใครเซ็นได้ถูกดันขึ้น
   ขั้น HR เอง ก็ไม่มีแถวไหนเข้าเงื่อนไขให้กดอีก · `mayOverrideManagerStep`,
   `managerDecision.adminOverride` และการบังคับเหตุผลใน `approvalPermission`
   **ไม่ถูกลบ** — เป็นด่านสุดท้ายฝั่งเซิร์ฟเวอร์ และถ้าวันหน้าเจอเคสที่ต้องกดจริง
   การเติมปุ่มกลับถูกกว่าการรื้อกฎขึ้นมาใหม่
   - **เคส "หัวหน้ามีอยู่แต่ไม่เซ็นสักที" ไม่ได้หายไปไหน และไม่เคยอยู่ในแท็บนั้น**
     — `nobodyCanSign` เป็นเท็จสำหรับใบแบบนั้นมาตลอด · ทางออกของมันคือ
     ตั้งค่าระบบ → ผู้รับช่วงอนุมัติ ซึ่งมีวันหมดอายุและร่องรอยครบกว่า
9. **แถบรับช่วงย่อเหลือประโยคเดียว** `รับช่วงอนุมัติแทน <ชื่อ> ถึง <วันที่>` ที่หัว
   คิวหลัก ขึ้นเฉพาะตอนมีทีมที่รับช่วงจริง
   - เก็บไว้เพราะเป็น**ที่เดียวบนจอที่บอกว่าสิทธิ์หมดวันไหน** ป้ายเขียวในแถว
     บอกไม่ได้
   - อีกสองประโยคของเดิม (การอนุมัติถูกบันทึกว่าทำแทน · หัวหน้าเจ้าของคิวยัง
     อนุมัติเองได้) ย้ายไปป๊อปอัปรายละเอียดของแถว ซึ่งเป็นที่ที่คนอ่านตอนกำลังจะกด
     — และเป็นทางที่มือถืออ่านได้ ต่างจาก tooltip

## ผลข้างเคียงที่ต้องรู้ก่อนเริ่ม
1. **ใบพวกนี้จะมีลายเซ็นเดียว** (ฝ่ายบุคคล) แทนที่จะเป็นสองขั้น — ไม่ใช่ของใหม่
   `initialStatus` ทำแบบนี้กับใบใหม่อยู่แล้ว และ §6 ยอมรับไว้ในกรณีนี้ แต่ตอนนี้
   จะครอบใบเก่าด้วย
2. **GET ที่เขียนฐานข้อมูล** การซ่อมตอนแสดงผลทำให้คำขออ่านมีผลข้างเคียง ·
   ยอมรับได้เพราะเป็น idempotent และปริมาณน้อย แต่ต้องกันไม่ให้รันซ้ำทุกครั้งที่
   poll โดยเช็คก่อนว่ามีใบเข้าเงื่อนไขจริงจึงค่อยเขียน
