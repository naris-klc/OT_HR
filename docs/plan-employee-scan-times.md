# พนักงานเห็นเวลาสแกนของตัวเอง

**สถานะ: รออนุมัติ** — ยังไม่เขียนโค้ด เอกสารนี้คือสิ่งที่จะสร้าง

## ทำไม

วันนี้ `บันทึกและประวัติ OT` ไม่พูดถึงไฟล์สแกนนิ้วเลย พนักงานเห็นแต่เวลาที่ตัวเอง
กรอก ส่วนเวลาที่เครื่องบันทึกไว้อยู่ในจอของฝ่ายบุคคลจอเดียว
(`ตรวจสอบใบของพนักงาน`) — คนที่ถูกตั้งคำถามจึงเป็นคนสุดท้ายที่ได้เห็นหลักฐาน

ความเห็นที่เขียนไว้ใน `app/api/entries/route.js` ปี 2026-09 บอกว่าจอพนักงาน
*ไม่ควร* เห็น เพราะ "เป็นคำถามที่เขาตอบไม่ได้" — **เจ้าของระบบกลับข้อนี้แล้ว
(2026-09-16)**: เขาตอบไม่ได้ก็จริง แต่เขาเป็นคนเดียวที่รู้ว่าวันนั้นทำอะไร และ
ตอนนี้เขาไม่มีทางรู้เลยว่ามีใบของตัวเองถูกแขวนคำถามไว้

## ข้อเท็จจริงหน้างานที่กำหนดดีไซน์ทั้งหมด

**ฝ่ายบุคคลนำเข้าไฟล์สแกนเดือนละครั้ง** (แจ้ง 2026-09-16) ตามมาสามอย่าง:

1. **เดือนที่กำลังเดินอยู่จะไม่มีเวลาสแกนเกือบตลอดทั้งเดือน** — สถานะปกติของจอนี้
   คือ "ยังไม่มีอะไรให้เทียบ" ไม่ใช่สถานะข้อยกเว้น
2. **ป้ายทุกใบจะโผล่ย้อนหลัง** หลังใบอนุมัติจบและพ้นวันตัดรอบไปแล้ว พนักงาน
   แก้ใบเองไม่ได้ — จอจึงต้องบอกทางออก (แจ้งฝ่ายบุคคล) ไม่ใช่ปล่อยให้ป้ายแดงลอย
3. **ป้ายจะมาพรวดเดียวทั้งเดือน** ไม่ใช่ทยอยมาทีละวัน

## สิ่งที่ตกลงแล้ว

| เรื่อง | ข้อสรุป |
|---|---|
| ขอบเขต | เฉพาะวันที่มีใบ OT — เติมบนแถวเดิม ไม่มีจอใหม่ ไม่มีไทม์ชีตรายวัน |
| ป้าย | เห็นครบเหมือนฝ่ายบุคคล: `ไม่ครบ` · `ไม่ได้สแกน` (แดง) · `เกินเวลา` (เทา) |
| วางที่ไหน | ทุกที่ที่มีแถว — การ์ด `รายการล่าสุด` · ตารางประวัติทั้งหมด · pop-up รายละเอียด |
| ใบที่อนุมัติจบแล้ว | ป้ายขึ้นทุกสถานะ — คนสองฝั่งต้องเห็นแถวเดียวกันเหมือนกัน |
| เดือนที่ยังไม่นำเข้า | บรรทัดสั้นบรรทัดเดียว ไม่มีป้ายบนแถว |
| คำอธิบาย | กติกาเทียบ + ตัวเลขชั่วโมงไม่ถูกแก้ + ถ้าไม่ตรงให้แจ้งฝ่ายบุคคล |
| มือถือ | การ์ดใส่ทั้งป้ายและบรรทัดเวลา เหมือนตาราง |
| ตอนกรอกใบใหม่ | ยังไม่ทำ — แยกเป็นงานหลัง |
| วันที่นำเข้าไฟล์ | ไม่แสดง |

## บั๊กที่ต้องแก้ไปพร้อมกัน — ไม่แก้แล้วเดือนเดินอยู่จะแดงทั้งเดือน

`scanChecksFor` ตอบ `hasScans` จาก **ช่วงวันของทุกแถวที่ส่งเข้าไป** แต่
`EmployeeView` โหลด `/entries?limit=200&scope=mine` **ไม่กรองเดือน** (กรองในหน้า
ที่ `monthEntries`) ถ้าใส่ `scan=check` ไปตรงๆ จะได้:

- แถวของเดือนที่แล้วมี punch → `scanChecked = true`
- แถวของเดือนนี้ไม่มี punch เพราะไฟล์ยังไม่เข้า → ได้ป้ายแดง `ไม่ได้สแกน` ทุกแถว

เกิดแน่นอนทุกเดือน เพราะรอบนำเข้าเป็นเดือนละครั้ง

**ทางแก้: ส่ง `period=` ไปกับ request** — จอนี้เป็นจอรายเดือนอยู่แล้วทุกส่วน
(hero, สามการ์ดอัตรา, รายการล่าสุด, ตารางทั้งหมด) และ `useEffect` โหลดใหม่ทุกครั้ง
ที่เปลี่ยนเดือนอยู่แล้ว การกรองที่เซิร์ฟเวอร์จึงตรงกับที่จอต้องการพอดี และ payload
เล็กลงด้วย จอ `ตรวจสอบใบของพนักงาน` ของฝ่ายบุคคลส่ง `period=` อยู่แล้ว —
ไม่มีบั๊กนี้ และไม่ต้องแก้

## จอที่จะได้ — สามสถานะ

### 1 · เดือนที่ยังไม่นำเข้าไฟล์ (สถานะปกติของเดือนที่เดินอยู่)

แถวไม่มีอะไรเพิ่ม มีบรรทัดเดียวใต้รายการ:

```
รอฝ่ายบุคคลนำเข้าไฟล์สแกนนิ้ว
```

> เจ้าของระบบเขียนมาว่า "รอ HR นำเข้าไฟล์สแกนนิ้ว" — ขอใช้ **ฝ่ายบุคคล** แทน
> HR เพราะทั้งแอปไม่มีคำว่า HR โผล่บนจอสักที่ ถ้าอยากได้ HR จริงๆ บอกได้

### 2 · เทียบแล้ว (เดือนที่ปิดไปแล้ว)

**เดสก์ท็อป — ตารางประวัติทั้งหมด** เพิ่มในเซลล์ `เวลา` ที่มี `ไม่พักเที่ยง` อยู่:

```
 วันที่      เวลา                    ×1.5 ปกติ  รวม   สถานะ
 14 ก.ย.    17:00–19:30                  2.50   2.50  อนุมัติแล้ว
 วันจันทร์   [ไม่ครบ] อีก 40 นาที
            เริ่ม 07:55 - 19:32
 12 ก.ย.    17:00–20:00                  3.00   3.00  อนุมัติแล้ว
 วันเสาร์    เริ่ม 07:21 - 17:05, 20:11
```

**มือถือ — การ์ดรายการล่าสุด** ป้ายไปอยู่แถวเดียวกับ `OT สวัสดิการวันเกิด` และ
`ยื่นแทนโดย` ที่มีอยู่แล้ว บรรทัดเวลาอยู่ใต้มัน:

```
┌──────────────────────────────────┐
│ 14  ซ่อมไลน์ผลิต 3                │
│ จ.  17:00–19:30                  │
│     [ไม่ครบ] อีก 40 นาที          │
│     เริ่ม 07:55 - 19:32           │
│     รอ สมชาย อนุมัติ              │
│              2.50 ชม. [อนุมัติแล้ว]│
└──────────────────────────────────┘
```

**pop-up รายละเอียด** — เพิ่มใน `Section คำขอ` ที่มี `เวลาที่ขอ` · `พักเที่ยง` ·
`ชั่วโมงตามนาฬิกา` อยู่แล้ว เป็น `Fact` ใหม่ชื่อ **เวลาจากเครื่องสแกน** พร้อมป้าย
ใต้มัน — ไม่สร้าง Section ใหม่ เพราะเป็นข้อเท็จจริงเรื่องเดียวกับเวลาที่ขอ

### 3 · เทียบแล้วและทุกแถวตรง

บรรทัดคำอธิบายขึ้นเหมือนสถานะ 2 แต่ไม่มีป้ายบนแถวไหนเลย — ซึ่งเป็นคำตอบที่ถูก:
เงียบเพราะเทียบแล้วไม่มีอะไร ไม่ใช่เงียบเพราะยังไม่ได้เทียบ

## คำอธิบายใต้รายการ (สถานะ 2 และ 3)

ใช้ `Disclosure` แบบเดียวกับที่ฝ่ายบุคคลเห็น พับไว้บนมือถือ:

```
วิธีเทียบเวลากับไฟล์สแกนนิ้ว ⌄
  เทียบเวลากับไฟล์สแกนนิ้วแล้ว — สแกนออกไม่ก่อนเวลาสิ้นสุด OT ถือว่าทำครบตามที่ขอ
  · เวลาเริ่มถือว่าตรงกันเมื่อห่างกันไม่เกิน 30 นาที
  · ตัวเลขชั่วโมงไม่ได้ถูกแก้จากไฟล์สแกน
  · ถ้าเวลาไม่ตรงกับที่ทำจริง แจ้งฝ่ายบุคคล
```

ประโยคสุดท้ายเป็นของจอนี้จอเดียว — ฝ่ายบุคคลไม่ต้องแจ้งตัวเอง ที่เหลือเป็นสตริง
เดียวกับ `HrEntries` โดยดึงจาก `lib/scanMatch.js` เหมือนเดิม ไม่ก๊อบข้อความ

## ของแถมที่ขอเคาะ — `เหมารายวัน`

จอพนักงานไม่มี `FlatDailyMark` เลย ทั้งที่ฝ่ายบุคคลมี ผลคือใบเหมารายวันของ
พนักงานอ่านว่า `08:00–20:00` แต่รวมได้ `8.00` โดยไม่มีอะไรอธิบาย และเมื่อป้าย
สแกนเข้ามา แถวเหมารายวันจะกลายเป็นแถวเดียวที่ไม่มีป้ายอะไรเลย (ตามกติกา
`ScanMismatchMark` ยืนลงบนวันเหมา) — ดูเหมือนระบบลืมเทียบ

**เสนอให้ใส่ `FlatDailyMark` ไปพร้อมกัน** คอมโพเนนต์มีอยู่แล้ว ใช้ `entry.flatDaily`
ไม่เกี่ยวกับไฟล์สแกน — **ถ้าไม่เอา บอกได้ ตัดออกไม่กระทบส่วนอื่น**

## ไฟล์ที่จะแก้

| ไฟล์ | แก้อะไร |
|---|---|
| `components/EmployeeView.jsx` | ส่ง `period=` + `scan=check` · เก็บ `scanChecked` · วางป้ายและบรรทัดเวลาสามที่ · Disclosure |
| `app/api/entries/route.js` | **แก้ความเห็น** ที่บอกว่าจอพนักงานไม่ควรเห็น — เหตุผลเปลี่ยนแล้ว |
| `components/HrEntries.jsx` | **แก้ความเห็น** บรรทัดที่เขียนว่า "THIS SCREEN AND NOT บันทึกและประวัติ OT" |

**ไม่ต้องแก้:** `lib/scanMatch.js` · `lib/scanMatchQuery.js` · `components/common.jsx`
· `app/styles.css` — ป้ายทั้งสามโทน บรรทัดเวลา และคลาสที่ใช้มีครบแล้ว งานนี้เป็น
การใช้ซ้ำล้วนๆ ถ้าระหว่างทำพบว่าต้องเพิ่มคลาสใน `styles.css` จะกลับมาถาม

**ไม่แตะ guard:** `scan=check` ไม่มี `requireRole` อยู่แล้วและ scope ผูกกับคนเรียก
— พนักงานได้ของตัวเองเท่านั้น ตรงกับที่ต้องการพอดี
