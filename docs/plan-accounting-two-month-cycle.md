## ทำไมต้องมี

ค่าจ้าง OT ของ **เดือนพฤศจิกายนและธันวาคมของทุกปี ถูกรวบจ่ายทีเดียวในเดือนมกราคม**
ใบที่ส่งให้บัญชีตอนนั้นจึงต้องเป็นใบเดียวที่มีสองเดือนอยู่ในนั้น พร้อมยอดรวมของทั้ง
งวด — ไม่ใช่ใบเดือนพฤศจิกายนกับใบเดือนธันวาคมวางคู่กันแล้วให้บัญชีบวกเอง การบวกด้วย
มือทุกเดือนคือขั้นตอนที่พลาด ซึ่งเป็นเหตุผลเดียวกับที่คอลัมน์ `รวม 1.5` / `รวม 3`
เข้ามาอยู่ท้ายไฟล์ CSV เมื่อ 2026-09-09

## หลักการที่ยึด

**ตัวเลขยังสร้างที่เดียว** — `lib/accounting.js` ยังเป็น "หนึ่งเดือน" เสมอ และห้าม
สอนให้มันรู้จักหลายเดือน เพราะกฎเกือบทุกข้อในนั้นเป็นกฎ*ของเดือน*:

- `latestPerSession` ตัดใบที่ยื่นซ้ำช่วงเวลาเดิม — การ dedupe ข้ามสองเดือนไม่มี
  ความหมายและจะกินใบที่ถูกต้องทิ้ง
- roster pass ของ `includeZero` เติมบรรทัดว่างจากทะเบียน ณ เดือนนั้น
- การซ่อม `unaccounted` ที่อ่านใบกำพร้ากลับมา

สิ่งที่เพิ่มคือ **ฟังก์ชันรวมผลลัพธ์ที่บริสุทธิ์** เรียกรายงานเดือนละครั้งแล้วเชื่อม
กัน — ทดสอบได้โดยไม่ต้องมีฐานข้อมูล ซึ่งเป็นรูปแบบเดียวกับที่ชุดเทสต์นี้ใช้อยู่แล้ว
ทั้งชุด

## 1. `lib/accountingCycle.js` — ไฟล์ใหม่ (pure)

```
cyclePeriods(period, period2) -> ['2026-11', '2026-12']   // เรียงน้อยไปมาก, กันซ้ำ, สูงสุด 2

```

### shape ของแถวที่รวมแล้ว — การตัดสินใจที่สำคัญที่สุดในแผนนี้

แถวเก็บ **ยอดรวมทั้งงวดไว้ที่ระดับบนสุดของแถวเหมือนเดิมทุกฟิลด์** (`ot15Hours`
`ot3Hours` `otHours` `buckets` `weightedHours` `birthdayHours` `overCeiling`)
แล้ว *เพิ่ม* `row.months[]` เป็นรายเดือน

ผลที่ได้คือทุกที่ที่อ่านของเดิมอยู่แล้วได้ยอดรวมงวดทันทีโดยไม่ต้องแก้ — แถว
`รวมแผนก` / `รวมบริษัท` / `รวมทั้งหมด` ใน CSV, กล่องกระทบยอด, ตัวเลขชั่วโมงใน
ดรอปดาวน์บริษัท — ส่วนคอลัมน์ใหม่อ่านจาก `months[i]` อย่างเดียว

ทางเลือกตรงข้าม (ทำ `months[]` เป็นแหล่งเดียวแล้วให้ทุกที่บวกเอง) คือการกระจาย
เลขคณิตออกไปตามหน้าจอ ซึ่งเป็นรูปของความผิดพลาดที่ `lib/accounting.js` ทั้งไฟล์
ตั้งใจปิดไว้ตั้งแต่ต้น

### กฎการเชื่อม

- เชื่อมแถวด้วย `employee.id` · คนที่มีชั่วโมงแค่เดือนเดียวได้ **แถวเดียว** อีกเดือน
  เป็นช่องว่าง ไม่ใช่ 0.00 — ตามกฎ `amount()` ที่ใบพิมพ์ใช้อยู่
- ชื่อ/ตำแหน่ง/แผนก เอาจากเดือน **หลังสุด** ที่คนนั้นปรากฏ — คนย้ายแผนกกลางงวดได้
  และแผนกที่ควรพิมพ์คือแผนกที่เขาอยู่ตอนปิดงวด
- เรียงใหม่ด้วย `compareCodes` ตัวเดิม (`src/lib/employeeCode.js`) ไม่ใช่
  `localeCompare` — เหตุผลเขียนไว้แล้วใน `lib/accounting.js`
- `headcount` **คำนวณใหม่จากแถวที่รวมแล้ว ห้ามบวกกัน** — คนที่มี OT ทั้งสองเดือนจะ
  ถูกนับสองรอบทันทีถ้าบวก
- `pending` / `unaccounted` / `supersededCount` บวกรายเดือน
- `reconciliation.ok` = ผ่านทุกเดือน · ต้องยังบอกได้ว่าเดือนไหนไม่ผ่าน
- รายชื่อบริษัท = ยูเนียน เรียงตาม config เหมือนเดิม
- **merge ของรายงานเดือนเดียว = ตัวมันเอง** (บวก `periods` กับ `row.months` ที่ยาว 1)
  → เส้นทางโค้ดเดียว ไม่มีสาขา "โหมดหนึ่งเดือน" ให้หลุดการทดสอบ


**ทั้งงวด** ซึ่งตรงกับสองคอลัมน์รวมบนกระดาษพอดี — ไฟล์กับใบยังอ่านคู่กันได้

ชื่อไฟล์: `OT-accounting-2026-11+2026-12-all.csv` (`+` ปลอดภัยบน Windows และ

## 4. ใบพิมพ์ — `components/AccountingPrint.jsx` + `app/print.css`

### กระดาษ

A4 แนวตั้ง **194mm เท่าเดิม** สลับ `colgroup` ตามจำนวนเดือนใน `periods`:

| โหมด | รหัส | ชื่อ-นามสกุล | ช่องตัวเลข | แถบหมายเหตุ | รวม |
| --- | --- | --- | --- | --- | --- |
| 1 เดือน (เดิม ไม่แตะ) | 24 | 54 | 17 + 17 | 82 | 194mm |
| 2 เดือน (ใหม่) | 22 | 50 | 6 x 12 | 50 | 194mm |

หัวตาราง **ยังสองแถวเท่าเดิม**:

```
 รหัส | ชื่อ-นามสกุล |  พ.ย. 69  |  ธ.ค. 69  |    รวม    | (แถบขาว)
      |             | 1.50|3.00 | 1.50|3.00 | 1.50|3.00 |
```

### สิ่งที่ห้ามขยับ

- **`ROWS_PER_PAGE` = 37** — แถบขอบ 10mm/12mm เท่าเดิม หัวสองแถวเท่าเดิม สูงแถว 7mm
  เท่าเดิม การตัดหน้าใน `paginate` และบรรทัดเปล่าห้าเส้น (`SPARE_LINES`) ไม่แตะเลย
  นี่คือสมบัติที่ต้องมีเทสต์ยึด
- **หัวเดือนต้องย่อเฉพาะโหมดสองเดือน** (`พ.ย. 69`) — `เดือนพฤศจิกายน 69` ที่ 9pt
  กว้างเกินแบนเนอร์ 24mm จะตกบรรทัด แถวสูงขึ้น แล้ว `ROWS_PER_PAGE` พังทันที ใบ
  เดือนเดียวคงคำเต็ม `เดือนกันยายน 69` ไว้ไม่แตะ (ต้องเพิ่ม `THAI_MONTHS_SHORT`
  หรือพารามิเตอร์ให้ `monthHead`)
- แถบขาว `td.note` ยังไม่มีเส้น ไม่มีหัวคอลัมน์ และยัง nowrap เหมือนเดิม · 50mm ยัง
  พอสำหรับคำว่า วันเกิด

### สิ่งที่เพิ่ม

- คู่ `รวม` ได้เฉดพื้นของตัวเอง เข้มกว่า `#deeaf6` เล็กน้อย ให้บัญชีแยกออกด้วยตาว่า
  คู่ไหนคือผลบวก · ยัง `print-color-adjust: exact` และยังอ่านรู้เรื่องถ้าเครื่องพิมพ์
  ตัดพื้นหลังทิ้ง เพราะเส้นตารางเป็นตัวเล่าโครงสร้าง
- แดงเกินเพดาน (`figureClass`): ช่องรายเดือนอ่าน `overCeiling` ของเดือนนั้น ช่องรวม
  อ่านของทั้งงวด
- วันเกิด ในแถบขาว: ติดถ้ามีเดือนใดเดือนหนึ่ง — ยอดระดับแถวรวมให้อยู่แล้ว
- `PageTag` และ `printName.accounting` รับหลายเดือน:
  `OT-accounting-2026-11+2026-12-all`
- `PrintChrome` เพิ่มบรรทัดคำแนะนำ: งวดจ่าย พฤศจิกายน + ธันวาคม 2569
- **PDF ไม่ต้องแก้อะไรเลย** — `lib/printFile.js` ถ่ายจาก DOM ที่กำลังจะส่งเครื่องพิมพ์
  ใบเปลี่ยนแล้วไฟล์ตามเอง
