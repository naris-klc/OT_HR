# แถวคำขอถอนใบ — สูงไม่เกิน 2 บรรทัด และกดเปิดรายละเอียดได้

รายงานไว้ 2026-09-16: *"ตาราง ux/ui ความกว้างไม่พอดี ดูไม่ค่อยสวยงาม ไม่อยากให้
ความสูงเกิน 2 แถว · อยากให้กดที่รายการแล้วแสดงรายละเอียดเพิ่มเติม"*

ตารางคือ `.withdraw-table` ในแท็บ **คำขอถอนใบ** บนการ์ดคิวรออนุมัติ
(`components/WithdrawalRequests.jsx`) รูปแบบตารางเพิ่งมาแทนกองการ์ดเมื่อ
2026-09-15 — เอกสารฉบับนี้ไม่ได้ล้มการตัดสินใจนั้น แก้เฉพาะความสูงของแถวกับทางเข้า
รายละเอียด

## แถวสูงเพราะอะไร

วัดจากภาพที่ผู้ใช้ส่งมา — แถวหนึ่ง **3–4 บรรทัด** และตัวการมี 3 อย่าง

| ตัวการ | ตอนนี้ |
| --- | --- |
| `รายละเอียด` งาน | ตกบรรทัดยาว เพราะคอลัมน์กว้าง 170px |
| ประโยคใต้เหตุผล | `งวด สิงหาคม 2569 · กำหนดสุดท้าย 03/09/2569 ซึ่งผ่านไปแล้ว — ตัดสินคำขอนี้ได้เฉพาะฝ่ายบุคคล` กินเต็ม 2 บรรทัดด้วยตัวเอง |
| ชื่อผู้ขอ | ชื่อ-นามสกุลเต็มในคอลัมน์ 130px จึงตกบรรทัดทุกแถว |

## สิ่งที่จะแก้

### 1 · ตัดข้อความที่ 2 บรรทัด

`.cell-clamp` — `-webkit-box` + `-webkit-line-clamp: 2` แบบเดียวกับที่
`.disclosure-body.clamp` ใช้อยู่แล้ว (app/styles.css) ใส่ให้ **รายละเอียด**,
**เหตุผลที่ขอถอน**, **ชื่อพนักงาน** และ **แผนก**

ตัดที่ CSS ไม่ตัดที่ JS: ข้อความเต็มยังอยู่ใน DOM ทุกตัวอักษร Ctrl-F หาเจอ
โปรแกรมอ่านหน้าจออ่านครบ และหน้าพิมพ์คลาย clamp ออกได้ที่เดียว — ตัดด้วย
`slice()` ในโค้ดจะเสียทั้งสามอย่าง

### 2 · ประโยคงวดปิดเหลือบรรทัดเดียว

เพิ่ม `cancelCutoffShortNote(entry, policy)` ใน `lib/entries.js` ข้าง
`cancelCutoffQueueNote` — **วันที่ยังฟอร์แมตที่เดียวคือ `cancelCutoffLead`**
ตามเหตุผลที่เขียนไว้เหนือฟังก์ชันนั้น (คอมมิต `5c2a0e2` เคยต้องไล่เก็บประโยค
เดียวกันคืนจาก 4 ไฟล์หลังมันแตกเป็น 3 สำนวน) ของใหม่จึงเป็น *หางที่สี่* ไม่ใช่
ประโยคใหม่

```
งวดปิด 03/09/2569 — เฉพาะฝ่ายบุคคล
```

**ประโยคเต็มไม่ได้หายไป** ยังอยู่ 3 ที่: `title`/`aria-label` ของกล่องปุ่ม ·
`Alert` ในกล่องยืนยันทั้งสอง · และหน้ารายละเอียด ที่ย่อคือ*บนแถว*เท่านั้น

### 3 · ปุ่ม `ปฏิเสธ` / `อนุมัติ`

คอลัมน์ปุ่มลง 236px → 150px ซึ่งเป็นความกว้างที่คืนให้เหตุผลกับรายละเอียด

**ความกว้างที่แบ่งใหม่ทั้งชุด** — ที่พินไว้ 856px เหลือ 736 เหตุผลที่ขอถอนได้
296px ที่พื้นความกว้างขั้นต่ำ (เดิม 176) และ 442px บนการ์ดที่วัดได้จริง 1178px
(เดิม 322)

| คอลัมน์ | เดิม | ใหม่ | ทำไม |
| --- | --- | --- | --- |
| พนักงาน | 190px | **230px** | ชื่อเต็มกับเลขลำดับต้องอยู่บรรทัดเดียว ไม่งั้นช่องนี้สูง 3 บรรทัด |
| วันที่ · เวลา | 130px | 130px | — |
| รายละเอียด | 170px | 170px | `DESCRIPTION_MAX_CHARS` จำกัดที่ 22 ตัวอักษรอยู่แล้ว |
| เหตุผลที่ขอถอน | ยืดหยุ่น | ยืดหยุ่น | คอลัมน์เดียวที่เนื้อหาไม่มีเพดาน |
| ผู้ขอ | 130px | **96px** | ชื่อตัวคำเดียวเหนือวันที่ |
| ปุ่ม | 236px | **150px** | คำสั้นลง |

⚠ **ผู้ใช้รับความเสี่ยงข้อนี้แล้วหลังได้ยินคำเตือน** — การ์ดใบนี้มีอีกแท็บชื่อ
รออนุมัติ OT ที่ปุ่ม `อนุมัติ` แปลว่า*อนุมัติให้ทำ OT* ส่วนปุ่มนี้แปลว่า
*อนุมัติให้ถอนใบทิ้ง* ซึ่งตรงข้ามกัน สิ่งที่กันความเข้าใจผิดไว้คือ

- ปุ่มยังเป็น `.btn.danger` แดง ไม่ใช่เขียวแบบปุ่มอนุมัติ OT
- `title`/`aria-label` เป็นคำเต็ม `อนุมัติให้ถอนใบนี้` / `ไม่อนุมัติการถอน`
- กล่องยืนยันยังพูดเต็มประโยคและยังเตือนว่าแก้กลับไม่ได้ — ไม่มีทางถอนใบได้ด้วย
  การกดปุ่มเดียว

### 4 · ชื่อผู้ขอ

`firstNameOf(name)` — ตัดคำนำหน้าออกจากคำแรก แล้วเอาคำถัดไป (`นางสาวรณพร
สอนฤทธิ์` → `รณพร`) ใช้ **เฉพาะคอลัมน์ผู้ขอ** คอลัมน์พนักงานยังเป็นชื่อเต็ม
เพราะเป็นตัวระบุตัวคน ชื่อเต็มของผู้ขออยู่ในหน้ารายละเอียด

### 5 · กดแถวเปิดรายละเอียด

`<tr className="row-open" tabIndex={0}>` — **ท่าเดียวกับคิวรออนุมัติและหน้ารายการ
OT ทุกตัวอักษร** (`.queue-table tbody tr.row-open`, `.hr-table tbody tr.row-open`)
ไม่ใช่ `role="button"` ด้วยเหตุผลที่เขียนไว้ที่นั่น: แถวที่อ้างว่าเป็นปุ่มจะเลิก
เป็นแถวสำหรับโปรแกรมอ่านหน้าจอ · ตัวกันคือ `closest('button, input, a, …')`
เพื่อไม่ให้กดปุ่มในแถวแล้วเปิดกล่องตามไปด้วย

กล่องใหม่ `WithdrawDetail` ประกอบจากของเดิมใน `components/common.jsx` ทั้งหมด —
ไม่มีชิ้นส่วนใหม่:

| ส่วน | ใช้ของเดิม |
| --- | --- |
| กรอบ | `Modal` (กลางจอ · sheet บนมือถือ) |
| เหตุผลที่ขอถอน / ผู้ขอ / วันที่ขอ | `Section` + `Fact` + `fact-grid` |
| รายละเอียดงาน | `ReasonCard` |
| ชั่วโมงแยกอัตรา | `.split.ot-split` + `BUCKETS`/`BUCKET_LABEL` |
| เทียบไฟล์สแกน | `ScanDayPunches` + `ScanMismatchMark` |
| ประวัติของใบ | `EntryHistory` |
| ผู้อนุมัติเดิม | `SignatureFacts` |
| ปุ่มท้ายกล่อง | `footer` ของ `Modal` — ปุ่มคู่เดิม |

ปุ่มในกล่องเรียก `setGranting` / `setRefusing` ตัวเดียวกับที่ปุ่มบนแถวเรียก
ทางเข้าจึงมีทางเดียว กล่องยืนยันกับการเขียนไม่ต้องรู้ว่าถูกกดมาจากไหน

### 6 · มือถือ (ต่ำกว่า 860px)

การ์ดยัง clamp 2 บรรทัดเท่ากัน · การ์ดทั้งใบกดได้ · ปุ่มคู่ยังเป็นครึ่งหนึ่ง
ของบรรทัดเต็มความกว้างสูง 44px ตามเดิม
