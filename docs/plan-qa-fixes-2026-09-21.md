## 2. ที่แก้ในรอบนี้

### 2.1 `?limit` ที่เป็นค่าติดลบทะลุเพดาน

**อาการ** `GET /api/logs?limit=-1` คืน **12,100 แถว** ทั้งที่เพดานคือ 500
เหมือนกันที่ `GET /api/employees/audit`

```js
const limit = Math.min(Number(q.limit) || DEFAULT_LIMIT, MAX_LIMIT);  // -1 รอดทุกด่าน
… .limit(limit + 1)                                                   // .limit(0) = ไม่จำกัด
```

`-1` ไม่เป็น falsy จึงไม่ถูกแทนด้วยค่าเริ่มต้น และ `Math.min` ก็ยิ่งเลือกมัน
พอบวกหนึ่งกลายเป็น `.limit(0)` ซึ่งใน mongoose แปลว่า *ไม่จำกัด*

**แก้** ใช้ `capFor` จาก `lib/entries.js` ซึ่งเป็นกติกาที่ถูกอยู่แล้วและมีที่ใช้
อยู่ก่อน — มันปฏิเสธทั้งค่าติดลบ ศูนย์ และค่าที่ไม่ใช่ตัวเลข พร้อมปัดเศษลง
ตัวเลขเพดานของแต่ละเส้นทางยังเป็นของตัวเอง (`MAX_LIMIT` ของ log คือ 500 ไม่ใช่
`MAX_LIST_LIMIT` ของใบ OT) จึงส่งเข้าไปเป็นพารามิเตอร์

**กระทบ** `app/api/logs/route.js` · `app/api/employees/audit/route.js` ·
`lib/entries.js` (`capFor` รับเพดานเข้ามาได้)

### 2.2 id ผิดรูป → 500 แทน 400

**อาการ** หก endpoint ตอบ *เกิดข้อผิดพลาดภายในระบบ* เมื่อ id ในพาธหรือใน query
ไม่ใช่ ObjectId:

```
GET    /api/entries/abc/trail
GET    /api/employees/zzz/audit
GET    /api/employees/zzz/impact
GET    /api/entries/usage/2026-09?employee=xyz
POST   /api/delegations        {"from":"abc"}
DELETE /api/delegations/abc
```

ทุกอันมาจาก `CastError` ของ mongoose ที่ `translate` ใน `lib/http.js` ไม่รู้จัก
จึงตกท่อสุดท้ายเป็น 500 พร้อม `console.error` เต็มสแตก

**แก้ที่ `translate` จุดเดียว** — CastError คือ *คำขอที่รูปแบบผิด* ไม่ใช่
*เซิร์ฟเวอร์พัง* จึงเป็น 400 เหมือน `ValidationError` ที่อยู่ข้างกัน การแก้ที่นี่
ครอบคลุมทุก route ที่มีอยู่และทุก route ที่ยังไม่ได้เขียน ซึ่งเป็นเหตุผลเดียวกับ
ที่ `route()` มีอยู่ตั้งแต่แรก

การตรวจรูป id ในแต่ละ route ยังคงอยู่และยังคงดีกว่า — `employees/audit` ตรวจ
`q.by` เองและตอบข้อความที่บอกว่า *ฟิลด์ไหน* ผิด ส่วน `translate` เป็นตาข่ายรอง

### 2.3 ตัวตรวจงวดสองตัวที่ตอบไม่ตรงกัน

```js
lib/reports.js       PERIOD_RE = /^\d{4}-\d{2}$/              // 2026-13 ผ่าน
lib/periodStatus.js  isPeriod  = /^\d{4}-(0[1-9]|1[0-2])$/    // 2026-13 ไม่ผ่าน
```

`\d{2}` รับ `00`–`99` ทั้งหมด ผลคือ `/api/reports/accounting/2026-13` ตอบ **200
พร้อมรายงานเปล่า** ขณะที่ `/api/periods/2026-13` ตอบ 400 — ระบบเดียวกันตอบคนละ
อย่างกับข้อมูลเข้าเดียวกัน คนที่พิมพ์ผิดอ่านผลลัพธ์ว่า *เดือนนั้นไม่มีข้อมูล*

**แก้** ให้ `PERIOD_RE` เข้มเท่า `isPeriod` — เดือนต้องเป็น 01–12

**แล้วการทดสอบหลังแก้ก็พบว่ามันไม่ใช่สองสำเนา แต่เป็นสี่** ยิงของจริงอีกรอบแล้ว
`/api/exports/entries.csv?period=2026-13` ยังตอบ **200 พร้อมไฟล์ที่มีแต่หัวตาราง**
เพราะสองเส้นทางนี้ไม่ได้ถาม `PERIOD_RE` เลย:

| เส้นทาง | เดิม |
|---|---|
| `exports/monthly.csv` | เขียน `/^\d{4}-\d{2}$/` ไว้เองเป็นสำเนาที่สาม — ไม่ขยับตามตัวจริง |
| `exports/entries.csv` | ไม่ตรวจอะไรเลย ส่ง `q.period` เข้า filter ตรง ๆ |

ไฟล์ CSV ที่มีแต่หัวตารางอ่านออกมาว่า *เดือนนั้นไม่มีใครทำ OT* ซึ่งเป็นประโยคที่
ผิดคนละแบบกับ *เดือนนั้นไม่มีอยู่* และคนที่เปิดไฟล์ใน Excel ไม่มีทางแยกออก ·
ทั้งสี่เส้นทางของเดือน (`accounting.csv`, `departments.csv`, `monthly.csv`,
`entries.csv`) กับเราต์รายงานถาม `PERIOD_RE` ตัวเดียวกันแล้ว และเทสต์ตรึงไว้ว่า
ไม่มีไฟล์ไหน *เรียก* สำเนาของกติกานี้อีก

### 2.4 งวดบัญชีสองเดือนที่ไม่ติดกัน

`GET /api/reports/accounting/2026-09?with=2026-03` รวมสองเดือนที่ห่างกันหกเดือน
เป็นงวดเดียวได้ และฟิลด์ `period` ที่คืนกลับกลายเป็น `2026-03` เพราะ
`cyclePeriods` เรียงแล้วคืนตัวแรก — ผู้ใช้เรียก `/2026-09` แต่ได้หัวรายงานเป็น
เดือนอื่น

งวดจ่ายของที่นี่คือ **สองเดือนที่ติดกัน** (`docs/plan-accounting-two-month-cycle.md`)
เดือนที่ไม่ติดกันไม่ใช่งวด

**แก้** route ปฏิเสธด้วย 400 เมื่อสองเดือนไม่ติดกัน · กติกา "เดือนถัดไปคืออะไร"

ฐานข้อมูล และเพื่อไม่ให้ route ต้องรู้เรื่องเลขเดือนข้ามปี

### 2.6 `.xlsx` — ชื่อแผ่นงานสลับ และ `r:id` ที่เป็น regex

สองข้อในบรรทัดเดียวกันที่ `src/lib/xlsx.js`:

```js
const first = /<sheet\b[^>]*?name="([^"]*)"[^>]*?r:id="([^"]*)"/.exec(workbook)
  ?? /<sheet\b[^>]*?r:id="([^"]*)"[^>]*?name="([^"]*)"/.exec(workbook);
//                    ↑ กลุ่ม 1 เป็น r:id แต่โค้ดข้างล่างอ่าน first[1] เป็น name
const rel = new RegExp(`<Relationship[^>]*Id="${first[2]}"…`).exec(rels);
//                                              ↑ ค่าจากไฟล์ที่ผู้ใช้อัปโหลด ต่อดิบ
```

**ยืนยันด้วยไฟล์จริงแล้ว** (สร้างด้วยตัวประกอบ zip ของ `test/xlsxImport.test.js` เอง):

| workbook | ผล |
|---|---|
| `<sheet name="ทะเบียน" r:id="rId1"/>` | ชื่อแผ่น `ทะเบียน` ✓ |
| `<sheet r:id="rId1" name="ทะเบียน"/>` | ชื่อแผ่น **`rId1`** ✗ |
| `r:id="r.d1"` กับ `Relationship Id="rXd1"` | **จับคู่ติด** ทั้งที่คนละตัว ✗ |

ลำดับ attribute ใน XML ไม่มีความหมาย โปรแกรมที่เขียนไฟล์จะเรียงอย่างไรก็ได้ และ
Excel เองก็เรียงไม่เหมือนกันทุกเวอร์ชัน · เคสที่สามยังไม่เคยเกิดจริง แต่ค่าที่มา
จากไฟล์ที่คนนอกส่งมา ไม่ควรกลายเป็นรูปแบบค้นหา

**แก้** ดึงแท็ก `<sheet …>` ออกมาก่อน แล้วอ่าน `name` และ `r:id` จากแท็กนั้นแยก
กัน — ลำดับจึงไม่มีความหมายอีกต่อไปและกลุ่มไม่มีทางสลับ · escape `r:id` ก่อนต่อ
เข้า `RegExp`

### 2.7 สี่จุดเล็กฝั่ง API

| จุด | เดิม | แก้เป็น |

### 2.8 เกณฑ์ความสูงของเป้ากด — แก้ **เอกสาร** ไม่ใช่ CSS

วัดจริงด้วย Chrome บน production build ทั้งเก้าจอ: `.btn` สูง **39px** ทุกความ
กว้าง ขณะที่ `docs/design.md` ประกาศ 44px ไว้สองแห่ง และในสไตล์ชีตมีกฎยกเป็น
44px เฉพาะจุด 28 แห่ง (แถวเมนู ปฏิทิน แถวนำเข้าสแกน) ไม่มีกฎกลาง

**สั่งไว้ 2026-09-21: เอกสารผิด ไม่ใช่โค้ดผิด — ปรับเกณฑ์เป็น 39px**
ปุ่มความสูง 39px คือสิ่งที่แอปนี้ใช้มาตลอดและผู้ใช้เห็นแล้วพอใจ ส่วน 44px ยังเป็น
ของจริงสำหรับ *แถวในเมนูและปฏิทิน* ซึ่งเป็นที่ที่นิ้วต้องเลือกจากรายการยาว
เอกสารจึงต้องแยกสองเรื่องนี้ออกจากกัน แทนที่จะประกาศเลขเดียวแล้วผิดทั้งแอป

## 3. สิ่งที่ตรวจแล้วและ **ผ่าน** — บันทึกไว้เพื่อไม่ต้องตรวจซ้ำ

- **การจับคู่ไฟล์สแกนนิ้ว** 20 เคสขอบของการเทียบเวลา + 17 เคสของการอ่านไฟล์
  ไม่พบข้อผิดพลาดในการคำนวณเลย · ไฟล์ 5.3MB (200k บรรทัด) ใช้ 378 ms · บรรทัด
  เดียวยาวหนึ่งล้านตัวอักษรไม่ทำให้ regex ค้าง (2 ms) · ฐานบนเครื่องนี้ยังไม่มี
  ข้อมูลสแกนเลย (0 punch / 0 batch)
- **การมอบอำนาจเต็มวงจร** สร้าง → ขอบเขตขยายทันทีและตรงกับที่เจ้าของคิวเห็นเป๊ะ

  ยกเลิกซ้ำ ตอบถูกหมด · กฎผู้เซ็นสองคนทำงาน
- **การคำนวณใหม่ตามเวอร์ชันกฎ** `versionForDate` เลือกกฎตาม `workDate` เสมอ
  ใบเก่าจึงคำนวณด้วยกฎที่มีผล ณ วันนั้น ไม่ใช่กฎล่าสุด
