## 2. ทำไมของที่ขอมาถึงยังไม่มี — ช่องว่างสามอย่าง

### 2.1 ตารางไม่รู้จัก "ใบ" รู้จักแต่ "ยอดรวม"

`GET /api/reports/monthly/[period]` คืนค่าเป็นยอดสรุปต่อคน
([route.js:160–228](../app/api/reports/monthly/%5Bperiod%5D/route.js#L160)) —
`entryCount`, `pendingCount`, `summary`, `cap`, `edits` **ไม่มี `_id` ของใบสัก
ใบเดียว** จะกดอนุมัติจากหน้านี้ไม่ได้ เพราะ `POST /entries/:id/approve` ต้องการ
`_id`

⚠️ และ `pendingCount` ที่มีอยู่ **ใช้แทนกันไม่ได้** — มันนับ `status !== 'approved'`
ทั้งหมด ซึ่งรวม `pending_mgr` ที่ยัง **ไม่ใช่ของ HR ให้เซ็น** (`approvalPermission`
ตอบ 409 *"ต้องผ่านการอนุมัติจากหัวหน้าก่อน"* — [lib/delegation.js:551](../lib/delegation.js#L551))
ถ้าเอา `pendingCount` มาขึ้นปุ่ม จะได้ปุ่มที่กดแล้ว 409 เป็นแถบ ๆ

### 2.2 ผลเทียบสแกนอยู่คนละ request คนละการ์ด และตั้งแต่วันนี้ยัง **พับอยู่**

ผลเทียบมาจาก `GET /api/scans?compare=1` → `compareMonthAgainstScans`
([lib/scanMatchQuery.js:139](../lib/scanMatchQuery.js#L139)) ซึ่งคืน

```
counts  { mismatch, short, startOff, noScan, overTime, flatDaily, checked }
people  [{ id, code, name, mismatch, noScan, flatDaily }]   ← เฉพาะคนที่มีปัญหา
```

แต่มันถูกเรียกและถูกวาด **อยู่ใน `ScanImport`** ([ScanImport.jsx:444](../components/ScanImport.jsx#L444))
และเมื่อ 2026-09-10 การ์ดนั้นถูกเปลี่ยนเป็น **พับปิดทุกครั้งที่เข้าหน้า**
(`scanOpen` ตั้งต้น `false` — [HrView.jsx:291](../components/HrView.jsx#L291))

ผลคือของที่สั่งมาว่า *"ให้แสดงสรุป แจ้งเตือนรายการที่ผลเทียบมีปัญหา"* วันนี้อยู่
**ลึกสองคลิก** ทั้งที่มันเป็นข้อเท็จจริงที่ต้องเห็นก่อนจะเซ็นอะไรทั้งสิ้น

**นี่คือแกนของรอบนี้: การนำเข้าไฟล์เป็น "การกระทำ" (พับได้) · ผลเทียบเป็น
"ข้อเท็จจริง" (ต้องเห็นเสมอ)** สองอย่างนี้ถูกมัดอยู่ในการ์ดใบเดียวกันมาตลอด และ
วันที่การ์ดนั้นถูกพับ ข้อเท็จจริงก็หายไปด้วย

### 2.3 ผลเทียบเป็นรายเดือน/รายคน แต่ตารางไม่เคยได้รับมัน

`compare.people` มี id พนักงานอยู่แล้ว จึง join กับแถวในตารางได้ทันที — ไม่ต้อง
คิดใหม่ ไม่ต้องยิง query เพิ่ม แค่ยกการ fetch ขึ้นไปไว้ที่ `HrView` แล้วส่งลงมา
ทั้งสองทาง

### ก้อน C · route ส่ง "ใบที่เซ็นได้" ลงมาต่อคน

เพิ่มใน `app/api/reports/monthly/[period]/route.js` ต่อพนักงานหนึ่งคน:

```js
approvable: {
  ids:       [...],   // _id ของใบที่ผู้อ่านคนนี้เซ็นขั้น HR ได้จริง
  hours:     48.0,    // ชั่วโมงรวมของใบเหล่านั้น — แถบล่างใช้พูด
  capOver:   1,       // กี่ใบที่ติดเพดาน → กล่องยืนยันต้องขอเหตุผล
},
pendingHrCount: 6,    // แทน/เสริม pendingCount เดิม
```

**ตัดสินด้วย `approvalPermission` ตัวจริง ไม่ใช่เช็ก `status === 'pending_hr'` เอง**
— เพราะกฎ §6 ข้อ "คนที่เซ็นขั้นหัวหน้าไปแล้ว เซ็นขั้น HR ของใบเดียวกันไม่ได้"
(`signedManagerStep` — [lib/delegation.js:569](../lib/delegation.js#L569)) เป็นกฎ
รายใบต่อรายคน ไม่ใช่กฎรายสถานะ ถ้าจอคิดเองจอจะเสนอปุ่มที่เซิร์ฟเวอร์ตอบ 409

ส่ง `delegations: []` ได้ เพราะคิว HR ยืมกันไม่ได้อยู่แล้ว — ข้อเท็จจริงนี้เขียน
ไว้แล้วที่ [ApprovalQueue.jsx:361](../components/ApprovalQueue.jsx#L361)
*"The HR confirmation queue is nobody's to lend"*

⚠️ ถ้า `สถานะที่นับ` = **อนุมัติแล้วเท่านั้น** จะไม่มีใบ `pending_hr` ในชุดเลย →
`approvable.ids` ว่างทุกแถว → ไม่มี checkbox ทั้งตาราง **ต้องมีประโยคบอก** ไม่ใช่
ปล่อยให้ช่องหายไปเงียบ ๆ ("ตั้ง สถานะที่นับ เป็น *อนุมัติแล้ว + รอ HR* เพื่อยืนยัน
ใบจากหน้านี้")

  โดย `actionable` ที่นี่นิยามใหม่เป็น:

  ```
  แถวที่ approvable.ids.length > 0  และ  ไม่มีผลเทียบสแกนติดปัญหา
  ```

- เรียก `POST /entries/:id/approve` ทีละใบวนลูป — เหมือน `run()` เดิมทุกประการ
  (API ไม่มี bulk endpoint และการประดิษฐ์อันที่สำเร็จครึ่งเดียวแย่กว่าตัวนับ
  ความคืบหน้า — เหตุผลเดิมของ [ApprovalQueue.jsx:801](../components/ApprovalQueue.jsx#L801))
- เสร็จแล้วเรียก `load()` + `onQueueDone('pending_hr', n)` → `App.jsx` ต้องส่ง
  `queueDone` ([App.jsx:1167](../components/App.jsx#L1167)) ลงมาให้ `HrView`
  **ถ้าลืมข้อนี้ badge บนเมนูจะค้าง** และนั่นคือรายงานของ 2026-08-28 ซ้ำรอบสอง
- **ยอดรวมไม่ขยับหลังกดยืนยัน** และนี่เป็นคุณสมบัติที่ดี: ค่าตั้งต้น `สถานะที่นับ`
  คือ *อนุมัติแล้ว + รอ HR* ซึ่งนับใบ `pending_hr` อยู่แล้ว การยืนยันจึงเปลี่ยน
  แค่ป้ายสถานะ ไม่ใช่ตัวเลข — ควรเขียนประโยคนี้ไว้บนจอด้วย

### ก้อน E · อนุมัติได้จากในหน้ารายละเอียดด้วย

ถ้าไม่ทำก้อนนี้ คนที่ผลเทียบติดปัญหาจะยัง **ต้องสลับไปหน้า รออนุมัติ OT อยู่ดี**
ซึ่งคือปัญหาเดิมที่สั่งมาให้แก้ แค่ย้ายที่

ใน [components/HrEntries.jsx](../components/HrEntries.jsx) เพิ่มต่อแถว:

- ปุ่ม **ยืนยัน** บนใบที่ `status === 'pending_hr'` (ข้าง ✏️ แก้ไข · ยกเลิก เดิม)
- ปุ่ม **ยืนยันทั้งหมดที่เหลือ (n ใบ)** ที่หัวรายการ สำหรับคนที่ตรวจครบแล้ว
- ป้ายผลเทียบต่อแถวมีอยู่แล้ว (`ScanMismatchMark`, `ScanDayPunches`) ไม่ต้องเพิ่ม
- `onChanged` มีอยู่แล้วและผูกกับ `load` ของ `HrView` อยู่แล้ว → ตัวเลขในตาราง
  อัปเดตเองเมื่อกลับออกมา

## 5. เจ็ดข้อที่ตัดสินแล้ว — 2026-09-10

ทั้งเจ็ดข้อถูกตอบในวันที่เขียนเอกสารนี้ ข้อความข้างล่างคือคำตัดสิน ไม่ใช่ตัวเลือก
อีกต่อไป **เหตุผลของแต่ละข้อถูกเก็บไว้ เพราะข้อที่ 1 กับข้อที่ 4 ต่างจากที่หน้า
รออนุมัติ OT ทำ และคนที่อ่านโค้ดสองหน้านี้เทียบกันจะสะดุดตรงนั้นแน่นอน**

1. **ติ๊กหนึ่งช่อง = ทั้งเดือนของคนนั้น** ✅ *(ตัวเลือก ก)*
   ไม่กางเป็นรายใบ ไม่จำกัดจำนวนใบต่อคน — แลกมาด้วยเงื่อนไขบังคับสองข้อ:
   แถบล่างต้องพูดสองหน่วยเสมอ (`3 คน · 17 ใบ`) และกล่องยืนยันต้องขึ้นทุกครั้ง
   แม้จะเลือกคนเดียว เพราะ "คนเดียว" ที่นี่ยังหมายถึงหลายใบอยู่ดี
   *ทำไมถึงต่างจาก รออนุมัติ OT:* ที่นั่นหนึ่งช่อง = หนึ่งใบ เพราะหน้านั้นเรียง
   ตามใบ หน้านี้เรียงตามคน — คำสั่งที่ว่า *"เลือกอนุมัติได้หลายคนหลายรายการ"*
   ระบุหน่วยไว้แล้วว่าคือคน

2. **แถวที่ผลเทียบมีปัญหา — ห้ามติ๊ก** ✅
   `checkbox disabled` + `title` บอกเหตุผล และ `เลือกทั้งหมด` ไม่นับแถวเหล่านี้
   ทางเดียวที่จะยืนยันคนกลุ่มนี้คือกดเข้าไปดูในหน้ารายละเอียด (ก้อน E) ซึ่งเป็น
   เหตุผลที่ก้อน E ไม่ใช่ของแถม — ถ้าไม่มี ก้อนนี้จะกลายเป็นทางตัน
   *กฎเดียวกับ `actionable` ของ รออนุมัติ OT:* แถวที่กดแล้วพัง ไม่ควรติ๊กได้
   ตั้งแต่แรก ที่นี่ "พัง" ไม่ได้แปลว่า 403 แต่แปลว่า *ยังไม่มีใครดู*

3. **เดือนที่ยังไม่ได้นำเข้าไฟล์สแกน — ติ๊กได้ปกติ** ✅ *(ตัวเลือก ก)*
   พร้อมการ์ดบนสุดที่พูดตัวโต ๆ ว่า **ยังไม่ได้เทียบ** ไม่ใช่ *"ทุกแถวตรง"*
   — สองประโยคนี้มองจากตารางเปล่า ๆ เหมือนกันเป๊ะ และนี่คือความต่างที่
   `scanChecked` ใน `HrEntries` มีไว้อธิบายอยู่แล้ว
   *ทำไมไม่บังคับ:* `lib/scanMatch.js` ประกาศตัวเองไว้ว่า *"เป็นการชี้ให้ดู
   ไม่ใช่การคิดใหม่"* การเอามาเป็นเงื่อนไขบังคับคือการยกระดับมันเป็นกฎ ซึ่ง
   ไม่เคยมีใครสั่ง และจะทำให้เดือนที่ไฟล์มาช้ากลายเป็นเดือนที่อนุมัติไม่ได้เลย

4. **`เลือกทั้งหมด` = ทุกแถวที่ตัวกรองเหลือไว้ รวมที่อยู่นอกหน้า pager** ✅
   ป้ายต้องเขียนจำนวนจริงกำกับ (`เลือกทั้งหมด (24)`) เพื่อให้คนบนมือถือที่เห็น
   ห้าแถวรู้ว่ากำลังจะติ๊กยี่สิบสี่
   *ทำไมถึงต่างจาก รออนุมัติ OT* ที่มีกฎว่า *"ติ๊กอยู่ได้เท่าที่แถวยังอยู่บนจอ"*:
   ที่นั่น pager คือตัวกรองจริง ที่นี่ pager เป็นแค่หน้าต่าง CSS (`off-page`)
   เดสก์ท็อปวาดครบทุกแถวเสมอ และ `CARD_PAGE` ใน `HrView` ประกาศไว้เองว่า
   **A PAGE IS NOT A FILTER** ปุ่มเดียวกันบนสองขนาดจอต้องหมายถึงสิ่งเดียวกัน

5. ~~**ยก `ConfirmModal` ออกไป `components/common.jsx` ใช้ร่วมกัน**~~ *(ตัวเลือก ก)*

4. **checkbox + แถบเลือก + กล่องยืนยัน** (ก้อน D) — วันที่หน้านี้เซ็นชื่อได้
5. **ยืนยันจากในหน้ารายละเอียด** (ก้อน E) — ปิดวง ไม่ต้องสลับหน้าอีกเลย
