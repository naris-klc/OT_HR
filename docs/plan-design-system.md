2. **`README.md`** — มีหัวข้อเรื่องหน้าตาราวสามสิบหัวข้อ เขียนเป็น *ประวัติ*

## 3.1 คำอธิบายรกบนจอ — กฎที่ขาด และเหตุผลว่าทำไมมันถึงขาด

**เพิ่ม 2026-09-10 หลังอ่าน `AGENTS.md` จบทั้งไฟล์**

`AGENTS.md` มีสี่หัวข้อ ไม่มีหัวข้อไหนพูดถึงหน้าตาเลย: บล็อกของ Next.js เอง ·
เครื่องไหนเสิร์ฟแอปและ build อย่างไรไม่ให้ล่ม · เอกสารต้องแก้ในคอมมิตเดียวกับ
พฤติกรรม · `test/docsMatchCode.test.js` ตรวจอะไรให้บ้าง **ไม่มีประโยคไหนกำหนดสี
เลย์เอาต์ ถ้อยคำบนจอ หรือปริมาณคำที่จอหนึ่งแบกได้**

และนี่คือสาเหตุ ไม่ใช่แค่ช่องว่าง: หัวข้อ *"A commit that changes behaviour must
find the paragraphs that describe it"* สอนให้ **อธิบายเป็นร้อยแก้ว เก็บประวัติ
อย่าปล่อยให้ย่อหน้าไหนค้างเป็นเท็จ** ซึ่งถูกต้องทั้งหมด — แต่เป็นกฎของ *เอกสาร*
เมื่อไม่มีกฎคู่กันบอกว่า *จอ* ไม่ใช่ที่อธิบาย นิสัยนั้นก็ไปลงบนจอแทน

วัดจากโค้ดวันนี้: `<div className="hint">` **112 จุด** ใน components ·
`AdminView.jsx` 20 จุดคนเดียว · รวมคลาสข้อความรอง (`hint` `note` `muted` `desc`
`small` …) **154 จุดใน 23 ไฟล์** · `.hint` คือ 12.5px สี `--muted-2`
(`app/styles.css:7497`)

**ทุกจุดผ่านเทสต์หมด** เพราะ `test/theme.test.js` ตรวจ *สี* และ
`test/docsMatchCode.test.js` ตรวจ *เอกสาร* — ไม่มีเทสต์ไหนนับคำบนจอ และไม่ควรมี
นี่เป็นเรื่องที่ต้องตัดสินด้วยกฎที่คนอ่านแล้วทำตาม

กฎที่เสนอให้ `docs/design.md` ถือ:

- **จอหนึ่งมี `.hint` ได้กี่จุด ให้ตั้งเพดาน** — ผมเสนอ *ไม่เกินหนึ่งจุดต่อการ์ด
  หนึ่งใบ* และการ์ดที่ต้องมีสองจุดคือสัญญาณว่าการ์ดนั้นทำสองเรื่อง
- **`.hint` เขียนได้เฉพาะสิ่งที่จอบอกเองไม่ได้** — เงื่อนไข ข้อยกเว้น
  ผลของการกด · ห้ามใช้ทวนสิ่งที่ป้ายข้าง ๆ พูดไปแล้ว
- **ประวัติการเปลี่ยนกฎไม่ขึ้นจอ** — มันอยู่ `README.md` ตามกฎ `AGENTS.md`
  คนใช้เปิดจอมาเพื่อกรอก OT ไม่ใช่มาอ่านว่ารอบที่เจ็ดยกเว้นอะไรไว้
- **ประโยคเดียว** — ถ้ายาวเกินหนึ่งบรรทัดที่ 390px แปลว่ามันเป็นเอกสาร ไม่ใช่ป้าย

**ผมเสนอให้ข้อนี้เป็นหัวข้อแรกของ `docs/design.md` ไม่ใช่หัวข้อท้าย** — เพราะมัน
คือข้อที่ผิดซ้ำได้มากที่สุด และเป็นข้อเดียวในเอกสารนี้ที่แก้ของที่ *มีอยู่แล้ว*
ไม่ใช่เพิ่มของใหม่

## 4. งาน "ให้เหมือน mobile app" — สี่ช่องโหว่จริง เรียงตามผลที่รู้สึกได้

เรื่องนี้ไม่ใช่เรื่องเอกสาร และไม่ใช่เรื่องสี ทุกข้อข้างล่างวัดจากโค้ดวันนี้

### ก. ไม่มี PWA manifest เลย — ผลมากที่สุด ต้นทุนน้อยที่สุด

**✅ ตัดสินแล้ว 2026-09-11: ทำ — `display: "minimal-ui"` ไม่เอา service worker**

> **เคยอ่านว่า "ทำ — `standalone` อย่างเดียว ไม่เอา service worker"** จนถึง
> 2026-09-11 · เปลี่ยนเป็น `minimal-ui` ด้วยเหตุผลที่ข้อ 5 — เกณฑ์ที่ปรับใหม่
> คือ *สะดวกที่สุดบนมือถือ* ไม่ใช่ *เหมือนแอปที่สุด*

`public/` มีแค่ `README.md` `logo.png` `logo-mark.png` · ใน `app/layout.js`
ไม่มี `manifest` ไม่มี `apple-touch-icon` ไม่มี `theme-color`

แปลว่าวันนี้ **เพิ่มลงหน้าจอโฮมไม่ได้อย่างที่ควรเป็น** — เปิดมาก็ยังเห็นแถบ
ที่อยู่ของเบราว์เซอร์ ซึ่งเป็นสิ่งเดียวที่บอกคนใช้ว่านี่ไม่ใช่แอป

#### สามเรื่องที่คู่มือ Next 16 ในเครื่องบอก และแผนฉบับแรกเขียนผิด

อ่าน `node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/01-metadata/manifest.md`
กับ `.../02-guides/progressive-web-apps.md` ตามกฎข้อแรกของ `AGENTS.md`:

1. **manifest ไม่ได้อยู่ใน `public/`** — App Router อ่านจาก **`app/manifest.js`**
   (หรือ `app/manifest.json`) เป็น file convention · แผนฉบับแรกเขียนว่า
   "ไฟล์ manifest หนึ่งใบ" ลอย ๆ ซึ่งชวนให้ไปวางผิดที่
2. **`theme-color` ไม่ได้อยู่ใน manifest** ถ้าอยากให้ตามธีม — ใน manifest มีได้
   ค่าเดียว · ที่ตามธีมได้คือ `export const viewport = { themeColor: [...] }`
   ใน `app/layout.js` ซึ่งออกมาเป็น `<meta name="theme-color" media="...">`
3. **แต่ `media` นั้นดูแค่ `prefers-color-scheme` ของเครื่อง — ไม่เห็นปุ่มสลับธีม
   ในแอป** ที่เขียน `data-theme` ลง `localStorage` ฉะนั้นคนที่ตั้งเครื่องเป็น
   สว่างแล้วสลับแอปเป็นมืด จะได้แถบสถานะสีสว่างคาไว้ · แก้ได้ด้วยการอัปเดต
   แท็ก `<meta name="theme-color">` ตอนกดสลับใน `components/ProfileView.jsx`
   ไม่กี่บรรทัด — **ผมเสนอให้ทำ** ไม่งั้น standalone จะดูครึ่ง ๆ กลาง ๆ ตรงจุด
   ที่คนเห็นชัดที่สุด

#### ไอคอน — เคยติด เคลียร์แล้ว 2026-09-10

> **เคยอ่านว่า "⚠ ติดจริง: ไม่มีไอคอนที่ใหญ่พอ"** — `logo-mark.png` 256×256 และ
> `logo.png` 449×445 ไม่ถึง 512 ที่เกณฑ์ติดตั้งของ Chrome ต้องการ · **ปลดแล้ว**
> ด้วย `public/app icon.png` ที่ส่งมาวันเดียวกัน

ต้นทางใหม่: **619×596 · PNG color type 6 (RGBA) · ทุกจุดทึบ** (สุ่ม 7,654 จุด
ไม่มีจุดโปร่งเลย) · ตัดคำ *"Primus OT System"* ออกแล้วตามเหตุผลที่
`scripts/make-icon.js` เขียนไว้ตั้งแต่ต้น

**ขอบเขตที่ตกลงไว้: ไฟล์นี้เป็นไอคอนตอนติดตั้งลงหน้าจอเท่านั้น — ตราบนเว็บยัง
เป็น `logo.png` / `logo-mark.png` เหมือนเดิม ไม่แตะ**

สามอย่างที่ตัวสร้างต้องทำ:

- **เล็มเศษสีเขียวที่ขอบล่าง** — เศษของ wordmark ที่ครอปออก
- **เผื่อขอบ** — วันนี้มาร์กชนขอบบนและซ้าย · iOS โค้งมุมเอง Android มาสก์เป็น
  วงกลมได้ → กินหัว P กับนาฬิกา · ย่อ 596 → ~410 ในผืน 512 ได้พอดี **ไม่ต้องขยาย
  ภาพ ไม่เบลอ**
- **ออก 192 · 512 · maskable 512** พร้อม `apple-touch-icon` 180

**ไม่ต้องเพิ่ม dependency** — `package.json` มี 7 ตัว ฝั่งเซิร์ฟเวอร์ทั้งหมด ·
`scripts/make-icon.js` ถอด PNG เองด้วย `zlib` อยู่แล้ว แต่รับเฉพาะ palette
(บรรทัด 63 โยน error ถ้า color type ≠ 3) · ไฟล์ใหม่เป็น type 6 จึงต้องเพิ่มทาง
อ่านอีกแบบ — ยังเป็น `zlib` ล้วน

ก่อนหน้า — และแชร์ลิงก์หน้าใดหน้าหนึ่งให้กันไม่ได้ นี่คือข้อที่ทำให้รู้สึกว่า
"เป็นเว็บ" มากที่สุดรองจากข้อ ก. และเป็นข้อที่แพงที่สุดในสี่ข้อ

#### ⚠ สองข้อที่ตัดสินแล้วชนกัน — ต้องตัดสินเพิ่มหนึ่งเรื่อง

**เอา standalone (ข้อ ก.) แต่ไม่ทำ URL (ข้อนี้) แล้วปุ่ม back ของ Android จะแย่
ลงกว่าเดิม ไม่ใช่เท่าเดิม** — วันนี้แอปอยู่ในแท็บเบราว์เซอร์ กด back แล้วอย่างน้อย
ยังถอยไปหน้าก่อนหน้าในแท็บ · พอเป็น standalone หน้าต่างนั้นไม่มีประวัติอะไรเลย
**กด back จากจอไหนก็ตาม = ปิดแอปทิ้ง** และไม่มีปุ่ม back ของเบราว์เซอร์ให้เห็น
เป็นทางออกด้วย

แต่การกันเรื่องนี้ **ไม่ต้องทำ URL routing ทั้งระบบ** — สแตกใน
`components/nav.jsx` ที่ใช้งานได้อยู่แล้วรับงานนี้ได้ ขอแค่ `pushState` หนึ่งครั้ง
ตอน mount + ตัวฟัง `popstate` ที่ป้อนเข้าสแตกเดิม ประมาณสิบห้าบรรทัด ไม่มีลิงก์
ต่อจอ ไม่มีอะไรแชร์ได้ ไม่ใช่ข้อ ข. ที่ปฏิเสธไป

**ผมเสนอ: ทำตัวกันนี้พร้อมข้อ ก.** — ถ้าไม่ทำ ควรตัดสินใจอย่างรู้ตัวว่ายอมให้
กด back แล้วแอปปิด ซึ่งบนมือถือคือสิ่งที่คนบ่นถึงเป็นอย่างแรก
