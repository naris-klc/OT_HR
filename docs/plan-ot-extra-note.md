# รายละเอียดเพิ่มเติม — ช่องที่ยาวได้ โดยไม่แตะใบ F-HR-027

> แผนงาน · ถามและเคาะกับผู้ใช้เมื่อ 2026-09-16 · ยังไม่ลงมือจนกว่าจะได้ยืนยัน

## โจทย์

พนักงานอยากอธิบายงานได้ยาวกว่า 22 ตัวอักษร · ฝ่ายบุคคลไม่อยากให้ใบพิมพ์ล้น ·
และผู้ใช้ไม่ยอมรับการย่อข้อความอัตโนมัติ เพราะไทยไม่มีช่องว่าง การตัดจึงตกกลางคำ
และอ่านไม่รู้เรื่อง

## ทำไม 22 ถึงเป็น 22 (ข้อมูลที่ต้องรู้ก่อนตัดสิน)

คอลัมน์ `รายละเอียดงานที่ทำ` บนใบกว้าง **51mm** — 194mm ลบอีกแปดคอลัมน์ที่ตรึง
ความกว้างไว้รวม 143mm (`colgroup` ใน `components/PrintForm.jsx`) ที่ 6.8pt ได้ราว
40 ตัวอักษรต่อบรรทัด และเซลล์เดียวกันยังต้องรับมาร์กต่อท้ายอีกสามอัน — ` (รออนุมัติ)`
` [ไม่พักเที่ยง]` ` (แทน)` ตัวยาวสุดกิน 12 ตัว **22 จึงคือที่ว่างที่เหลือ ไม่ใช่ตัวเลข
ที่เลือกมาลอย ๆ**

`.f027 td.desc` ใน `app/print.css` เป็น `nowrap` + `text-overflow: ellipsis` ซึ่ง
ตัดกลางคำจริง วันนี้ไม่เห็นผลเพราะ 22 ตัวไม่เคยล้น — ยกเว้นใบที่บันทึกก่อนมีกฎ
(schema ยอมถึง 500) ที่ยังพิมพ์ออกมาโดนตัด

## สิ่งที่เคาะแล้ว

| ข้อ | คำตอบ |
| --- | --- |
| ช่องเดิม `รายละเอียดงานที่ทำ` | **คงไว้ 22 ตัวอักษร** ใบ F-HR-027 ไม่เปลี่ยนแม้แต่มิลลิเมตรเดียว |
| ช่องใหม่ | `รายละเอียดเพิ่มเติม` · ไม่บังคับ · **200 ตัวอักษร** |
| พิมพ์ลงใบไหม | **ไม่** ทั้งใบ F-HR-027 ไฟล์ CSV และสรุปส่งบัญชี ไม่แตะเลย |
| เห็นที่ไหน | กล่องรายละเอียดใบ (`ReasonCard`) เท่านั้น — ในคิวรออนุมัติต้อง**กดดูรายละเอียดก่อน ไม่ขึ้นในแถว** |
| วางตรงไหนในกล่อง | การ์ดเดิม ใต้ข้อความหลัก — คนอ่านได้เนื้อหาเรื่องเดียวกันต่อกัน ไม่ต้องมองสองที่ |
| ในฟอร์มบันทึก OT | **ซ่อนหลังลิงก์ `อธิบายเพิ่มเติม (ไม่บังคับ)`** คนส่วนใหญ่ไม่ใช้ ฟอร์มจึงไม่ยาวขึ้น |
| ใครกรอก/แก้ได้ | เหมือนช่องเดิมทุกประการ — พนักงาน · หัวหน้าบันทึกแทน · ฝ่ายบุคคลแก้ไข |
| ใบเก่าที่ยาวเกิน 22 | **ปล่อยไว้** ไม่ย้ายข้อมูล ไม่แก้ ellipsis ในงานนี้ |

**ทำไมถึงแยกช่องแทนขยายช่องเดิม** — ทางเลือกอื่นทั้งหมดจบที่การตัดคำ: ขยายเป็น
2 บรรทัดก็ยังมีเพดาน และเดือนที่มีหลายช่วงเวลาต่อวันจะดันใบล้นไปหน้า 2 · ปล่อยยาว
แล้วให้ระบบย่อคือสิ่งที่ผู้ใช้ปฏิเสธ · แยกช่องคือทางเดียวที่**ไม่มีข้อความไหนถูกบีบ
ลงช่องที่เล็กกว่าตัวมันเลย**

## แผนแก้ไฟล์

1. **`src/config/policy.js`** — `EXTRA_NOTE_MAX_CHARS = 200` และ
   `normaliseExtraNote(raw)` คืน `{ value }` / `{ error }` · ค่าว่างถูกต้องเสมอ
   (คืน `''`) เพราะช่องนี้ไม่บังคับ · อยู่ข้าง `normaliseDescription` ด้วยเหตุผล
   เดียวกัน: ทุกเส้นทางเขียนต้องตอบคำถามนี้เหมือนกัน
2. **`src/models/OtEntry.js`** — `extraNote: { type: String, trim: true, default: '', maxlength: 200 }`
   · ใส่ใน `snapshot()` ด้วย เพื่อให้ประวัติการแก้ไขเทียบค่าก่อน/หลังได้
   · เพดาน schema เท่ากับกฎพอดี ไม่ต้องเผื่อแบบ `description` เพราะไม่มีข้อมูลเก่า
3. **`lib/entries.js`** — เพิ่ม `'extraNote'` ใน `ENTERED_FIELDS` (ประวัติจับการแก้)
   และใน `select` ของคิวที่บรรทัด 82 · **ไม่ต้องมี `extraNoteUnchanged`** คู่กับ
   `descriptionUnchanged` เพราะไม่มีใบเก่าที่ยาวเกินเพดานให้ต้องยกเว้น
4. **`app/api/entries/route.js` (POST)** และ **`app/api/entries/[id]/route.js` (PATCH)**
   — เรียก `normaliseExtraNote` ตรงที่เรียก `normaliseDescription` อยู่แล้ว
5. **`components/OtForm.jsx`** — ลิงก์ `อธิบายเพิ่มเติม (ไม่บังคับ)` ใต้ช่องเดิม
   กดแล้วกาง textarea พร้อมตัวนับ `n/200` แบบเดียวกับช่องเดิม · **ใบที่เปิดมาแก้แล้ว
   มีข้อความอยู่แล้ว ต้องกางไว้ตั้งแต่แรก** ไม่งั้นข้อความที่มีอยู่จะถูกซ่อนจากคนที่กำลังแก้

   **ถ้อยคำที่ผู้ใช้เคาะไว้ ใช้ตามนี้ทุกตัวอักษร:**

   - ลิงก์ที่ยังไม่กาง — `อธิบายเพิ่มเติม (ไม่บังคับ)`
   - คำใบ้ช่องล่าง — `อธิบายรายละเอียดเพิ่มเติม (ไม่แสดงในแบบฟอร์ม F-HR-027)`
   - ช่องบนคงคำใบ้เดิมที่บอกว่ามันคือ `รายละเอียดงานที่ทำ` ที่พิมพ์ลงใบ

   **ไม่มีเลขรุ่นในคำใบ้ และไม่ได้อ่านจากค่าตั้งค่า** — `formCode` (ค่าเริ่มต้น
   `F-HR-027 Rev.4`) ตั้งค่าได้ในหน้าตั้งค่าระบบและพิมพ์ลงหัวใบจริง แต่คำใบ้บรรทัด
   เดียวไม่คุ้มกับการเพิ่มฟิลด์เข้า `/api/auth/me` · รหัสฟอร์มไม่เคยเปลี่ยน เปลี่ยน
   แต่เลข Rev. — ตัดเลขออก คำใบ้จึงไม่มีวันหมดอายุ
6. **`components/common.jsx`** — `ReasonCard` รับ prop `extraNote` วางใต้ข้อความหลัก
   ในการ์ดเดิม ใช้ `Disclosure` 4 บรรทัดตัวเดิม · เพิ่ม `extraNote` ใน `FIELD`
   (ป้าย `รายละเอียดเพิ่มเติม`) ให้ประวัติการแก้ไขอ่านออก
7. **จุดเรียก `ReasonCard` ทั้งสาม** — `ApprovalQueue.jsx` · `EmployeeView.jsx` ·
   `WithdrawalRequests.jsx` ส่ง `extraNote` เพิ่ม
8. **`app/styles.css`** — ป้ายย่อยในการ์ด ใช้โทเคนเดิม ไม่มีสีดิบ

**ไม่แตะ**: `components/PrintForm.jsx` · `app/print.css` · `AccountingPrint.jsx` ·
เส้นทาง CSV ทั้งสอง · `DESCRIPTION_MAX_CHARS`
