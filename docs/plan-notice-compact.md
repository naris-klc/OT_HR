# การแจ้งเตือนที่ยังไม่กระชับ — สำรวจทั้งแอป 2026-09-11

> **สถานะ 2026-09-12 — กอง ข กับ กอง ค ทำแล้ว** ผู้ใช้สั่ง *"โอเคทำแค่ 1 กับ 2
> ก่อน"* คือสองข้อแรกของ §ลำดับที่เสนอ ซึ่งเป็นสองข้อที่ไม่ต้องตัดสินใจ UX
> รายละเอียดอยู่ที่ README §การแจ้งเตือนพูดด้วยเสียงเดียวกัน และแถวใน
> `docs/features.md` · **กอง ก · จ · ฉ ยังไม่ได้แตะ** และคำถามท้ายเอกสารนี้
> ยังไม่มีข้อไหนถูกตอบ

ถามมาว่า *"ยังมีการแจ้งเตือนตรงไหนใน app ที่ไม่กระชับ และควรกระชับเป็นรูปแบบ
เดียวกันอีกมั้ย รวมถึงพวกคำอธิบายยาว ๆ ด้วย"* — นี่คือผลสำรวจ ยังไม่ได้แก้อะไร
และยังไม่มีข้อไหนตกลงกัน เอกสารนี้เป็นบัญชีของสิ่งที่พบกับคำถามที่ต้องตอบก่อน
ลงมือ ไม่ใช่ใบสั่งงาน

## รูปแบบที่ถือว่า "กระชับ" คืออะไร

สี่คอมมิตที่ผ่านมาได้ทรงเดียวกันมาแล้ว และมันคือมาตรฐานที่ข้อเสนอทุกข้อข้างล่าง
วัดกับมัน:

- `7393bfe` แถบ งวด… — พูดครบในแถวเดียว ไม่มีฝาพับ
- `bf6cb5f` การ์ด ผลเทียบ เหลือสองแถว และแถบ แจ้งเตือน เหลือแถวเดียว
- `74e66fb` กล่อง ยังไม่ได้เทียบกับไฟล์สแกนนิ้วมือ เหลือแถวเดียว
- `9573432` แถบ ประกาศวันหยุดบริษัท เหลือแถวเดียว และถอนฝาพับทั้งชุด

กติกาที่สรุปได้จากสี่ใบนี้ มีสามข้อ:

1. **เขียนเป็นสายข้อความสายเดียว ไม่ใช่ก้อนซ้อนก้อน** — บล็อกแชร์บรรทัดกันไม่ได้
   สายเดียวตัดบรรทัดตรงที่*ประโยค*ตัด ไม่ใช่ตัดหนึ่งครั้งต่อหนึ่งก้อน
2. **ชั้นที่สองไม่เขียนขนาดตัวอักษรเอง** — ใช้ `.alert .say` ที่มีอยู่แล้ว
   (`app/styles.css:6298`) ถ้ายังต้องมีชั้นที่สองจริง ๆ
3. **ฝาพับไม่ใช่คำตอบของกล่องที่ยาว** — ถ้าย่อให้พอดีแถวเดียวได้ ก็ไม่ต้องมีปุ่ม

## ลำดับที่เสนอ

1. **กอง ข** (`.say`) — ไม่ต้องตัดสินใจอะไร ไม่เปลี่ยนคำสักคำ และทำให้ทุกข้อ
   ที่เหลือทำง่ายขึ้น เพราะชั้นที่สองจะเหลือกลไกเดียว
2. **กอง ค** (ตัดที่ซ้ำ) — ได้ความสั้นมาฟรี ไม่เสียข้อมูล
3. **กอง ก** ทีละใบ เรียงตามคนเห็นบ่อย: `BackupBanner` → แถบรับช่วงกับแถบ
   แสดง N จาก M บนคิว → หน้านโยบายการคำนวณ (ซึ่งมีแถวเดียวเป็นตัวอย่างอยู่แล้ว)
4. **กอง จ** — ตัดสินใจเรื่องฝาพับทีเดียวทั้งสามจุด แล้วแก้ความเห็นสี่จุดที่ชี้
   ไปยังต้นแบบที่ถอนไปแล้ว
5. **กอง ฉ** — คู่ Alert + `.hint` ในโมดัลของ `EmployeeView` ก่อน

2. **กอง จ: ฝาพับสามจุดที่เหลือ ตัดทิ้งเหมือนแถบวันหยุด หรือเก็บไว้** — ถ้าตัด
   ข้อความที่อยู่หลังฝาต้องย่อลงให้พอดีแถวเดียว ไม่ใช่กางค้างไว้เฉย ๆ
3. หน้านโยบายการคำนวณ: ให้มันใช้ทรงแถวเดียวแบบที่ `PolicyDriftBanner` ใช้บนคิว
   เลยไหม — รายการ drift กับปุ่มบันทึกเวอร์ชันจะไปอยู่ที่ไหน
4. กอง ง (กล่องผลลัพธ์) เห็นด้วยกับเกณฑ์ที่ผมใช้แยกมันออกมาไหม ถ้าไม่ มันจะ
   เป็นงานคนละขนาดกันเลย
5. ทำทีเดียวทั้งหมด หรือแบ่งเป็นคอมมิตละกอง
