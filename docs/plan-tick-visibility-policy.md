## เรื่องที่ต้องแก้

ผู้ใช้รายงาน 2026-09-16: ตำแหน่ง **เจ้าหน้าที่บริการ** ยังเห็นช่อง **ไม่พักเที่ยง**
และช่อง **เหมารายวัน** โผล่บนวันพุธ (วันทำงานปกติ) ทั้งที่ควรมีเฉพาะวันหยุด

กฎที่ใช้อยู่ตอนนี้ฝังในโค้ด — `FLAT_DAILY_POSITIONS` ใน [lib/entries.js](../lib/entries.js)
และเงื่อนไขใน `mayTickFlatDaily` / `mayTickNoBreak` ของสองจอ ([components/OtForm.jsx](../components/OtForm.jsx),
[components/ApprovalQueue.jsx](../components/ApprovalQueue.jsx)) เปลี่ยนทีต้องแก้โค้ดและ deploy

| ช่อง | โค้ดตอนนี้ | ที่ต้องการ |
|---|---|---|
| เหมารายวัน | เฉพาะเจ้าหน้าที่บริการ · ทุกวัน | เฉพาะเจ้าหน้าที่บริการ · **เฉพาะวันหยุด** |
| ไม่พักเที่ยง | ทุกตำแหน่ง · เฉพาะวันหยุด | **ยกเว้นเจ้าหน้าที่บริการ** · เฉพาะวันหยุด |

ผู้ใช้สั่งเพิ่ม 2026-09-16: ตั้งค่าได้บนหน้าจอ ไม่ต้องแก้โค้ดเมื่อกฎเปลี่ยนอีก

## ข้อตกลงที่ถามผู้ใช้แล้ว (2026-09-16)

1. **ใช้ทั้งสองจอ** — ฟอร์มยื่น OT และกล่องแก้ไขเร็วในคิวรออนุมัติ
2. **ซ่อนแล้วปลดค่าทิ้ง เงียบๆ** — ไม่คงกฎเดิมที่ว่า "ติ๊กไว้แล้วยังแสดงเพื่อให้ปลดได้"
3. **ฝั่งเซิร์ฟเวอร์ไม่แตะ** — ยังเป็นกฎเรื่องสิ่งที่วาดบนจอ `POST /api/entries` รับค่าเหมือนเดิม
4. เงื่อนไขตำแหน่ง **3 โหมด**: ทุกตำแหน่ง / เฉพาะที่เลือก / ยกเว้นที่เลือก
5. เงื่อนไขวัน **3 โหมด**: ทุกวัน / เฉพาะวันหยุด / เฉพาะวันทำงาน
6. รายชื่อตำแหน่ง **ดึงจากทะเบียนพนักงานจริง** (`/employees?all=1`) ไม่ให้พิมพ์เอง
7. การเปลี่ยนค่า **ลงประวัตินโยบาย** แต่ **ไม่คำนวณชั่วโมงใหม่** → เป็น `COSMETIC_KEYS`

### ข้อ 2 แลกอะไรไป

กฎเดิม ("already ticked ยังแสดง") มีเหตุผลเขียนไว้ทั้งสองจอ: แถวที่ยื่นไว้ก่อนกฎใหม่
จะถือ flag ที่คิด 8 ชม. โดยไม่มีปุ่มบนจอไหนปลดได้ ผู้ใช้เลือก **ปลดออกอัตโนมัติ
โดยไม่แจ้ง** แทน — ผลคือเปิดฟอร์มแก้ไขแถวเก่าที่ผิดกฎใหม่แล้วกดบันทึก ตัวเลขจะ
เปลี่ยน (เหมารายวัน 8 ชม. → OT ตามเวลาจริง) ยอมรับความเสี่ยงนี้แล้ว การปลดต้องผูกกับ
**กฎธุรกิจ** (ตำแหน่ง/วัน) เท่านั้น ไม่ใช่กับ **สิทธิ์ผู้อ่าน** — กล่องแก้ไขเร็วซ่อนช่อง
เหมารายวันจากหัวหน้าด้วย `mayCorrectEntries` ซึ่งไม่ใช่เหตุผลที่จะล้างค่าของคนอื่น

## คีย์นโยบายใหม่ 6 ตัว

ใน `DEFAULT_POLICY` ([src/config/policy.js](../src/config/policy.js)) บล็อกใหม่
"ช่องติ๊กบนฟอร์ม OT":

```js
flatDailyPositionMode: 'only',      // 'all' | 'only' | 'except'
flatDailyPositions: ['เจ้าหน้าที่บริการ'],
flatDailyDayScope: 'offDays',       // 'all' | 'offDays' | 'workDays'
noBreakPositionMode: 'except',
noBreakPositions: ['เจ้าหน้าที่บริการ'],
noBreakDayScope: 'offDays',
```

ค่าเริ่มต้นคือกฎที่ผู้ใช้สั่งวันนี้ — ติดตั้งแล้วพฤติกรรมถูกต้องทันทีโดยไม่ต้องไปกดตั้งค่า

**`FLAT_DAILY_POSITIONS` ถูกถอด** จาก lib/entries.js ค่าเดิมย้ายไปเป็นค่าเริ่มต้นของ
`flatDailyPositions` · `isFlatDailyPosition()` ถูกถอดตามไปด้วย (ไม่มีใครเรียกอีก)

## ตัวตัดสินร่วม — lib/entries.js

ฟังก์ชันเดียวที่ทั้งสองจอเรียก เพื่อไม่ให้กฎเดียวกันเขียนสองแบบ:

```js
export function tickVisible({
  position, workDate, mode, positions, dayScope, holidays, weekendDays,
})
```

- ตำแหน่ง: `all` → จริงเสมอ · `only` → อยู่ในลิสต์ · `except` → ไม่อยู่ในลิสต์
- วัน: `all` → จริงเสมอ · `offDays` → `isCompanyOffDay()` · `workDays` → ไม่ใช่
- ปฏิทินโหลดไม่สำเร็จ (`holidays: null`) → อ่านเป็น `[]` เหมือนเดิม: ช่องหายไปในวันที่
  ควรแสดง ดีกว่าโผล่ในวันที่ห้ามแสดง (เหตุผลเดิมของ `mayTickNoBreak`)
- `isCompanyOffDay()` อยู่ต่อไม่เปลี่ยน — วันเกิดยังถูกกันออกเชิงโครงสร้าง เพราะจอไม่ถือวันเกิด

**โหมดยื่นแทน (proxy)**: ยังเป็น `every` — ทุกคนในลิสต์ต้องผ่านเงื่อนไข เหตุผลเดิม
(ใบเดียวติ๊กเดียวเขียนลงทุกคน)

## หน้าตั้งค่า — บล็อกที่ 6

`POLICY_SECTIONS` เพิ่ม `{ id: 6, title: 'ช่องติ๊กบนฟอร์มบันทึก OT' }` แถวทั้งหมดเป็น
แถวนโยบายปกติ (คำถามซ้าย · ตัวเลือกขวา · ยืนยันก่อนบันทึก) เรียงคู่ละ 3 แถว:

1. ช่องเหมารายวัน แสดงกับตำแหน่ง → ทุก / เฉพาะที่เลือก / ยกเว้นที่เลือก
2. ตำแหน่งของช่องเหมารายวัน → **แถวชนิดใหม่**: เปิด Modal ติ๊กรายชื่อตำแหน่ง
3. ช่องเหมารายวัน แสดงในวัน → ทุกวัน / เฉพาะวันหยุด / เฉพาะวันทำงาน
4–6. ชุดเดียวกันของช่องไม่พักเที่ยง

**แถวเลือกตำแหน่ง** เป็นของใหม่ชิ้นเดียวในงานนี้ — หน้าตั้งค่าทุกแถวเดิมเป็นดรอปดาวน์
ค่าเดียว ส่วนนี้ต้องติ๊กได้หลายค่า ใช้ `Modal` + `ConfirmDialog` จาก `components/common.jsx`
ไม่สร้างคอนโทรลใหม่ ไม่ใช้ `<select>` (`test/noNativeSelect.test.js`)

- รายชื่อมาจาก `/employees?all=1` โหลดเมื่อเปิดบล็อก เรียงตามชื่อ ตัดซ้ำ
- ตำแหน่งที่เก็บไว้แต่ไม่มีพนักงานคนไหนถืออยู่แล้ว ยังแสดงในลิสต์และติ๊กค้างไว้ —
  ไม่ให้ค่าหายเงียบเพราะคนลาออก
- แถวที่ 2 และ 5 **ไม่มีผล** เมื่อโหมดเป็น "ทุกตำแหน่ง" → ใช้ `inertReason` ที่หน้านี้มีอยู่แล้ว

ย่อหน้าใต้แถว (hint) บอกผลกระทบจริง: ซ่อนแล้วค่าที่ติ๊กค้างจะถูกปลดออกเมื่อแก้ไขใบนั้น
