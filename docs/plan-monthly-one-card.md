# ตรวจสอบประจำเดือน — เอาทุกอย่างเข้ามาอยู่ในการ์ดใบเดียว เหมือน รออนุมัติ OT

**สถานะ: ข้อเสนอ ยังไม่เริ่มเขียนโค้ด** — 2026-09-10

รายงานมา พร้อมภาพหน้าจอ: *"ควรปรับให้ส่วนตามรูป ไม่แยกออกจากส่วนหลักของหน้า
ยังไงดี เอาไปรวมกันได้มั้ย เหมือนหน้ารออนุมัติ ot"*

---

## 1. นับของจริงก่อน — วันนี้มีกี่ก้อนลอยอยู่เหนือการ์ด

อ่านจาก `components/HrView.jsx` ตามลำดับที่มันวาด:

| # | ก้อน | เป็นอะไร | เห็นในภาพ |
|---|---|---|---|
| 1 | `MonthAlerts` | `.alert` พับได้ ปิดได้ | (อยู่เหนือกรอบภาพ) |
| 2 | `ScanCompareCard` | `.alert` สามสถานะ | (อยู่เหนือกรอบภาพ) |
| 3 | `.month-strip` | บรรทัดเปล่าบนพื้นหน้า — `PeriodStatus compact` + ปุ่ม `ไฟล์สแกนนิ้วมือ ▼` | ✅ บรรทัดบนสุด |
| 4 | `ScanImport` | **การ์ดขาวเต็มใบ** (`<div className="card no-print">`) | ✅ กล่องใหญ่กลางภาพ |
| 5 | `error` | `.alert` | — |
| 6 | `.month-panel` | การ์ดหลัก = `.card-head` + `.queue-tools` + ตาราง | (อยู่ใต้กรอบภาพ) |

**หน้า รออนุมัติ OT มีก้อนเดียว** — `.card.flush` ที่ข้างในเป็น `.card-head` →
`.queue-tools` → ตาราง จบ

นี่คือคำตอบของคำถาม "ทำไมมันดูแยกออกจากกัน": **มันแยกออกจากกันจริง ๆ — ห้าก้อน
ต่อหนึ่งการ์ด** และภาพที่ส่งมาจับได้ตอนที่ก้อนที่ 4 กางอยู่ ซึ่งเป็นตอนที่มันหนัก
ที่สุด

### ⚠ และมันแย่ลงเพราะรอบที่แล้ว ไม่ใช่ดีขึ้น

รอบ 2026-09-10 เอา *ผลเทียบสแกน* ออกจากการ์ดนำเข้า ขึ้นมาเป็นการ์ดของตัวเอง —
ด้วยเหตุผลที่ยังถูกอยู่ (มันเป็นข้อเท็จจริงที่ต้องอ่านก่อนเซ็น ไม่ใช่การกระทำ
เดือนละครั้ง) แต่**ผลข้างเคียงคือเพิ่มก้อนที่ลอยอยู่เหนือการ์ดไปอีกหนึ่ง** และบน
เดือนที่ยังไม่ได้นำเข้าไฟล์ ตอนนี้จอมีเรื่อง "สแกน" อยู่ **สามก้อนซ้อนกัน**:

```
[ ยังไม่ได้เทียบกับไฟล์สแกนนิ้วมือ ]   ← ScanCompareCard
⚠ งวด กันยายน 2569 …  ซ่อนไฟล์สแกนนิ้วมือ ▲   ← ปุ่มสลับบน strip
┌ ไฟล์สแกนนิ้วมือ ─────────────────┐   ← การ์ดนำเข้า
│ กันยายน 2569 · นำเข้าแล้ว 0 จาก 4 …│
└────────────────────────────────┘
```

สามบรรทัดแรกของสามก้อนพูดคำว่า "ไฟล์สแกนนิ้วมือ" ทั้งหมด

## 2. ทางเลือกที่คิดแล้วทิ้ง

### ❌ (ก) ย้าย `ScanImport` เข้าไปในการ์ดเฉย ๆ แล้วจบ

แก้ก้อนที่ 4 ก้อนเดียว เหลืออีกสี่ก้อนลอยอยู่เหมือนเดิม — `strip` ยังเป็นบรรทัด
เปล่าคั่นระหว่าง `MonthAlerts` กับการ์ด ซึ่งเป็นรูปเดิมที่รายงานว่า *"ส่วนกรอง
ข้อมูลควรต่อเนื่องกับส่วนตาราง"* เมื่อรอบก่อน แค่เลื่อนขึ้นไปหนึ่งชั้น

### ❌ (ข) ยุบ `ScanCompareCard` กลับเข้าไปในการ์ดนำเข้า

ได้จำนวนก้อนลดลงหนึ่ง แต่**กลับคำตัดสินที่เพิ่งลงมือไปเมื่อวานด้วยเหตุผลที่ยัง
ถูกอยู่** การ์ดนำเข้าพับปิดทุกครั้งที่เข้าหน้า และคำตอบของ *"เดือนนี้เซ็นได้
หรือยัง"* ต้องอ่านได้โดยไม่ต้องกดอะไร

### ❌ (ค) ย้ายทั้ง `MonthAlerts` และ `ScanCompareCard` ไปไว้ *ใต้* ตาราง

ก้อนน้อยลงเหนือการ์ดจริง แต่ทั้งสองอันมีไว้ให้อ่าน **ก่อน** เชื่อยอดรวม การเอาไป
ไว้ใต้ยอดรวมคือคำเตือนที่มาถึงหลังจากคนอ่านตัดสินใจไปแล้ว

## 3. ✅ ข้อเสนอ — การ์ดใบเดียว ห้าส่วน

```
┌ .card.flush.month-panel ────────────────────────────────────────┐
│ .card-head                                                       │
│   ตรวจสอบประจำเดือน · 24 คน                                      │
│   กันยายน 2569 · แผนกผลิต1            [ไฟล์สแกน ▾] [พิมพ์/ส่งออก ▾]│
├──────────────────────────────────────────────────────────────────┤
│ .month-notices   ← งวด… · MonthAlerts · ผลเทียบสแกน · error       │
│                     (ทั้งบล็อกหายไปเลยเมื่อไม่มีอะไรจะพูด)          │
├──────────────────────────────────────────────────────────────────┤
│ .scan-drawer     ← ScanImport กางในนี้ ไม่ใช่การ์ดของตัวเอง         │
├──────────────────────────────────────────────────────────────────┤
│ .queue-tools     ← ค้นหา · ประจำเดือน · แผนก · สถานะที่นับ          │
├──────────────────────────────────────────────────────────────────┤
│ .batch-bar / ตาราง                                               │
└──────────────────────────────────────────────────────────────────┘
```

### 3.1 `.month-strip` ถูกลบทิ้งทั้งอัน

ของสองอย่างบนนั้นไปคนละที่ และนั่นคือเหตุผลที่มันควรตายมากกว่าถูกย้าย:

- **ปุ่ม `ไฟล์สแกนนิ้วมือ ▼` → ขึ้นไปอยู่ใน `.card-head`** ข้าง `พิมพ์ / ส่งออก ▾`
  ซึ่งเป็นที่ที่ *ทุกการ์ดในแอปนี้วางปุ่มของมัน* อยู่แล้ว — และเป็นประโยคที่
  README เขียนไว้เองตอนรอบ declutter
- **`PeriodStatus compact` → ลงไปอยู่ใน `.month-notices`** เพราะมันคือ *คำเตือน*
  ไม่ใช่ *ปุ่ม* — มันมีของมันเองอยู่แล้วทั้งไอคอน ⚠ และตัวพับ `รายละเอียด`

**⚠ ข้อที่ต้องระวัง:** `PeriodStatus` รับ prop `actions` ซึ่งมีไว้ให้ strip ส่ง
ปุ่มสแกนเข้าไป ถ้าปุ่มย้ายขึ้น card-head แล้ว `actions` จะไม่มีคนใช้ — ต้องเลือก
ว่าลบ prop ทิ้ง หรือเก็บไว้ (`test/monthSearch.test.js:301` ตรึงมันอยู่)

### 3.2 `.month-notices` — บล็อกเดียวสำหรับ "อ่านก่อนเชื่อยอด"

สามอย่าง เรียงตามความเร่งด่วน: **งวด → ผลเทียบสแกน → MonthAlerts → error**

เหตุผลที่มันยังอยู่ **เหนือ** `.queue-tools` ไม่ใช่ใต้ตาราง: ข้อโต้แย้งเดิมของ
`MonthAlerts` ยังถูกอยู่ทุกตัวอักษร — *สิ่งที่มันเตือนคือตัวเลขบนจอนี้ และคนที่
มันเตือนคือคนที่กำลังจะเซ็นตัวเลขนั้น* ที่เปลี่ยนคือมันอยู่ **ในการ์ดที่มันพูดถึง**
แทนที่จะลอยอยู่เหนือมัน

`.month-notices` ทั้งบล็อกไม่ถูกวาดเลยเมื่อไม่มีสมาชิก — เดือนที่ปิดเรียบร้อยและ
เทียบสแกนแล้วจะได้การ์ดที่เป็น หัว → ตัวกรอง → ตาราง เท่านั้น ซึ่งเป็นรูปเดียวกับ
รออนุมัติ OT เป๊ะ

### 3.3 `ScanImport` เลิกเป็นการ์ด

เปลี่ยน root จาก `<div className="card no-print">` เป็น `<section className="scan-drawer no-print">`
— **มีผู้เรียกคนเดียว** (ตรวจแล้ว: `HrView` เท่านั้น) จึงไม่กระทบใคร

ข้างในไม่ต้องแตะเลยสักบรรทัด สิ่งที่หายไปคือ พื้นขาว ขอบ เงา และ `border-radius`
ของการ์ดใบที่สอง — ซึ่งคือทั้งหมดของสิ่งที่ทำให้มัน "แยกออกจากส่วนหลัก" ในภาพ
แทนที่ด้วยพื้น `--neutral-wash` กับเส้นคั่นบน-ล่าง แบบที่ลิ้นชักในแอปนี้ใส่กัน

**⚠ ราคาที่จ่าย:** การ์ดจะยาวมากตอนกางลิ้นชัก — ลิ้นชักนี้สูงประมาณ 420px ทับบน
ตารางที่สูงอยู่แล้ว แต่มันเป็นของที่ต้องกดถึงจะกาง (เดือนละครั้ง) และ `scanOpen`
เปิดหน้าเป็น `false` เสมอ

### 3.4 หัวการ์ดรับปุ่มที่สาม

วันนี้ `.card-head` ฝั่งขวามี ชิปจำนวนคน + `พิมพ์ / ส่งออก ▾` เพิ่ม
`ไฟล์สแกน ▾` เข้าไปเป็นปุ่มที่สอง

**⚠ ต้องวัดบนมือถือ** — `.card-head` wrap อยู่แล้วที่ 860px แต่สามของ (ชิป + สอง
ปุ่ม) บนจอ 360px อาจตกเป็นสามบรรทัด ถ้าตก ทางแก้คือยุบสองปุ่มเป็นเมนูเดียว หรือ
ให้ปุ่มสแกนเป็นไอคอนล้วนบนมือถือ (`.act-label` ซ่อน — กลไกที่ตารางนี้ใช้อยู่แล้ว)

## 4. สิ่งที่ *ไม่* เปลี่ยน — เขียนไว้กันคนเข้าใจผิดว่าเป็นการรื้อ

- **ไม่มีกฎสิทธิ์ไหนขยับ** `readsScans`, `mayCorrect`, `approvable` เหมือนเดิมทุกตัว
- **ไม่มีเราต์ไหนถูกแตะ** ไม่มี query ใหม่ ไม่มีฟิลด์ใหม่
- **ไม่มีตัวเลขไหนคำนวณใหม่** ทุกอย่างในรอบนี้เป็นที่อยู่ของ DOM กับ CSS
- **ลำดับการอ่านไม่กลับด้าน** งวด → ผลเทียบ → แจ้งเตือน → ตัวกรอง → ตาราง คือ
  ลำดับเดิมที่มันเป็นอยู่ทุกวันนี้ แค่ห้ากล่องกลายเป็นห้าส่วนของกล่องเดียว
- **`ScanCompareCard` ไม่ถูกยุบกลับ** — ยังเป็นคอมโพเนนต์ของตัวเอง ยังอ่านได้
  โดยไม่ต้องกดอะไร แค่ย้ายเข้าไปอยู่ในการ์ด

## 6. ⚠ สิ่งที่ผมยืนยันเองไม่ได้ และต้องให้คนดู

รอบนี้เป็นเรื่อง **ความสูงกับการ wrap** ล้วน ๆ ซึ่งเป็นสิ่งที่เทสต์อ่านซอร์ส
มองไม่เห็นเลย (บทเรียนจาก `ReferenceError` เมื่อกี้ยังสด) และผมไม่มีรหัสเข้าระบบ
จึงเปิดหน้าที่ต้องล็อกอินมาวัดเองไม่ได้

**สามจุดที่ต้องมีคนมองด้วยตา:**

1. `.card-head` บนจอ 360px — ชิป + สองปุ่ม ตกกี่บรรทัด
2. ความสูงการ์ดตอนกางลิ้นชักสแกน บนจอ 1440 และ 360
3. เดือนที่ "ไม่มีอะไรจะพูด" — `.month-notices` หายไปจริงไหม หรือเหลือช่องว่าง
   เปล่า ๆ กับเส้นคั่นลอย ๆ

## 7. ลำดับคอมมิตที่เสนอ

1. **`ScanImport` เลิกเป็นการ์ด** — เปลี่ยน root + CSS ลิ้นชัก ยังอยู่ที่เดิมใน
   DOM ก้อนนี้ก้อนเดียวก็แก้ภาพที่ส่งมาได้ครึ่งหนึ่งแล้ว และย้อนกลับง่ายที่สุด
2. **สร้าง `.month-notices` แล้วย้าย สี่ตัวเข้าไป** (งวด · ผลเทียบ · MonthAlerts ·
   error) — `.month-strip` ตายในก้อนนี้
3. **ปุ่ม `ไฟล์สแกน` ขึ้น `.card-head` + ย้ายลิ้นชักเข้าการ์ด** — ก้อนที่ต้องวัด
   บนมือถือ และเป็นก้อนเดียวที่มีความเสี่ยงเรื่อง layout จริง ๆ

หยุดหลังก้อนไหนก็ได้โดยหน้าไม่พัง
