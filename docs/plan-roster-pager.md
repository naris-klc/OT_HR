เหมือนกัน"* — *เหมือนกัน* หมายถึงแถบที่เพิ่งลงใต้ คิวรออนุมัติ ในวันเดียวกัน
(ดู [plan-queue-pager.md](plan-queue-pager.md))

เอกสารนี้บันทึก**ดีไซน์ที่ตกลงกันก่อนเขียนโค้ด** ตาม AGENTS.md §จอใหม่ไม่ได้เริ่ม
จากศูนย์ · เหตุผลเชิงกลไกอยู่ใน README §แถบเปลี่ยนหน้าเดียวทั้งแอป เอกสารนี้เก็บ

## 0. ของที่มีอยู่แล้ว จึงไม่ต้องออกแบบ

*เหมือนกัน* แปลตรงตัวว่า **ห้ามสร้างแถบที่สอง** สิ่งที่ใช้ซ้ำทั้งหมด:

| ของเดิม | อยู่ที่ | ใช้ยังไงในงานนี้ |
|---|---|---|
| `TablePager` | `components/common.jsx` | แถบทั้งแถบ ทั้งกล่องเลือกขนาด ทั้งลูกศร ทั้งประโยคนับ |
| `PAGE_SIZES` | เดียวกัน | 10 · 20 · 50 · 100 — ไม่ส่ง `sizes` คือรับสี่ค่านี้ |
| `usePageReset` | เดียวกัน | กลับหน้า 1 เมื่อตัวกรองขยับ |
| `unit` | พร็อพของ `TablePager` | `"คน"` |
| `AdminView.jsx` import | บรรทัดเดียวที่ 75 | ไฟล์นี้ import `TablePager` กับ `usePageReset` มาตั้งแต่ ประวัติเวอร์ชันนโยบาย แล้ว — **ไม่มี import ใหม่เลย** |
| `.table-pager` | `app/styles.css` | ระยะขอบของแถบ ใช้ได้ตรง ๆ เพราะการ์ดนี้เป็น `.card` ธรรมดา |

**สิ่งที่งานนี้เพิ่มลงสไตล์ชีตคือบรรทัดเดียว** —
`.table-wrap.roster-list { scroll-margin-top: calc(62px + 14px); }`

## 1. คำถามที่ถาม และคำตอบที่ได้

ถามสี่ข้อก่อนเขียนโค้ด ได้คำตอบครบทั้งสี่:

| คำถาม | คำตอบ | ผลต่อโค้ด |
|---|---|---|
| หน้าละกี่แถวตอนเปิดจอ | **20** | `useState(20)` |
| แถบเติมคำว่าอะไร (`แสดง 1–20 จากทั้งหมด 214 …`) | **คน** | `unit="คน"` |
| กดเปลี่ยนหน้าแล้วจอเลื่อนไหม | **เลื่อนขึ้นหัวตาราง** | `goPage` + `scroll-margin-top` |
| บรรทัด `แสดง 9 จาก 214 คน` บนแถบค้นหา เอายังไง | **เก็บทั้งสองบรรทัด** | ไม่แตะ `.found` เลย |

**ข้อที่สี่คือข้อเดียวที่จอนี้มีและคิวไม่มี** สองประโยคขึ้นต้นด้วยคำเดียวกันและ
ลงท้ายด้วยหน่วยเดียวกัน แต่ตอบคนละคำถาม:

* `แสดง 9 จาก 214 คน` — **ตัวกรองซ่อนไปกี่คน** ขึ้นเฉพาะตอนพิมพ์ค้นหา อ่านจาก
  ทะเบียนทั้งเล่ม (`rows`) เป็นประโยคเดียวบนจอที่บอกว่ารายชื่อสั้น ๆ ตรงหน้าคือ
  ผลกรอง ไม่ใช่ทะเบียน
* `แสดง 1–9 จากทั้งหมด 9 คน` — **หน้านี้คือช่วงไหนของเก้าคนนั้น** อ่านจาก `shown`

`test/tablePager.test.js` §12 ตรึงทั้งสองประโยคไว้ในเคสเดียวกัน เพราะการ
"ทำให้ไม่ซ้ำ" ในภายหลังคือการลบประโยคแรก

## 2. สามข้อที่ต่างจากคิวรออนุมัติ — และทั้งสามทำให้งานน้อยลง

**หนึ่ง — ไม่มีช่องติ๊ก** กฎ A PAGE IS NOT A FILTER จึงเหลือข้อเดียว: ตัดจาก
`shown` ไม่ใช่ `rows` ไม่มีแถบแบตช์ ไม่มี เลือกทั้งหมด ไม่มีสถานะครึ่งติ๊ก และ
ไม่มีเอฟเฟกต์ริบติ๊กให้ต้องเลือกว่าผูกกับอะไร

**สอง — `scroll-margin-top` ค่าเดียว** คิวต้องใช้สี่ค่าเลือกด้วย `:has()` เพราะ
`.batch-bar` กับ `.queue-mobile-bar` ติดอยู่ใต้แถบแอปเป็นบางสถานะ จอนี้ไม่มีอะไร
`position: sticky` นอกจาก `.appbar` ทั้งบนเดสก์ท็อปและใต้ 860px

**สาม — ไม่ต้องพกระยะขอบมาเอง** การ์ดของคิวเป็น `.card.flush` ที่ `padding: 0`
แถบจึงต้องมี `.table-pager.flush-pager` คืน 18/12px ให้ (คลาสนั้นชื่อ
`.queue-pager` ตอนเอกสารนี้ถูกเขียน — เปลี่ยนชื่อวันเดียวกันเมื่อ สรุป OT ส่งบัญชี
มาเป็นผู้เรียกรายที่สอง) การ์ดของ ทะเบียนพนักงาน
เป็น `.card` ธรรมดาที่มี padding 18px อยู่แล้ว — **แถบจึงไม่มี `className` เลย**
และเทสต์ตรึงไว้ว่าห้ามมี

## 3. ทางที่ไม่ได้เลือก

* **ไม่แบ่งหน้าที่เซิร์ฟเวอร์** `/employees?all=1` ไม่มีเพดานและส่งทะเบียนทั้งเล่ม
  อยู่แล้ว ซึ่งเป็นเหตุผลเดียวกับที่ช่องค้นหาบนจอนี้ทำงานในเบราว์เซอร์ได้ · สอน
  ให้ `skip` คือการอ่านทะเบียนเดียวกันด้วยวิธีที่สอง
* **ไม่ผูก `usePageReset` กับ `rows`** `load()` ทำงานใหม่หลังทุก แก้ไข ทุก
  รีเซ็ตรหัสผ่าน และทุกไฟล์ CSV — ผูกแล้วการแก้ข้อมูลคนที่อยู่หน้า 3 จะเด้งคนแก้
  กลับหน้า 1 ทุกครั้ง
* **ไม่เลื่อนจอจากเอฟเฟกต์** เอฟเฟกต์ที่ผูกกับ `page` จะทำงานตอน reset ด้วย
  ตารางจะถูกกระชากเข้ามาทุกตัวอักษรที่พิมพ์ลงช่องค้นหา
* **ไม่แตะตารางอื่นบน ตั้งค่าระบบ** แผนกและทีม · ประวัติการแก้ทะเบียน · วันหยุด
  ไม่ได้ถูกขอ และแต่ละตารางมีคำถามของตัวเอง (ประวัติการแก้ทะเบียน มี `hasMore`
  ของมันเองอยู่แล้ว)
